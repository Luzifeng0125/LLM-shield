# 任务必要性复核：本轮人工入口

2026-10-29 更新：本版已退役为历史模板研究资料。用户指出28题循环扩展及指令提示答案的问题，日常请使用 [自然文档 v3](../任务必要性复核_自然文档_v3_20261029/开始这里.md)。本目录原题、原始复核文件和哈希保持不变；以下保留当时使用说明，不能当作最新复核状态。新收到的两份 ZIP 已另存本机 `../复核接收_20261029`。

当前日期：2026-10-26。本包为第二版，增加了“同文本、同任务、不同职责上下文”的对照。

## 先完成首批 28 题

1. 双击 `打开复核页面.cmd`，或直接双击本文件夹内的 `action_review.html`。本文件夹可以整体复制到其他位置，使用时先完整解压；打开页面不需要安装 Python 或模型。
2. 页面中选择本目录的 `review-first-batch.json`。
3. 标注者 A 填写真实姓名或编号，选择“独立标注 A”，逐题保存，导出 JSON。
4. 另一位真实标注者独立完成同一批题，选择“独立标注 B”。两人先独立填写，不对照模型建议。
5. 将两份导出文件放入本目录的 `reviews` 文件夹，交给 AI 导入和整理分歧。

首批用于确认口径，不足以宣称模型通过人工评测。口径确定后，再复核完整的 `review-task.json`。页面支持载入已有导出文件续标；关闭页面前要导出，页面不自动联网或保存到浏览器存储。

## 人工需要判断什么

- 给定具体任务必须保留的事实或关系是什么？
- 此信息仅需在本机处理，还是确实需要向指定接收方披露？
- 最少需要总数、稳定代号、粗粒度信息还是原值？
- 资料与权限不充分时，应当暂停还是先删除该项仍可完成任务？
- 写出判断依据；不要因为信息“有用”就认定原值必须披露。

其中“指导老师已获授权”的题目是明确写出的虚构场景假设，不代表当前产品已有真实身份认证。

## 不同文件的用途

- `review-first-batch.json`：首批 28 题，不含机器建议。
- `review-task.json`：完整 336 题，不含机器建议。
- `cases.jsonl`：机器建议及研究输入，仅供开发，不应在独立标注前阅读建议答案。
- `manifest.json`：96 个合成源案例、12 个表达模板族，训练/验证/测试分别为 224/56/56 条判断。
- `reviews`：人工导出文件，只保存在本机，Git 已忽略，文件夹已创建。

这些数据全部为 AI 构造的虚构材料。当前没有一条已经过本轮真实人工复核；源案例和模板组不跨拆分，但该合成留出集不是独立盲测。

## 标注导入后由 AI 完成

使用 `scripts/merge_action_reviews.py` 导入两份文件，核对案例哈希、两位标注者、动作适用性与硬约束。缺少一方或存在未裁决分歧的题目继续保持待复核，不会自动变成金标。裁决可以使用同一页面的“歧义裁决”角色导出。

示例（在 `delivery/app` 中执行，替换成实际导出文件名）：

```powershell
python scripts/merge_action_reviews.py --cases '../../03_数据与人工复核/任务必要性复核_20261026_v2/cases.jsonl' --a '../../03_数据与人工复核/任务必要性复核_20261026_v2/reviews/A.json' --b '../../03_数据与人工复核/任务必要性复核_20261026_v2/reviews/B.json' --out '../../03_数据与人工复核/任务必要性复核_20261026_v2/reviewed/round1'
```

人工复核齐备后，由 AI 重新运行训练、比较、消融与置信度校准。未经人工验证的候选不替换活动模型。
