# LLM-shield · 隐盾

隐盾把**材料上传、敏感信息处理和连续追问**放在同一个**本地**对话入口中：
本地完成「识别 → 决策 → 转换」，通过权限与外发安全校验后，才把**脱敏后的文本**交给云端生成服务。

全过程在三个边界（发给模型的请求 / 展示给用户的结果 / 提交给工具端的内容）上做泄露观测。

## 处理主流程

对话、预览、单次运行三条入口**共用同一套本地策略路径**（`processing.analyze()`），
不存在"某个入口少做了一步检查"的情况：

```text
web/ → server.py → chat.py 或 pipeline.py
                     ↓
                 m1_access 权限与材料读取
                     ↓
          material_processing 材料展开、逐份识别、坐标统一
                     ↓
                 m2_detect 识别与分段
                     ↓
         m4_necessity 模型评分 → m3_decide 硬约束
                     ↓
              m6_transform 脱敏与代号映射
                     ↓
        m7_egress 外发复检 → 模型 / 展示 / 工具
                     ↓
                 m8_audit 记录三个边界结果
```

`schema.py` 是跨模块数据契约，`config.py` 读 `config/*.yaml`、模型目录与环境变量。
`m9_data` 与 `scripts/` 属离线工具，不在在线链路内。

> **失败关闭**：启用 GLiNER 而模型缺失或推理异常时，请求**暂停**，不会被当成"没有命中"；
> 识别失败永远不会被解释成"这段是干净的"。

## 运行

**已有本地便携包**：双击 `delivery/启动隐盾.cmd`，打开 <http://127.0.0.1:8787/>。

**从 GitHub 克隆**（需要 Python 3.12）：

```powershell
git clone https://github.com/Luzifeng0125/LLM-shield.git
cd LLM-shield
powershell -ExecutionPolicy Bypass -File .\delivery\安装开发环境.ps1
.\delivery\启动隐盾.cmd
```

安装脚本创建项目虚拟环境并安装锁定依赖；只在不存在时从 `.env.example` 生成 `.env`，默认离线演示。
若要调用真实 API，在 `delivery/app/.env` 设置 `LLM_MODE=real` 并填写 `LLM_API_KEY`。
**不要把密钥提交到 Git**（`.env` 已被 `.gitignore` 拦截）。

仓库只保留约 1 MB 的动作模型（`models/necessity_action.joblib`），
**不含**便携 Python、虚拟环境或 GPU 模型权重。

### 手动启动

```bash
cd delivery/app
python run.py --host 127.0.0.1 --port 8787
```

### 运行时自检

```bash
python scripts/check_runtime.py     # 启动前检查模型与 API 配置（不打印密钥或模型路径）
python scripts/run_checks.py        # 一次性跑完全部测试与冒烟检查
python scripts/benchmark_local.py   # 只测本地处理耗时，不外呼、不落载荷
```

服务本身提供两个只读诊断端点：

| 端点 | 返回 |
|---|---|
| `GET /api/health` | 动作模型 / 识别器 / 真实 API 配置 / 会话容量的就绪状态；**不返回密钥与模型路径** |
| `GET /api/metrics` | 各阶段耗时中位数与 P95；每项最多保留最近 500 个数值，**只统计数字、不记录内容** |

本地识别与决策的并发上限由 `SHIELD_MAX_PARALLEL_ANALYSES` 控制（默认 2，范围 1–8）；
满载时新请求暂停并提示重试，避免并发把显存打满。

## 敏感信息识别

识别层由**两条路**组成，各司其职、类别不重叠，结果经统一合并策略归并：

| 检测器 | 负责类别 | 说明 |
|---|---|---|
| **正则规则**（常开） | 格式类 | 带校验位验证：身份证 GB 11643、银行卡 Luhn；手机号允许段内空格/连字符 |
| **词典 + 上下文**（常开） | 姓名 / 敏感属性 / 列名 | GLiNER 启用时让出机构/地点规则（词典的贪婪前缀边界过宽） |
| **GLiNER**（`SHIELD_USE_GLINER=true`） | 语义 5 类 | 人名 / 机构 / 地点 / 宿舍 / 敏感属性；基于 `gliner_multi-v2.1`（Apache-2.0）微调 |

**格式类永远交给正则，不交给模型**——实测让 GLiNER 覆盖 13 类会让高敏类别 F1
从 0.914 掉到 0.779（模型买到的是人名召回，付出的是格式类误报）。

启用方式：`delivery/app/.env` 中设 `SHIELD_USE_GLINER=true`。

### 模型目录

**决策模型随包放在项目内 `delivery/app/models/`**（约 1 MB），克隆即可运行，无需额外准备。
识别模型（GLiNER，约 1.1 GB）因体积不随仓库分发，需要用 `SHIELD_MODEL_DIR` 单独指向：

```
<SHIELD_MODEL_DIR>/                 # 默认取项目内 delivery/app/models/
  ├── necessity_action.joblib   决策模型（m4，总是加载，约 1 MB）
  ├── gliner_v3/                识别模型（m2，可选，约 1.1 GB）
  ├── gliner_multi_v21/         重训用基座
  └── gliner_multi/             重训用基座
```

> **启用 GLiNER 时 `SHIELD_MODEL_DIR` 必须是纯 ASCII 路径**：sentencepiece 的 C++ 后端
> 打不开含中文的路径，而项目目录名是「隐盾」。决策模型自己不需要这个限制
> （joblib 读中文路径没问题），所以默认值才敢用项目内 `models/`。
> `config.necessity_model_path()` 会先找统一模型目录、找不到再回退项目内 `models/`
> ——打包后的 exe 与默认克隆都走这条回退。

### 三个关键工程点

1. **字符级中文分词**：GLiNER 默认分词会把整串连续中文当成一个 token，导致实体边界错位。
   项目改用字符级分词器（`m2_detect/char_splitter.py`）。
2. **滑窗批量推理**：长文本按 `max_len-32` 滑窗，**所有窗口一次性批量送进模型**
   （`model.inference`）而不是逐窗循环；多份材料的窗口还会合成一批（每批最多 16 个窗口），
   结果按材料还原坐标。实测 2000 字从 ~500 ms 降到 **~190–210 ms**，
   这是把识别耗时压回「P50/P95 ≤ 500 ms」指标内的关键一步。
3. **合并策略**：同类别重叠取置信度更高的精确边界；跨类别冲突按检测器可信度排序（正则 > 模型），
   避免模型的高置信猜测覆盖带校验位的正则结果。

### 实测

识别层默认「正则 + 词典 + 语义类 GLiNER」（格式类由正则底座权威判定）。粒度无关口径 F1：

| 测试集 | 基线（正则+词典） | + GLiNER（语义 5 类，默认） | + GLiNER（13 类） |
|---|---|---|---|
| `gold_v3` test（旧留出集，**与训练语料同源**） | 0.8411 | **0.9500** | 1.0000 |
| `field_v1`（独立手写集，87 条 / 149 实体） | 0.7790 | **0.9068** | 0.8443 |

识别耗时（本机 RTX 5060，启用 GLiNER）：短文本中位数约 **25 ms**；
2000 字冒烟约 **192 ms**；三份材料约 **28 ms**；约 2000 字材料加长历史约 **427 ms**
（长材料单次最大值 492 ms）。样本数仍少，**不当作生产 P95** —— 实际请求的分阶段耗时用
`/api/metrics` 收集。

> **上表第二行才是可信的数字。** `gold_v3` 与训练语料出自同一个生成器——
> 身份证一律 `999999` 开头、邮箱一律 `@example.invalid`、80 条 test 里有 63 条
> 与训练集存在 8-gram 以上连续重合（78.8%），它衡量的是「有没有背下模板」。
> `field_v1` 是独立手写的 87 条真实场景文本（真实地区码、真实 BIN、真实域名、
> 复姓与少数民族姓名、大量数值诱饵），与训练语料的 8-gram 重合率仅 **2.4%**。
>
> 把 GLiNER 从 13 类收窄到语义 5 类，并在正则底座补上「带分隔符手机号、裸分数、
> wx_/wxid_ 微信 ID、ghp_/AKIA 密钥」四条规则后：独立集 F1 **0.8383 → 0.9068**，
> 高敏类别 F1 0.770 → 0.914，纯负例误报 13/17 → 10/17 条；同源旧集从 1.0000
> 降到 0.9500 —— 降掉的正是模型背下来的假密钥/裸分数模板，不是真实能力。
> 详见 [评测报告-独立手写集field_v1](docs/评测报告-独立手写集field_v1.md)。
>
> 两项指标都基于**合成或手写数据**，不能直接当作真实场景的隐私保护准确率。
> 回归门禁见 `delivery/app/tests/test_field_v1.py`：任何识别层改动都必须同时看这两把尺子。

### 模型权重不在仓库内

仓库只带**决策模型**（约 1 MB）与训练/评测脚本，**不带 GLiNER 权重**（约 1.1 GB）。
要启用语义识别需自行准备：

1. 取 `urchade/gliner_multi-v2.1`（Apache-2.0）与 `microsoft/mdeberta-v3-base` 的 tokenizer；
2. 用 `delivery/app/` 下的训练脚本微调；
3. 放到**纯 ASCII 路径**（如 `D:/project/models/gliner_v3`）——sentencepiece 的 C++ 后端
   打不开含中文的路径，而项目目录名「隐盾」正好是中文；
4. `.env` 设 `SHIELD_USE_GLINER=true`，用 `SHIELD_MODEL_DIR` 指向该目录，并按
   `requirements-gpu.txt` 装 GPU 依赖。

目录约定见上文「模型目录」；也可用 `SHIELD_GLINER_MODEL_DIR` 单独指定 GLiNER 目录。

## 当前实现边界

- **动作决策**：TF-IDF + 逻辑回归分类器本地选动作，安全校验**只接受或暂停，不做规则动作兜底**。
- **跨轮状态**：会话内代号已稳定（同一实体在同一会话永远得到同一代号），多轮历史进入模型输入；
  复检只豁免**本轮载荷中这些代号所在的准确位置**，不读取跨会话全局映射。
  **多轮一致性的人工验收尚未做** —— 机制已实现，但"多轮下来确实没出错"还没有证据。
- **细粒度决策**：含不同敏感类别的同一句会**按实体边界拆成互不重叠的决策片段**，
  所以"同句里姓名假名化 + 电话删除"已经能做到。尚未实现的是**单个片段内输出多个动作**。
- **组合式重识别**（如唯一奖项 + 组织 + 代号联合可重新识别到人）尚未覆盖。
- **身份与存储**：身份选择目前是界面配置，**不是**生产级身份认证；会话为进程内存储，
  仅支持单进程运行，重启后历史消失。多人部署需接可信身份源与持久化会话存储。
- 真实 API 已用**公开短文本与合成 Excel** 验证连通；人工任务评测、多轮一致性验收与
  第二台干净设备部署仍待补，不能据现有工程检查推断真实场景任务完成率。
- 合成弱标签分数和离线测试**不能**当作真实隐私保护准确率。
