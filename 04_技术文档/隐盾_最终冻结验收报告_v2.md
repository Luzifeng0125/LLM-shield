## 任务 3：C3 的词表外状态

上一版允许「核准」以及词表外说法记为 `unmentioned` 或 `unparsable`。两种 `kind` 的意义不同，出口不唯一。

v2 第 4.2 节改成一张五行之表，全篇沿用：

| 情况 | C3 输出 |
| --- | --- |
| 原文没有提及状态 | `unmentioned` |
| 原文明确提及词表内状态 | 对应规范值 |
| 原文提及状态，但词表不能得到唯一规范值 | `unparsable` |
| 原文两个相互矛盾的状态 | `unparsable` |
| 属性不需要状态 | `not_applicable` |

「核准」只对应 `unparsable`。同一句重复同一个可映射状态仍是一个规范值。同一句内部的矛盾状态不拆成两条活动值。两条证据分别给出不同状态，才进入 Source Conflict 资格判断。

## 任务 4：Source Conflict 的分组

上一版已经把 Claim Relation 和 Source Conflict 分开，也有时间切片，但还没有把“哪些证据有资格比较”写成同时成立的条件。两个不同数字仍可能被直接当成冲突。

v2 第 7.2 节规定，七条全部成立才进入冲突比较：主体一致、属性一致、范围一致、口径一致、时间重叠或不能证明不相交、同一维的规范值明确且不相容、不存在已接受的父子修订或已接受的更新关系。`fact_key` 只索引前四个身份字段，有效时间另判。任一身份字段为空时不生成可比较的 `fact_key`。

| 边界 | 方案结果 | 验收 |
| --- | --- | --- |
| 同一事实、同一时间、不同金额 | `conflict`，`paused` | T7-a |
| 同一事实、有效时间不相交 | `temporal_slice`，不直接冲突 | T12、T12-a |
| 同一主体、不同属性 | 不同 `fact_key`，不冲突 | T7-b |
| 同一属性、不同口径 | 不直接记 Source Conflict | T7-c |
| 父子修订 | 旧值退出活动集 | T2，以及 T7 夹具中的对照 |
| 多条证据只填写不同必要维 | 允许联合支持 | 第 7.2 节与 T13 |
| 同一必要维无法消除的矛盾 | `paused`，不得用结论挑选 | T7、T7-d |

时间一边或两边为 `unmentioned` 时，方案不把它当成已经证明的另一时段，因此仍可进入比较。时间为 `unparsable` 时资格不能判定，直接 `paused`。这个处理是保守拒判，不是把缺失时间写成冲突或非冲突。

联合支持没有被取消。金额和状态可以来自同一事实身份下的不同锚点。身份不全的句子必须先通过链接，不能用半边值拼事实。身份已经相同的句子不必再靠指代链接才能比较。

## Claim Assertion 的必要维度

证据侧原来已有 `unparsable` 和 `unmentioned` 的处理，结论侧没有对称规则。结论没写清时，仍可能被证据里的某个值撑成支持。

v2 第 2 节和第 7.2 节现在是同一组判定：

| 情形 | `claim_relation` | 四态 |
| --- | --- | --- |
| 结论侧必要维 `unparsable` | `blocked` | `paused` |
| 结论侧必要维 `unmentioned` | `missing`，不是 `match` | `paused` |
| 证据侧必要维 `unparsable` | `blocked` | `paused` |
| 证据侧必要维 `unmentioned` | `missing` | `paused` |
| 两边都是 `value` 且不相等，没有未解决的证据间冲突 | `mismatch` | 其余必要维均已确定时为 `invalid` |
| 证据之间冲突未解决 | 不挑选一边 | `paused` |

不必要的维度不沿用这张表。人数的状态是 `not_applicable`，不因为没写状态而暂停。两边都没写有效时间时，有效时间不是必要维。

第 8 节的 T4 附例把这六条放进现有夹具。没有新增 T 编号。现有 T1–T13 的金标不需要改写：T1 的两边都有确定状态且不相等，所以仍是 `invalid`；它不是“结论没写状态”。

## C3/C4 公平性

实验 A 使用同一 `registry_sha256`，只比较链接类型、目标和依据片段是否符合链接金标。注册表中的身份槽位不属于链接器的发现。人工登记必须标记为受控子任务。

实验 B 才把注册表错误、提取错误和链接错误一起计入组级四态，并且禁止使用人工增删后的注册表。C4 即使运行，替换的也是提取或链接，不是候选发现。方案因此不宣称端到端的候选发现创新。

状态对照使用同一原始锚点。「核准」在 C3 固定为 `unparsable`，C4 可以提出 `approved`，只与金标比较。比较前不得修改 C3 词表。

C4 看不到 C3 的提取、链接和解释。模板哈希覆盖注册表哈希。没有获准的离线模型时，C4 记为未执行，不用 C3 的输出填空。
