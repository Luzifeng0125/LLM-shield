## 2. 四态

判定对象是当前修订是否许可这句结论。原始快照只负责追溯当时引用了哪一段。

结论得到支持，必须是每个必要维在结论侧和活动证据侧都有确定规范值，并且两边相等。结论自己没写清的必要维，不能因为证据里有一个值就算支持。

| 状态 | 条件 | 交付 |
| --- | --- | --- |
| `still_valid` | 定位唯一；当前引文指纹与原始引文相同；没有未解决的证据间冲突；每个必要维在结论侧和活动侧都是 `value` 且规范值相等 | 仍须过 `precheck` |
| `affected_still_valid` | 定位唯一；当前引文指纹已经变化；重新提取成功；活动值与结论在每个必要维上都是相等的 `value` | 仍须过 `precheck`，并标记原文已变 |
| `invalid` | 定位和提取完成；结论侧必要维都有确定规范值；每个必要维的活动侧也有唯一 `value`；至少一维与结论不相等；证据之间没有未解决冲突 | 不交付 |
| `paused` | 定位失败或不唯一；需要继承身份但链接被拒绝；必要维在结论侧或证据侧为 `unmentioned` 或 `unparsable`；证据之间存在未解决冲突 | 不交付 |

一组里有一条 `invalid` 或 `paused`，整次不交付。一句的证书不读取另一句结论的状态。

必要维的六条闭包见第 7.2 节。这里先固定四态与那六条的对应关系：

| 情形 | 四态 |
| --- | --- |
| 结论侧必要维为 `unparsable` | `paused` |
| 结论侧必要维为 `unmentioned` | `paused`，不是 `match` |
| 证据侧必要维为 `unparsable` | `paused` |
| 证据侧必要维为 `unmentioned` | `paused` |
| 两边都是 `value` 但不相等，且该维没有未解决的证据间冲突 | 该维为 `mismatch`；其余必要维均已确定时，四态为 `invalid` |
| 证据之间存在未解决冲突 | `paused`。不用结论挑选其中一条 |

不必要的 `unmentioned` 不阻断。例如人数属性的状态应为 `not_applicable`，不因为状态没写而暂停。

## 3. 三个不能混用的概念

| 概念 | 产生位置 | 回答的问题 | 例子 |
| --- | --- | --- | --- |
| Evidence Assertion | L3 | 这条证据自己写了什么 | 原文写 8000 元，提取结果就是 8000 元 |
| Claim Relation | L4 | 这个活动值与披露结论是否一致 | 结论写 9000 元，比较结果是 `mismatch` |
| Source Conflict | L4 | 同一适用事实范围内，几条证据的活动值是否互相不一致 | 同一活动、同一口径、同一时间，一条写 12 人，另一条写 15 人，且没有修订关系 |

L3 不输出 `supports`、`contradicts`、`match` 或 `mismatch`。原文写 8000、结论写 9000 时，证据提取保持 8000，关系在 L4 才出现。

三月 12 人与四月 15 人不是 Source Conflict。它们没有进入“同一适用事实范围”。第 7.2 节先做身份和适用范围匹配，然后才允许比较数值。

## 4. 标识、主体库与状态

### 4.1 标识

普通 SHA-256 只做实验库内部的完整性校验，不能称为匿名化。低熵标识使用 HMAC-SHA256。密钥两把，放在仓库外的本地文件，不进 Git：`vault_key` 用于主体、范围、结论编号和引文指纹；`export_key` 用于离开本机的导出编号。本机 2–3 名研究人员按操作系统权限读取。一年轮换一次，或在怀疑泄露时立即轮换。不建设密钥管理系统。

显示值取前 16 位十六进制，内部保存完整 64 位。下列示例用密钥 `example-only-not-for-real-data` 与 `example-export-key-not-for-real-data` 算出，不得用于真实数据。

| 标识 | 算法 | 示例或作用 |
| --- | --- | --- |
| `subject_id` | HMAC(`vault_key`, 主体类型 + 库内聚类键) | 聚类 `cluster-014` 得到 `749f861b0fbd1072` |
| `context_scope_id` | HMAC(`vault_key`, 范围类型 + 范围本地键) | `4d269c18534694f5` |
| `grain_id` | 封闭口径表代号 | 不哈希自由文本 |
| `fact_key` | 库内 SHA-256(主体、属性、范围、口径) | `1a66661bf4e82f14`。不含值、有效时间、观察时间和修订号 |
| 导出事实号 | HMAC(`export_key`, `fact_key`) | `c7734f7298074011` |
| `fact_version_id` | HMAC(`vault_key`, `fact_key` + 值 + 单位 + 极性 + 状态 + 有效时间) | 值变化则版本变，身份不变 |
| `evidence_id` | HMAC(`vault_key`, 内容指纹 + 修订 + 定位) | 某次修订中的绑定 |
| `revision_id` | HMAC(`vault_key`, 文档系列 + 父修订 + 全文指纹 + 修订时间) | 修订事件 |
| `claim_id` | HMAC(`vault_key`, 披露编号 + 原子序号 + 规范元组) | 原子结论 |
| `candidate_id` | HMAC(`vault_key`, `revision_id` + `evidence_anchor` + 已填身份字段) | 公共注册表中的候选。不含金额、状态、极性和结论 |

对范围名 `spring-recruit` 直接做 SHA-256 得到 `28557b79c5a929b4`。这个值可以被猜出来，方案不使用它。

主体、属性、范围、口径四个字段都非空时才计算 `fact_key`。任一为空，不生成可比较的 `fact_key`，也不进入 Source Conflict。该事实若仍被结论依赖，按必要身份缺失暂停。两个空主体不算同一主体。

主体库保存姓名、学号、电话与 `subject_id` 的对应，不导出。实验库保存全文和证书，不导出。导出包只有 HMAC 编号、维度种类和金标状态。同名且没有区分信息时不分配 `subject_id`。禁止用姓名哈希当主体号。

### 4.2 属性与状态

状态不进入 `fact_key`。`status_required` 写在属性上。任务模板不能把“必要”改成“不必要”。今年四个任务没有追加必要状态。极性对全部属性都必要，并且与状态分两个字段保存。

| `attribute_id` | 状态是否必要 | 主要模板 |
| --- | --- | --- |
| `participant_count` | 否 | activity_stats |
| `event_time` | 否 | activity_notice、activity_stats |
| `location` | 否 | activity_notice、meeting_minutes |
| `person_role` | 否 | meeting_minutes |
| `task_item` | 是 | meeting_minutes |
| `deadline` | 否 | meeting_minutes |
| `budget_amount` | 是 | meeting_minutes、project_intro |
| `public_fact` | 否 | project_intro、activity_notice |

每个维度使用同一种带标签的值。业务状态不和“没说”“说了但不能规范化”混在一个枚举里。

| `kind` | 含义 |
| --- | --- |
| `value` | 已明确表达一个规范值。状态的规范值见下表 |
| `unmentioned` | 文本没有说及这一维 |
| `not_applicable` | 该属性不使用这一维 |
| `unparsable` | 文本说及了这一维，但不能确定唯一规范值 |

状态的 `value` 只允许：`suggested`、`planned`、`requested`、`pending`、`not_yet_approved`、`approved`、`rejected`、`completed`、`cancelled`。  
`unmentioned`、`unparsable`、`not_applicable` 都不是审批结果，不放进这张业务表。不得输出 `unspecified`，也不得在缺少状态或不能确定状态时填 `approved`。

极性的 `value` 只允许 `affirm` 和 `neg`。否定词本身不推出业务状态。

C3 状态规则只有下面这一张表。同一个表达不得在后文改成另一种 `kind`。

| 情况 | C3 输出 |
| --- | --- |
| 原文没有提及状态 | `unmentioned` |
| 原文明确提及词表内状态 | 下表中的规范值 |
| 原文提及状态，但词表无法得到唯一规范值 | `unparsable` |
| 原文出现两个相互矛盾的状态表达 | `unparsable` |
| 属性不需要状态 | `not_applicable` |

C3 整词映射只产生规范值，不产生“没说”：

| 表达 | 规范值 |
| --- | --- |
| 建议、拟、考虑 | `suggested` |
| 计划、准备 | `planned` |
| 申请、提请 | `requested` |
| 正在审批、等待审批 | `pending` |
| 尚未批准、还未批准 | `not_yet_approved` |
| 批准、已同意、通过 | `approved` |
| 已否决、已驳回 | `rejected` |
| 已完成、已落实 | `completed` |
| 取消 | `cancelled` |

下列表达提及了审批结果，但不能映射到唯一规范值，C3 固定为 `unparsable`，不是 `unmentioned`：

| 表达 | C3 输出 | 原因 |
| --- | --- | --- |
| 未批准、未获批准、没有批准 | `unparsable` | 否定范围不能确定为唯一业务状态 |
| 核准 | `unparsable` | 词表外的状态提及 |
| 其他词表以外的状态说法 | `unparsable` | 词表外的状态提及 |

「核准」只有 `unparsable` 这一个 C3 结果。不得输出 `unmentioned`，也不得为了让 C4 更好看而把「核准」加入 C3 词表。C4 可以另行提出它等于 `approved`。该判断只有人工金标能计分，结构校验不因为它不在 C3 词表里就否决，也不因为它是合法枚举值就判对。

同一句里重复同一个可映射状态，例如“批准，已经批准”，仍是一个 `approved`。同一句里出现互相矛盾的状态，例如“已批准”和“已否决”同时出现，该维为 `unparsable`，不拆成两条活动值。两条不同证据分别写出 `approved` 和 `rejected`，才按第 7.2 节进入 Source Conflict 资格判断。

“尚未批准”不得写成 `rejected`。“已否决”“已驳回”才是 `rejected`。“尚未达到 12 人”改的是人数极性，状态为 `not_applicable`，不是 `not_yet_approved`。

提取器对某一维弃权时，证书按上表落值，不得一律写成 `unmentioned`。没有提及才是 `unmentioned`；提及了但不能规范化，是 `unparsable`。链接步骤里的 `abstain` 只表示拒绝建立指代，不改写这一维的 `kind`。

状态替换只在两种关系下发生：同一锚点的父子修订，或第 6.4 节已经接受的更新关系。新陈述只替换它自己明确写出的维。没有这两种关系时，两个不同的活动状态若已通过冲突资格判断，就是 Source Conflict，结论 `paused`。相近的措辞本身不是修订。

## 5. 定位

| 对象 | 含义 |
| --- | --- |
| 原始快照 | 生成披露时的修订 |
| 当前修订 | 现在要复核的修订，带父修订号 |
| 原始定位 | 快照中的 `block_id` 或业务键，以及当时的引文 |
| 当前定位 | 当前修订中唯一对应的锚点 |
| 内容变化 | 两个引文指纹不同 |
| 事实变化 | 重新提取后的活动值与结论不同 |

当前定位按顺序进行，没有模糊相似度：

1. 全文指纹相同，且原定位仍在范围内。
2. 表格工作表、业务键和列标识恰好一行。文字变了也使用这一格。
3. 夹具 `block_id` 在当前修订中恰好一次。文字变了也使用这一段。
4. 原始引文经换行规范化后在当前全文恰好出现一次。这一步找不到改写句。
5. 零次或多次：`paused`。

| 检查 | 通过条件 | 失败 |
| --- | --- | --- |
| L1 原始 | 定位落在生成快照内且唯一 | `paused` |
| L2 原始 | 该位置字节与保存的原始引文一致。只允许统一换行并去掉末尾至多一个换行 | `paused` |
| L1 当前 | 上面五步得到唯一锚点 | `paused` |
| L2 当前 | 送去提取的字符串就是该锚点的字节 | `paused` |

L2 当前不要求与原始引文相同。`affected_still_valid` 还要求当前字节重新提取成功，并且每个必要维都与结论相等。链接依据的起止位置也使用这条 L2 字符串，见第 6.4 节。

## 6. 双通道、公共候选注册表与链接

### 6.1 通道里有什么

结论通道的输入只有披露文本和封闭表版本。它输出 Claim Assertion，字段与证据提取相同，对象是结论句。它看不到任何原文，也不参与生成候选。

证据提取对每个锚点单独进行。输入只有该锚点的当前字节和封闭表。看不到披露文本，看不到结论标签，看不到其他锚点的金额和状态，也看不到公共注册表以外的候选。输出是 Evidence Assertion。C3 与 C4 的提取结果可以不同。提取结果不能增删公共候选。

证据链接只建立身份继承，不改写已经提取的金额、状态、极性和单位。C3 和 C4 接收同一份公共候选注册表。

### 6.2 公共候选注册表

注册表是一份事实身份目录。它回答“当前修订里有哪些可指称的证据锚点，以及结构上能确定的主体、属性、范围和口径”。它不回答这些锚点的金额、状态、极性、有效时间，也不回答它们是否支持披露结论。

生成程序是实验目录中的确定性程序 R0，规格名 `yin-dun.candidate_registry.v1`。R0 不是 C3，不是 C4，也不是现有产品里的动作模型或 GLiNER。R0 本轮尚未编写。

R0 只读取：

- 夹具已经划出的锚点，以及该锚点的原始字节。锚点来自 `block_id` 或表格业务键，不来自 C3/C4。
- 文档结构：父节树、表名、列标识。
- 冻结的结构映射：列标识到 `attribute_id`，封闭口径代号，节标题或范围字段到范围本地键的精确映射。
- 主体库中已经存在的结构键。自由文本姓名不在 R0 中做哈希。

R0 不读取：

- 披露文本、Claim Assertion，以及结论中的金额、状态、极性、有效时间。
- 最终金标，包括四态、链接金标、冲突金标和候选身份金标。
- C3 或 C4 的提取、链接、解释和置信度。
- 任何按“是否与结论一致”作出的筛选、排序或截断。

处理边界：

1. 每个夹具锚点最多一条候选。不按结论合并，也不因为后来提取失败而删除。
2. `parent_scope` 只取父节树中的父节点。没有父节则为空字符串。空父节的候选不能参与跨句链接。
3. `context_scope_id` 只在范围映射命中时填写。父节编号不得直接当作活动范围。
4. `attribute_id`：表格用列映射；正文只用冻结属性中心词的整词匹配。零次或多次命中都保留候选，该字段为空字符串。R0 不猜测属性。
5. `grain_id` 只接受封闭口径表中的精确代号，或表格里的口径列。否则为空字符串。
6. `subject_id` 只按结构键查询主体库。同名且不能区分时不分配，与第 4.1 节相同。
7. 七个字段全部写出。未知用空字符串，不用缺键，也不用结论里的值填空。
8. 注册表中不出现 `numeric_value`、`unit`、`status`、`polarity`、`valid_time`、披露原文和金标。
9. 输出规范 JSON，并计算整表的 `registry_sha256`。

候选记录的字段固定为：

| 字段 | 内容 |
| --- | --- |
| `candidate_id` | 第 4.1 节的 HMAC。同一输入始终得到同一编号 |
| `evidence_anchor` | 该候选自己的锚点，不得为空 |
| `subject_id` | 结构键对应的主体。不能确定则为空 |
| `attribute_id` | 列映射或中心词唯一命中。不能确定则为空 |
| `context_scope_id` | 活动或组织范围。不能确定则为空 |
| `grain_id` | 封闭口径代号。不能确定则为空 |
| `parent_scope` | 父节标识。没有则为空 |

```json
{
  "schema": "yin-dun.candidate_registry.v1",
  "registry_sha256": "<整表哈希>",
  "candidates": [
    {
      "candidate_id": "asrt_a",
      "evidence_anchor": "block:a1",
      "subject_id": "749f861b0fbd1072",
      "attribute_id": "budget_amount",
      "context_scope_id": "4d269c18534694f5",
      "grain_id": "grain_travel",
      "parent_scope": "sec_1"
    }
  ]
}
```

上例只说明字段。它不是一条已经实现的注册结果。

人工是否参加：

- R0 的运行步骤里没有人工筛选。
- 若某一轮改由人按原始证据和文档结构登记候选，文件头必须写 `registry_origin = human_controlled`。这只构成第 10 节的受控指代实验，不得写成端到端的人工智能发现。
- 人工登记只能看到原始证据和文档结构。不能看到披露结论、最终金标，以及 C3/C4 的输出。
- 注册表在链接金标和四态金标开始之前冻结，并记录哈希。看到金标之后不得回头增删候选。
- 本年只有 2–3 名研究人员。登记者和金标标注者可能是同一批人。做不到人员分离时，仍须先冻结哈希；该次运行不得报告为端到端能力。人员分离做不到，就明确写成限制，不用流程措辞把它说成已经盲化。

C3 与 C4 的输入一致：

- 两边加载同一文件、同一 `registry_sha256`。哈希不同，该次对照作废。
- 发给某一锚点的上下文是该注册表中 `parent_scope` 相同的全部候选。切片只按父节相等，不按句子相似度，也不按结论筛选。
- 两边的切片规则相同，因此切片结果相同。模型不得缩小这个集合。
- 提示模板哈希必须覆盖注册表哈希。检查模板时同时检查注册表。

候选生成阶段自身的错误单独计数，对照的是候选身份金标。该金标只含七个身份字段，不含披露是否成立，也不能反过来删改注册表。错误分为漏登记、多余登记、身份字段错误。实验 B 把这三类错误计入端到端结果。实验 A 报告它们，但不把它们算作 C3 或 C4 的链接能力。

属性中心词覆盖有限。自由文本没有唯一中心词时，`attribute_id` 保持为空。这会减少可链接候选，或使事实身份不能建立。这个缺口保留为 R0 的错误，不用人工补全后冒充程序已经识别。

### 6.4 链接输出与程序验证

C4 的链接输出必须包含：

| 字段 | 要求 |
| --- | --- |
| `link_type` | `explicit_coreference`、`implicit_semantic_reference`、`ellipsis`、`abstain` 之一 |
| `target_candidate_id` | `abstain` 时为空。否则必须是注册表中的 `candidate_id` |
| `basis_span` | 当前证据 L2 原文中的连续片段。`abstain` 时为空 |
| `basis_start` | 该片段在 L2 字符串中的起点，按 Unicode 码位 |
| `basis_end` | 终点，不含自身 |
| `link_rationale` | 只供审计。不参与接受或拒绝 |

```json
{
  "schema": "yin-dun.link_decision.v1",
  "link_type": "explicit_coreference",
  "target_candidate_id": "asrt_a",
  "basis_span": "上述建议",
  "basis_start": 0,
  "basis_end": 4,
  "link_rationale": "审计说明，不是正确性证明"
}
```

`basis_start` 与 `basis_end` 的例子取决于 L2 字符串。夹具必须用实际字符串核验，不照抄这里的数字。

程序先看 `link_type`。值为 `abstain` 时不建立链接，也不再检查目标、片段和唯一性。这是允许的结果，不是结构故障。其他三种类型才继续做下列检查，任一项失败都拒绝链接，并记为结构失败：

1. `target_candidate_id` 在本次公共注册表中存在，且不属于当前锚点自己。
2. `basis_span` 非空，且与当前证据 L2 原文的对应切片完全一致。
3. `0 ≤ basis_start < basis_end ≤ 文本长度`，并且 `text[basis_start:basis_end]` 就是 `basis_span`。
4. 目标候选的 `parent_scope` 与当前证据的父节相同，且不为空。
5. 当前锚点若也有候选记录，则主体、属性、范围、口径中双方都已填写的字段不得不一致。空字段不构成冲突，也不构成一致。
6. 可链接集恰好包含这一个目标。可链接集是同一父节中、与当前候选没有第 5 步硬冲突、且不是当前锚点自己的全部候选。零个或多个都拒绝。
7. `link_type` 为 `explicit_coreference` 时，`basis_span` 必须包含 C3 显式词表中的一项。隐式指代和省略不使用这个词表。

`link_rationale` 不读取、不评分、不能补救失败的片段或失败的唯一性。原文中确实存在这段话，只说明位置真实，不说明它指向目标候选。结构验证通过之后，链接是否正确仍由人工链接金标评价。

候选不唯一时必须拒绝，即使句中有“上述”。候选唯一但没有可定位依据时也必须拒绝。唯一性不是语义关系。

C3 继续只用显式词表和程序计数。词表为“上述、该预算、此项”。C3 的 `link_type` 只允许 `explicit_coreference` 或 `abstain`。程序在当前 L2 原文中定位词表命中，并填写 `basis_span` 与起止位置。没有命中则 `abstain`，即使可链接集大小为 1。命中且可链接集大小为 1 时，目标就是那一个候选。命中但大小不是 1 时拒绝。C3 不输出 `implicit_semantic_reference` 或 `ellipsis`。

C4 可以输出四种 `link_type`。非显式关系必须提交当前原文中的依据片段。没有片段、片段不存在或位置错误，程序拒绝。结构通过只表示可以进入金标比较。

是否需要链接，只看当前锚点在公共注册表里的四个身份字段，不看 C3 或 C4 的提取结果。四个字段任一为空，当前锚点不能独立形成 `fact_key`，必须链接成功后才继承目标身份。链接失败则 `paused`，不用已经提取到的半边值判 `invalid`。四个字段都已填写时，不因为父节里还有其他候选而强制链接。

注册表身份已经相同的不同锚点，可以在不同维度上联合支持，也可以在同一维度上进入冲突比较。这条路径不需要额外的指代链接。指代链接只补齐缺失身份，不把两个身份不同的锚点直接拼成一个事实。同一锚点的新旧版本则只走父子修订。

已接受链接可以成为更新关系，但只替换新证据明确写成 `value` 的那些维。金额和状态仍来自各自锚点的 L3，不来自注册表，也不来自结论。

G04 的「核准」没有显式词表。C3 对状态输出 `unparsable`；句中若没有“上述、该预算、此项”，C3 的链接为 `abstain`。C4 可以提出 `implicit_semantic_reference` 或 `ellipsis`，并提交依据片段。程序仍检查存在性、位置、父节、硬冲突和唯一性。唯一候选本身不使该链接成立。C4 把「核准」提成 `approved` 是否正确，只由状态金标决定。

结论通道与证据提取仍然互相看不见。注册表和上下文包不把它们连起来。

## 7. L3 与 L4

### 7.1 L3：Evidence Assertion Extraction

必要字段：`subject`、`attribute`、`context_scope`、`grain`、`numeric_value`、`unit`、`valid_time`、`polarity`、`status`、`evidence_location`。每一维都是第 4.2 节的 `kind`。

```json
{
  "schema": "yin-dun.evidence_assertion.v1",
  "evidence_id": "ev_b",
  "revision_id": "rev_2",
  "evidence_location": {"anchor": "block:b1", "quote_sha256": "..."},
  "dimensions": {
    "subject": {"kind": "unmentioned"},
    "attribute": {"kind": "unmentioned"},
    "context_scope": {"kind": "unmentioned"},
    "grain": {"kind": "unmentioned"},
    "numeric_value": {"kind": "unmentioned"},
    "unit": {"kind": "unmentioned"},
    "valid_time": {"kind": "unmentioned"},
    "polarity": {"kind": "value", "value": "affirm"},
    "status": {"kind": "value", "value": "approved"}
  }
}
```

上例对应“上述建议已经批准。”这是提取结果的形状：状态为 `approved`，金额未提及。它还不知道自己是否支持某句结论，也不代替注册表。C3 遇到「核准」时，同一位置的状态必须是 `{"kind": "unparsable"}`，不能写成 `approved`，也不能写成 `unmentioned`。

结构校验：

- `value` 的状态和极性必须落在封闭表内。
- 数值类 `value` 必须能由引文按已冻结的折叠规则得到。引文里没有的数，改成 `unmentioned`，并记一条提案错误。
- 同一维不能有两个 `kind`。
- 属性不需要状态时，状态必须是 `not_applicable`。
- 需要状态但文本没有提及时，是 `unmentioned`。
- 文本提及了状态但不能按第 4.2 节得到唯一规范值时，是 `unparsable`。「核准」属于这一类。
- 证书不拿 C3 词表否决 C4 的合法状态值。「核准」可以被 C4 标成 `approved`。结构校验只确认它属于封闭枚举；对错由金标判断。

结论通道使用同一字段结构和同一 `kind` 规则，schema 名为 `yin-dun.claim_assertion.v1`，并且没有 `evidence_location`。结论侧的「核准」同样不是自动的 `approved`。C3 规则下它是 `unparsable`。结论表达不清楚时，不得把它改写成证据里已经出现的状态。

### 7.2 L4：Claim-Evidence Verification

L4 的输入是独立的 Claim Assertion、若干 Evidence Assertion、已接受或已拒绝的链接、父子修订，以及注册表身份。输出三个部分：活动值、`claim_relation`、`source_conflict`，然后是四态。

证书使用的事实身份只取注册表。未链接的锚点使用自己的四个身份字段。已接受链接的锚点使用目标候选的四个身份字段，不用当前句里的空字段覆盖目标。L3 提供金额、单位、有效时间、极性、状态，以及供人工抽查的身份提取记录；L3 的身份字段不改写 `fact_key`。因此 C3 和 C4 的事实分组相同，不会因为某一通道先抽出了主体或属性而改变冲突比较的范围。身份字段提错，记在注册表错误里，不记成链接增益。

活动值按维度收集。一个维度上，被父子修订或已接受更新关系替换的旧值保留在提取记录里，但退出活动集。替换只覆盖新陈述明确写出的维。

`claim_relation` 的每一维只比较活动值与结论：

| 值 | 条件 |
| --- | --- |
| `match` | 两边都是 `value` 且规范值相等 |
| `mismatch` | 两边都是 `value` 且规范值不等 |
| `missing` | 该维必要，但结论侧或活动侧没有 `value`。`unmentioned` 落在这里 |
| `not_applicable` | 该维对这个属性不适用 |
| `blocked` | 结论侧或活动侧为 `unparsable`，或本句需要的链接被拒绝 |

`unmentioned` 不是 `match`。结论侧必要维为 `unmentioned` 时是 `missing`，随后 `paused`，不能因为证据侧有值就改成 `match`。

Source Conflict 先做资格判断，再比较数值。`fact_key` 是主体、属性、范围、口径的稳定索引，不含有效时间。时间另判。

两条证据进入某一维的冲突比较，必须同时满足：

1. 主体都已填写且相同。
2. 属性都已填写且相同。
3. 组织或活动范围都已填写且相同。
4. 统计口径都已填写且相同。
5. 有效时间重叠，或不能证明它们属于不相交的时间。两条都是 `value` 且交集为空时，不合格，记 `temporal_slice`。一边或两边为 `unmentioned` 时，不能证明不相交，因此时间条件仍成立。任一边为 `unparsable` 时，资格不能判定，该组 `paused`，既不宣布冲突，也不宣布清除。
6. 这一维两边都是明确的 `value`，且规范值不相容。
7. 不存在已经接受的父子修订，也不存在已经接受、并且由新证据明确写出该维的更新关系。

不同 `fact_key`、不同口径、不相交的有效时间，不得直接记为 Source Conflict。仅仅出现两个不同数字，不足以产生冲突。

| `source_conflict` | 条件 |
| --- | --- |
| `none` | 没有一对证据同时满足上面七条 |
| `conflict` | 至少一对证据满足上面七条 |

多证据联合支持继续保留。材料 A 只写出 8000 元，材料 B 只写出已批准，二者在链接之后成为同一事实身份，并且各自填写不同维度时，可以同时活动。任一必要维上出现两个未被修订消除的不相容 `value`，则 `paused`。禁止用披露结论选择其中一条作为正确答案。

必要维：主体、属性、极性、口径始终必要；今年的属性都有数值和单位；状态在 `status_required` 为真时必要；结论或活动证据写出了有效时间时，有效时间必要。两边都没写有效时间时，有效时间不是必要维。

闭包顺序：

1. L1 或 L2 失败，直接 `paused`。
2. 运行 R0，冻结注册表哈希。此步没有结论、没有金标、没有 C3/C4 输出。
3. 对每个当前锚点做 L3。此步没有结论，也不改注册表。
4. 对需要继承身份的锚点做链接。拒绝的链接不传递身份。
5. 用父子修订和已接受的更新关系确定活动值。旧值退出活动集的范围只限于新陈述明确写出的维。
6. 先做 Source Conflict 资格判断。任一必要维为 `conflict`，结论 `paused`。不用结论挑选一边。
7. 需要继承身份但链接被拒绝：不合并，结论 `paused`。不用半边证据判 `invalid`。
8. 任一必要维为 `missing` 或 `blocked`，结论 `paused`。这包括结论侧必要维 `unmentioned` 或 `unparsable`，也包括证据侧必要维 `unmentioned` 或 `unparsable`。
9. 每个必要维都是 `match`：指纹未变则 `still_valid`，指纹变了则 `affected_still_valid`。
10. 每个必要维都是确定的 `match` 或 `mismatch`，至少一维为 `mismatch`，且没有未解决冲突：`invalid`。

表格人数由程序按口径重算。重算结果与活动数值不同时，该数值不进入 `match`。模型不能改这个数。

有效时间不相交的陈述不进入该结论的活动集，关系记为 `temporal_slice`，不是冲突。

### 7.3 T13 的实际步骤

材料 A，锚点 `a1`：“建议将差旅预算调整为 8000 元。”  
材料 B，锚点 `b1`：“上述建议已经批准。”  
父节 `sec_1` 的可链接候选只有 A。结论：“差旅预算已经批准为 8000 元。”

1. R0 只从 A、B 的原文和父节结构生成注册表。A 的四个身份字段均已填写。B 仍保留为候选，但属性为空，不能独立形成 `fact_key`。注册表不写 8000，不写“建议”或“批准”，不写结论。
2. 结论通道得到金额 `8000`、单位元、状态 `approved`、极性 `affirm`、口径差旅。没有原文。
3. L3(A) 得到金额 `8000`、状态 `suggested`。没有结论。
4. L3(B) 得到状态 `approved`、金额 `unmentioned`。没有 A 的金额，也没有结论。
5. B 的上下文包是同一注册表的父节切片，外加 B 的原文。没有金额和状态。
6. C3 在 B 的原文中定位“上述”，填写依据片段和起止位置。可链接集为 `{A}`，大小为 1，接受链接。
7. 链接继承 A 的主体、属性和口径，不继承 8000，也不继承“建议”。
8. B 明确写出了状态，所以 A 的 `suggested` 退出活动集。A 的 8000 仍然活动。
9. 金额只有一个活动值，状态只有一个活动值，`source_conflict` 为 `none`。两边与结论都是 `match`。
10. 若 B 的文字与生成时保存的引文相同，四态为 `still_valid`。

父节里再加一笔可链接预算时，第 6 步可链接集大小为 2。即使“上述”存在，链接也拒绝，闭包因此 `paused`。  
父节只有 A，但当前句是“场地申请另案处理。”时，C3 没有显式词，必须 `abstain`。只因为候选唯一而连到 A，是错误链接。正确结果为 `paused`。  
只有 A、没有 B 时，活动状态是 `suggested`，与结论的 `approved` 为 `mismatch`，四态为 `invalid`。这是 T1。

## 9. 指标

交付指 `still_valid` 或 `affected_still_valid`。

| 指标 | 定义 |
| --- | --- |
| 错误接受 | 金标为 `invalid` 或 `paused`，系统却交付 |
| 过度失效 | 金标可交付，系统给 `invalid` |
| 过度暂停 | 金标可交付，系统给 `paused` |
| 覆盖率 | 系统给出交付或 `invalid` 的比例 |
| 选择性错误接受率 | 系统交付的结论中，金标不可交付的比例 |
| 注册表漏登记、多余登记、身份字段错误 | 只评价 R0 或人工受控登记，不记入 C4 的链接增益 |
| 链接结构失败 | 依据片段不存在、位置错误、候选不存在、不唯一或硬冲突。这是程序拒绝，不是模型语义分 |
| 链接语义错误 | 结构通过，但目标或类型与链接金标不一致 |

全暂停会使错误接受变成 0，覆盖率也是 0。只报错误接受的结果不予接受。

统计单位是文档组。连续 n 组没有错误接受时，95% 上界约为 3/n，并报告 Clopper–Pearson 上界。18 组约 16.7%，测试 12 组约 25%。上界到 5% 大约需要 60 组，今年不承诺。与基线比较用文档组配对的精确 McNemar 检验。零错误接受不写成零风险。

## 10. 对照与两种实验

| 组 | 提取者 | 证书与上下文 |
| --- | --- | --- |
| C0 | 现有隐盾 | 不产生证书 |
| C1 | 字符串相等，同名即同一人 | 无 |
| C2 | 只做 L1/L2 | 无 L3/L4 |
| C3 | 规则词表和显式指代词 | 第 7 节证书，第 6 节同一注册表 |
| C4 | 获准的离线指令模型 | 同一证书结构、同一 `registry_sha256`、同一父节切片 |

C4 的请求不含 C3 的提取结果、链接和解释。提示模板哈希和注册表哈希一起检查。两边分别对仲裁后的金标计分。模型不输出六动作，也不输出允许或拒绝。

### 10.1 受控指代实验与端到端实验

实验 A，受控指代关联：C3 和 C4 使用同一份已经冻结的公共候选注册表，只比较链接类型、目标、依据片段是否与链接金标一致。注册表里的身份槽位不是被测链接器发现的。若 `registry_origin = human_controlled`，结果只能称为受控子任务，不得称为完整的端到端人工智能创新。

实验 B，端到端：要说明整条事实解析流程的增益时，候选漏登记、多余登记、身份字段错误、证据提取错误和指代错误都进入组级四态。实验 B 禁止使用人工增删过的注册表。R0 的中心词和列映射是规则，不是 C4 的能力。C4 替换的是提取或链接，不替换候选发现。因此本年即使运行 C4，也不能写成模型自主发现了候选事实。

这一限制是当前条件和题目边界决定的。不另开一个候选发现模型课题来消除它。

消融从 C3 只改一处：A1 同名合并；A2 不比较极性和状态；A3 结论与原文进入同一次提取；A4 只做 L2；A5 把 `unmentioned` 填成结论里的值。A3 和 A5 就是要防止通道串线和把缺失当成一致。

C4 要单独回答的是：在不看见结论、并且候选注册表与 C3 相同的前提下，词表外状态和非显式指代是否更接近金标，同时组级错误接受不超过 C3。显式且候选唯一的 T13-a 上，C3 就应该做对，这不构成模型增量。T13-b 到 T13-e 检查的是拒绝边界，不是模型优势。

状态对照同样使用同一原始锚点，不使用对方的提取结果。「核准」的 C3 结果固定为 `unparsable`。C4 可以输出 `approved`，只与状态金标比较。不得先把「核准」写入 C3 词表再比较。

实证标准在提示词冻结时写死，打开验证集之后不改：测试组上 C4 的组级错误接受不高于 C3；预先指定的正式探针上 C4 与金标更一致；C4 覆盖率不低于 C3；C4 不把金标为 `paused` 的组交付出去。任一不满足，就写明增益未证实。即使满足，12 组的上界仍然约 25%，自动外发保持关闭。接口只允许研究人员手工调用，并且仍走 `precheck`。

没有获准的离线模型时，C4 记为未执行。不下载、不训练、不把项目文本送到外部接口，不用 C3 的数字填写 C4。

GLiNER 和序列标注只提供提及候选，不能充当 R0，也不能充当 C4。`necessity_action.joblib` 只提供动作概率。它们不能充当 C4。

### 10.2 预实验不得冒充正式测试

G04 已经含有「核准」，并且会用来检查词表和提示词是否违反第 4.2 节。因此：

- 18 组只用于手册、κ 和方法调整。
- 词表、提示词、R0 映射和判定规则在正式测试材料解封前冻结。冻结之后，预实验里出现过的表达若被写进 C3 词表，就不再是词表外探针。
- 「核准」不得为了提高 C4 的对照表现而加入 C3 词表。
- 正式测试至少有一组词表外状态、一组非显式指代。这两组在提示词冻结之后新写，只放进测试 12 组，不放进开发集和验证集。
- 不把预实验原句复制到 36 组。近义改写也算同一材料：活动、金额、状态表达和句式骨架同时保留，即视为非独立。
- 本方案不写下正式探针的原句，避免在冻结前提前设计测试句。
- 验证集与测试集分开封存。验证集打开后也不改提示词。测试集只跑一次。
- 人工注册表、链接金标和四态金标分开保存。注册表哈希在后两类标注开始前已经固定。

这两组在 12 组测试里各至少一组。结果只能说明这两条新材料，不能写成稳定的模型能力。样本就停在这里，不再为了把人工智能效果说大而加题。

## 15. 申报表述

隐盾第三阶段研究来源文档修改后，已生成的披露结论是否仍被当前证据支持。系统先按原始证据和文档结构建立公共候选身份，再分别提取证据和结论实际写出的内容。一条证据可以只写出部分维度，同一事实身份下再合并；没写到或不能解析的必要维度不算支持。证据之间只有在主体、属性、范围、口径和时间资格都成立、且没有已接受的修订关系时，才判断冲突；冲突不靠结论去挑选。指代必须给出当前原文中可定位的依据，候选不唯一就拒绝，候选唯一但没有依据也拒绝。「尚未批准」与「已否决」分开。「核准」在规则基线中固定为不能规范化，不写成没有提及。词表外表达只有在正式测试的新材料上超过规则基线，才讨论模型增益。不能确认就暂停。模型不决定外发。本研究不提出新的依赖图或失效传播算法，也不把公共候选登记写成已经实现的模型能力。
