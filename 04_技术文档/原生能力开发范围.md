# 隐盾原生能力开发范围

2026-11-18 调整实现方向。前一轮将五项产品能力按第三方接入实施，与用户要求在隐盾内部开发相应功能存在偏差。从本轮起，以隐盾自身的服务、配置、数据结构和界面承载功能。

## 产品能力与实现目标

| 参考产品 | 在隐盾内部实现的目标 | 本轮后的状态 |
| --- | --- | --- |
| Presidio | 可配置实体规则、类别注册、格式校验、规则版本、冲突处理和替换 | 已有隐盾原生规则识别器，复用 Span、合并及六动作转换。默认在线流程已移除 Presidio 库调用 |

## 当前原生路径

用户入口 → 隐盾权限和材料用途检查 → 本机解析 → 格式识别、词典、GLiNER 与注册规则 → 六动作模型与硬约束 → 本机转换 → 隐盾边界规则和泄露复检 → 模型生成或交付。

注册规则由 `recognition` 配置，边界策略由 `policies` 配置。旧版 `presidio`、`nemo` 配置键作为迁移别名读取，实际执行隐盾自己的代码。若同时提供新旧键，配置校验会拒绝多余字段，避免歧义。GLiNER 继续用于语义识别。

知识检索接口为 `POST /api/knowledge/retrieval`，授权、材料读取、动作转换、词项检索、引用和出口复检均在隐盾内部完成。原 Dify 兼容地址仍可读取同一服务。

此前的 LiteLLM、Lakera 配置仍是可选外部连接，当前本机均未启用。它们对应的原生功能按上表实施，验收以隐盾自身入口为准。

## 验收方式

对原生规则识别和策略检查，阻止导入 presidio_analyzer 与 nemoguardrails，并阻止网络调用，再执行正常管线的识别、规则拒绝、未知类别、配置错误及六边界测试。原生能力使用自己的实现来源标识。发布说明按已运行的功能记录开发进度。

本轮在应用最小环境完成 24 项集成、边界与 API 测试，原生规则测试同时禁止第三方护栏库导入及网络请求。现有格式校验、GLiNER、六动作和硬约束继续通过原入口执行。新旧配置读取均已测试。

默认配置回归通过 491 项及 33 项子检查。此前 GLiNER 对部分代号上下文的误报具有偶发性，本轮回归通过并不代表该识别问题已修复。
