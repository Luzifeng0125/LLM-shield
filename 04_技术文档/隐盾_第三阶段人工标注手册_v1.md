# 隐盾第三阶段人工标注手册 v1

日期：2026-11-24。  
依据：`隐盾_第三阶段核心研究方案最终冻结版_v2.md`。本手册不另立研究问题，也不把尚未编写的 L3、L4、C3 写成已经完成的标注器。  
适用材料：预实验 18 组优先。正式 36 组在提示词、R0 映射和本手册冻结之后再标注。  
人员：2–3 人。只有两人时，分歧保持未决，不得由原标注者把自己的分歧改成一致。

## 1. 标注对象

每一份标注都落在一个文档组上。同一文档系列的全部修订留在同一组，不拆进另一个划分。

| 对象 | 标注什么 | 不标注什么 |
| --- | --- | --- |
| 文档组 | 组号、划分（18 组或开发/验证/测试）、任务模板 | 六动作、外发许可 |
| 原始文档快照 | 生成披露时的修订号和引文 | 用当前修订改写当时的引文 |
| 当前修订 | 父修订号、当前全文指纹是否与快照相同 | 没有父修订记录时，不得把两句相近的话写成修订 |
| 证据锚点 | `block_id` 或表格业务键，以及该锚点的原文 | 模糊匹配出来的“大概同一段” |
| Claim Assertion | 披露句每个维度的 `kind` 和规范值 | 原文里有什么 |
| Evidence Assertion | 该锚点原文每个维度的 `kind` 和规范值 | 这句是否支持结论 |
| 候选事实 | R0 登记的七个身份字段；人工只核对，不按结论增删 | 金额、状态、极性、有效时间 |
| 指代链接 | 是否同一事实，以及原文中的依据片段 | 哪些旧值应当退出 |
| 更新关系 | 是否明确更新，以及更新了哪些维度 | 只因为连到了同一事实就覆盖旧值 |
| 四态结果 | `still_valid`、`affected_still_valid`、`invalid`、`paused` | 允许外发或六动作 |

定位不唯一、没有锚点、或精确检索不是恰好一次时，四态直接标 `paused`。不补一个“最像”的锚点。

## 2. 维度

证据和结论使用同一套维度。每一维只有四种 `kind`：`value`、`unmentioned`、`not_applicable`、`unparsable`。不得增加 `unspecified`，也不得在缺少或不能确定时填一个业务值。

| 维度 | `value` 时记录 | 空着或不能确定时 |
| --- | --- | --- |
| `subject` | 结构主体键对应的 `subject_id`。同名且没有区分信息时不分配 | 两名张三不能区分，标 `unparsable`。禁止用姓名哈希代替 |
| `attribute` | 封闭属性：`participant_count`、`event_time`、`location`、`person_role`、`task_item`、`deadline`、`budget_amount`、`public_fact` | 中心词零次或多次命中，保持空，标 `unmentioned` 或 `unparsable`，不猜测 |
| `context_scope` | 活动或组织范围的 `context_scope_id` | 父节编号不是活动范围。对不上范围映射就留空 |
| `grain` | `grain_all`、`grain_excluding_staff`、`grain_travel` | 多个口径或没有精确口径，留空 |
| `numeric_value` | 原文中的规范数字。引文里没有的数不能写入 | 没写是 `unmentioned` |
| `unit` | 与数字一起出现的单位 | 属性需要单位但没写，是 `unmentioned` |
| `valid_time` | 原文写出的适用时间 | 没写是 `unmentioned`。不能把缺失时间当成另一个月份 |
| `polarity` | `affirm` 或 `neg` | 极性对所有属性都必要。否定词只进极性 |
| `status` | 第 3 节的九个业务值之一 | 见第 3 节。状态不进入事实身份 |
| `evidence_location` | 锚点加引文指纹。结论侧没有这个字段 | 锚点不唯一则整组 `paused` |

`value` 必须能由该锚点原文得到。结论通道只看披露文本，证据通道只看该锚点原文。

今年这些属性的状态是否必要，按冻结方案固定，任务模板不能改：

| 属性 | 状态 |
| --- | --- |
| `task_item`、`budget_amount` | 必要 |
| `participant_count`、`event_time`、`location`、`person_role`、`deadline`、`public_fact` | 不必要，应标 `not_applicable` |

必要维在结论侧或证据侧为 `unmentioned` 或 `unparsable` 时，四态是 `paused`，不是匹配。两边都有确定规范值但不相等，并且证据之间没有未解决冲突，才是 `invalid`。

## 3. 状态与极性

极性字段和状态字段分开保存。否定词不推出业务状态。“尚未达到 12 人”的极性是 `neg`，人数的状态是 `not_applicable`，不是 `not_yet_approved`。

C3 和人工金标共用下面的映射。同一个说法只有一个结果。

| 原文 | 结果 |
| --- | --- |
| 没有提及状态 | `unmentioned` |
| 建议、拟、考虑 | `suggested` |
| 计划、准备 | `planned` |
| 申请、提请 | `requested` |
| 正在审批、等待审批 | `pending` |
| 尚未批准、还未批准 | `not_yet_approved` |
| 批准、已同意、通过 | `approved` |
| 已否决、已驳回 | `rejected` |
| 已完成、已落实 | `completed` |
| 取消 | `cancelled` |
| 未批准、未获批准、没有批准 | `unparsable` |
| 核准，以及其他词表外的状态说法 | `unparsable` |
| 同一句里两个互相矛盾的状态 | `unparsable` |
| 属性不需要状态 | `not_applicable` |

“尚未批准”不是 `rejected`。“已否决”“已驳回”才是 `rejected`。同一句里重复“批准，已经批准”，仍是一个 `approved`。

「核准」在 C3 和本手册的规则金标里只有 `unparsable`。不得写成 `unmentioned`，也不得为了让后续模型更好看而加入词表。C4 可以另行判断它是否等于 `approved`，对错只由状态金标决定，不在本轮实现。

## 4. 身份链接和更新关系

这两份记录必须分开保存。身份链接回答“是不是同一事实”。更新关系回答“新陈述是否明确替换了旧值的哪些维度”。

| 记录 | 允许的取值 | 作用 |
| --- | --- | --- |
| `identity_link` | 冻结方案的 `explicit_coreference`、`implicit_semantic_reference`、`ellipsis`、`abstain` | 只继承主体、属性、范围、口径 |
| `update_relation` | `reference_only`、`updates_dimension`、`unknown` | 只有 `updates_dimension` 能让指名的旧维度退出活动集 |

规则：

1. 只建立身份链接时，旧事实的金额、状态和其他维度都保留。链接不是更新。
2. `updates_dimension` 必须给出当前原文中的依据片段，以及 `basis_start`、`basis_end`。片段必须与该位置的原文完全一致。
3. `updated_dimensions` 只列出新陈述明确写出的维度。
4. 没有列入的维度保留原活动值。
5. 关系是 `unknown` 或 `reference_only` 时，任何旧值都不得退出。`unknown` 不能消除冲突，四态暂停。
6. 同一必要维上两个值都还活动，又没有有效修订或更新时，标 `paused`。不得用披露结论挑选其中一边。

显式词只有“上述、该预算、此项”。没有这些词时，规则链接标 `abstain`，即使父节里只有一个候选。候选多于一个时，即使有“上述”也拒绝链接。

工作例子：

A：“建议将差旅预算调整为 8000 元。”  
B：“上述建议已经批准。”

B 可以对 A 建立 `explicit_coreference`。更新关系是 `updates_dimension`，`updated_dimensions` 只有 `status`。依据片段是“已经批准”。A 的 8000 元继续活动，A 的“建议”退出状态。这是 T13 的正例，四态金标是 `still_valid`。

负面例子：

C：“上述建议曾经获得批准。”

C 可以因为“上述”讨论身份，关系却是 `unknown`，不是 `updates_dimension`。不得把“曾经批准”写成当前状态，也不得让 A 的金额或“建议”退出。不能确定当前状态时，四态标 `paused`。

父子修订是另一条更新路径，必须有记录在案的父修订号。措辞相近本身不是修订。修订同样只替换新文本明确写出的维度。

## 5. 候选注册表怎么核对

R0 已经能根据锚点、原文、父节、表格和冻结中心词生成注册表。标注者核对它，而不是重做一份。

核对时只能看原始证据和文档结构。不能看披露结论、四态金标、链接金标，也不能看 C3 或 C4 的输出。

可以标的错误只有三类：漏登记、多余登记、身份字段错误。不得因为某条候选支持或不支持结论而删掉它。未知身份保持空字符串。

自由文本没有唯一中心词时，属性就应当为空。例如“尚未达到 12 人”没有出现“人数”或“活动人数”，R0 不会猜它是人数。这不是漏做的模型能力，后续提取器也不得用结论把属性补上。

注册表生成之后立刻记录 `registry_sha256`。此后开始链接金标和四态金标。看到金标之后不得回头增删候选。若必须人工登记，文件头写 `registry_origin = human_controlled`，该次只能作为受控材料，不能写成模型发现了候选。

C3 和 C4 将来必须读取同一哈希。哈希不同的对照作废。本轮没有 C3 和 C4。

## 6. 标注顺序、分歧和金标

每组两人独立标注。第三人只仲裁分歧，不重新标注已经一致的字段。κ 用仲裁前的两份标注，不把仲裁后的一致当成 κ。

顺序：

1. 登记文档组、快照、当前修订和锚点。定位失败就标 `paused`，停在这一步。
2. 冻结并核对 R0 注册表。
3. 证据断言只看锚点原文。
4. 结论断言只看披露文本。
5. 链接金标看原文、父节和已经冻结的注册表，不看披露结论，不看模型输出。
6. 更新关系单独填写。身份链接不能自动生成更新关系。
7. 四态金标最后填写。此时可以同时看到结论、证据、链接和更新，但仍不看模型输出。

分歧记录保留两份原标注、分歧字段和仲裁结果。仲裁不能发明词表外的状态。主体判断的 κ 低于 0.70，或冲突与值变化的 κ 低于 0.60，就停止扩展到 36 组。κ 按文档组自助：每次抽一组文档的仲裁前标注，使用 Cohen's κ，即观察一致率减去期望一致率，再除以 1 减期望一致率。本轮没有 κ 计算脚本。

金标分三处保管：

- 注册表哈希在前。
- 链接金标其次，且不含披露结论。
- 四态金标最后。

三处文件不要合成一份给标注者提前看。导出包不带姓名、学号和电话。

## 7. 四态怎么落笔

| 四态 | 何时标注 |
| --- | --- |
| `still_valid` | 定位唯一，引文指纹未变，没有未解决的证据冲突，每个必要维两边都是相等的 `value` |
| `affected_still_valid` | 同上，但当前引文指纹已经变化，重新提取后仍然全部匹配 |
| `invalid` | 必要维都有确定值，至少一维不相等，证据之间没有未解决冲突 |
| `paused` | 定位失败、需要链接但被拒绝、必要维缺失或不能解析、更新关系为 `unknown`、证据冲突不能消除 |

一组里有一条 `invalid` 或 `paused`，整组不交付。本手册不产生外发决定。

T1–T13 的核心金标保持冻结方案，不在标注时改写：T1、T2、T5、T6、T9 为 `invalid`；T3 为 `affected_still_valid`；T7、T4、T8、T10、T13 的多候选和无依据子例为 `paused`；T11、T12 和 T13 的显式且唯一正例为 `still_valid`。子例里的“不同属性”和“不同口径”不记 Source Conflict。T13 的历史状态子例不能标成当前已经批准。

## 8. 本轮不做的标注

不标注六动作。不把 GLiNER 或动作模型的输出当成事实金标。不把「核准」标成 `approved` 来充当规则金标。不把结构上存在的依据片段直接当成语义链接正确。正式探针的原句不写进手册。
