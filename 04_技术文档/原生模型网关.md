# 原生模型网关

隐盾直接向获准的 OpenAI 兼容供应商发送经过本机检查的消息。模型选择、回退、预算预留、限流与费用记录由本项目代码执行。原来的单供应商调用和显式 mock 模式仍可使用。

## 配置与使用

在活动配置文件中增加 `model_gateway`。端点、价格和接收范围由管理员核对，密钥填写在指定的环境变量中。以下使用合成地址，价格仅用于说明单位。

```yaml
model_gateway:
  enabled: true
  currency: CNY
  monthly_budget: 50000000
  requests_per_minute: 30
  targets:
    primary-model:
      base_url: https://your-approved-provider.example/v1
      model: your-model
      key_env: SHIELD_PRIMARY_KEY
      disclosure_scope: campus-approved
      timeout: 30
      input_price: 2000000
      output_price: 3000000
    backup-model:
      base_url: https://your-approved-backup.example/v1
      model: your-backup-model
      key_env: SHIELD_BACKUP_KEY
      disclosure_scope: campus-approved
      timeout: 30
      input_price: 2000000
      output_price: 3000000
  routes:
    primary:
      disclosure_scope: campus-approved
      targets: [primary-model, backup-model]
```

预算以百万分之一货币单位记录。例中 50000000 对应 50 元，input_price 为 2000000 表示每百万输入 token 收费 2 元。币种和价格须按供应商的实际计费自行配置。

在本机环境配置 `LLM_PROVIDER=shield`、`LLM_MODE=real`、`SHIELD_MODEL_ROUTE=primary` 及两项密钥。重启后普通对话和连接检查都会进入原生网关。使用单目标路由也可启用预算和限流。

## 发送与失败处理

1. 校验整条路由的地址、模型、凭证和管理员声明的接收范围。不同范围的目标不能出现在同一回退链。
2. 对完整消息按 UTF-8 字节数加每条 256 的协议余量估计输入 token，并按请求输出上限计算预留金额。该方法是预算估算，供应商实际 tokenizer 与协议开销可能不同。
3. SQLite 事务检查本月累计预留及报告金额和最近 60 秒的请求次数，然后插入尝试记录。并发请求共用本机账本。
4. 发送前再检查材料授权。HTTP 429、5xx 或连接类异常可尝试下一个获准目标。认证、参数、内容解析错误直接结束。
5. 供应商返回有效的输入与输出 token 数时，按配置价格更新费用。缺少回执、异常和进程中断保留预留。每个回退目标重新预留并消耗一次请求额度。

实际回执超过预留时记录报告费用，后续按新余额限制请求，因此预算是本机准入与预留机制。费用账本需要结合供应商账单核对。币种变化要求先迁移账本。月份按 UTC 划分。

## 状态与数据

“识别与集成”页面可用管理员凭证读取当月用量。API 为 `GET /api/models/usage`，同时要求本机请求和管理员认证。数据库位于 `outputs/model_gateway/usage.sqlite3`，记录路由、目标、配置版本、时间、金额、状态与 token 数。状态包括预留、待核对和已报告。数据库不记录正文、密钥或供应商响应正文。

本轮已有原生路由、范围限制、失败回退、并发预算、限流、用量查询及诊断入口测试。测试使用合成上游。机构级虚拟密钥、按组织和用户分账、自动核账及管理配置界面仍待开发。

2026-11-18 定向验证通过 32 项，其中包含实际回环 HTTP 通信、超时后的预算保留及并发预算预留。默认配置回归通过 497 项及 33 项子检查，旧多轮用例的 GLiNER 误报再次出现 1 项失败。本轮未调用付费模型。当前本机仍保留原供应商直连配置，启用原生网关前需核对目标、价格与预算。
