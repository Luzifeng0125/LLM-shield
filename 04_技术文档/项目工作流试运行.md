# 隐盾项目工作流试运行

同步基线为 `origin/main` 的 `26aced1`。项目入口沿用 `启动隐盾.cmd`。

## 启用

在仓库根目录用 PowerShell 7 生成本次启动的管理员凭证并启动服务。若服务已在 8787 端口运行，先关闭原进程。团队也可以在应用本机的 `.env` 中设置长期凭证。

```powershell
$env:SHIELD_WORKFLOW_ADMIN_TOKEN = [Convert]::ToBase64String([System.Security.Cryptography.RandomNumberGenerator]::GetBytes(32))
Start-Process -FilePath $env:ComSpec -ArgumentList '/d /c 启动隐盾.cmd' -WorkingDirectory (Get-Location).Path -WindowStyle Hidden
```

等本机服务完成预热后，在同一 PowerShell 会话建立项目。可查阅 `http://127.0.0.1:8787/openapi.json` 获取完整接口定义。

```powershell
$headers = @{ Authorization = "Bearer $env:SHIELD_WORKFLOW_ADMIN_TOKEN" }
$root = 'http://127.0.0.1:8787/api/workflows'
$project = Invoke-RestMethod -Method Post -Uri "$root/projects" -Headers $headers
$base = "$root/projects/$($project.project_id)"
```

管理员可操作本实例的全部项目，供应商凭证只可用于签到提交。团队上线时还需接入组织身份及部署边界。数据库位于 `delivery/app/outputs/workflows/projects.sqlite3`，原名映射与验收集依靠主机账户和磁盘权限保护。项目撤回后清理活动数据库记录，备份由部署者管理。

## 任务等效替身

对项目的 `/assignments` 提交资源和可分配对象。资格中的资源索引以请求中的资源顺序为准，从零开始。

```json
{
  "resources": [{"label":"合成场地甲","capacity":1},{"label":"合成场地乙","capacity":1}],
  "assignments": [{"subject":"合成人员甲","eligible":[0,1]},{"subject":"合成人员乙","eligible":[0]}]
}
```

响应含随机排列后的数字别名、资格和容量，以及确定性本机解。将 `local_solution` 的 JSON 传给 `/assignments/{assignment_id}/verify`，通过校验后会在本机还原原标签。用 `DELETE /assignments/{assignment_id}` 可撤回映射。存在正在调用外部生成的项目时，撤回请求返回冲突，可在本轮结束后重试。

也可向 `/assignments/{assignment_id}/propose` 提交 `{"confirm_structure_disclosure":true}`。生成服务只收到容量和资格数组，经统一网关复检后发送，返回的数字方案通过完整性、资格和容量验证后才交给调用者。如果部署启用了 OPA，管理员需要按组织授权把 `student_leader / assignment_planning / external_model / model_input` 加入许可。资格与容量组合本身可能产生关联推断，是否允许外发须按具体数据范围决定。暂以人员—资源分配为任务目录。

## 零名单签到

1. 管理员向项目的 `/suppliers` 创建供应商，记录 `supplier_id`，通过合适渠道交付当次返回的 `supplier_token`。
2. 用 `/suppliers/{supplier_id}/passes` 签发凭证，如 `{"subject_key":"internal-001","ttl_seconds":3600}`。使用主办方自己的内部标识，保持同一参与对象在本项目里使用同一标识。参与者凭证中没有标识原值。
3. 供应商以自己的 Bearer 凭证调用 `POST /api/workflows/check-ins`，提交 `pass_token` 和 UUID 格式的 `event_id`。成功仅返回 `{"checked_in":true}`。断网时可在客户端保留同一事件编号并联网重传。同一事件和凭证重复提交返回原确认，新的重复核销被拒绝。断网期间客户端不能确认签到，补传时仍检查有效期及撤销状态。
4. 管理员通过 `GET /check-ins/summary` 查看汇总数。用 `DELETE /suppliers/{supplier_id}` 停用供应商并作废其凭证，再创建新供应商和新凭证。旧签到已计入汇总。

当前交付为签到与重传接口。现场客户端离线队列、扫码 UI、对接真实供应商、通知与应急联系属于实地试点部署项。

## 私密任务验收

1. 买方在项目的 `/benchmarks` 提交 8–32 条隐藏用例及各自预期计数，可设置 `max_candidates`。例如用例 `{"rows":[{"team":"a"},{"team":"b"}],"expected":1}` 可用于核对指定值计数。正式用例应覆盖不同规模、无匹配和缺失字段。
2. 管理员代收供应商的 JSON 描述，提交至 `/benchmarks/{benchmark_id}/candidates`。可用候选为 `{"name":"supplier-a","version":"1","spec":{"operation":"count_equal","field":"team","value":"a"},"quoted_cents_per_task":200}`，或使用 `{"operation":"count_all"}`。报价单位为分，耗时为本地执行时间。
3. 候选按版本及完整描述的 SHA-256 锁定，重复提交同一版本会复用结果。候选额度用尽后，新版本不执行。通过 `/report` 导出本机汇总，由买方决定是否向供应商披露。

当前执行器只解释受限的计数描述，供应商可执行包、跨组织交付和双向保密需要独立部署验收。

2026-11-17，本机 GPU 环境通过 468 项回归与 38 项独立冒烟检查。真实 DeepSeek 对一组 3 人、2 个资源的合成任务生成可行方案，隐盾完成校验并在本机还原 3 项分配。并发签到测试仅有一次核销成功，且允许同事件重传。

在应用目录安装 `requirements-presidio.txt`，运行 `python -m scripts.compare_presidio` 可复现 [Presidio Anonymizer](https://presidio.dataprivacystack.org/api/anonymizer_python/) 的本地算子对照。此次两个合成短文本均得到相同替换结果。该对照固定识别偏移，计的是替换时间，识别质量及真实语料还需独立评测。
