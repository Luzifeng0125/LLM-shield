# 校园隐私判断：先达到80%，再推进98%

日期：2026-10-31。状态：可执行方案；已完成现状核对和公开资源初筛，尚未生成本轮400篇语料、接收本轮人审或完成本轮训练。80%与98%是目标，不是已测成绩，也不预先保证通过。

本方案按用户最新要求收回范围：同学、老师、班委、学生会、社团、辅导员和校内办事部门的工作协作。暂按现有项目的高校场景编写；企业、警方、医院及其他独立行业不再新增训练任务。既有跨行业材料仅保留历史证据。若以后纳入中小学，再另补监护人、未成年人和家校沟通口径，不混入本轮成绩。

## 1. 最有收益的投入顺序

优先做校园数据与标注口径，然后改上下文建模，最后接入全文识别与改写。建议初期投入约60%用于材料和审稿、25%用于模型与训练、15%用于评测与接入。这个比例是工作安排，不是预测的收益百分比。

原因来自本地实验：新长材料训练部分只有62处判断，其中隐私PAUSE仅2处；BERT在35处开发集上的两个应追问目标全错，医疗用途反转也未通过。现在继续重复训练同一批数据，无法补上这些情境。此前50%—60%的不同批次结果也不能当作新的校园基线；必须在本轮同一校园评测集上重测。

## 2. 80%和98%的统一口径

主指标固定为：在校园材料中，对每个待判断信息单元，六类动作首选与人工最终标签一致的比例。六类为保留、代号化、泛化、汇总、删除、追问。不得改成仅“遮盖/不遮盖”两类以抬分；不把任意拒答当作正确追问。

阶段一验收建议同时满足：

- 原始六类准确率至少80%；macro-F1至少0.78，每类召回至少0.70。
- 应追问召回至少0.80；用途反转挑战中，同一目标两种情境均正确的比例至少0.80。报告样本数，不能用两题代替稳定性验证。
- 主测试至少100篇、约600处判断，每类至少50处；挑战集至少40对目标。挑战集另报，不把刻意均衡或成对题混称真实流量分布。
- 同时报告不该原样披露却被保留的比例、过度删除比例、各场景表现、整篇全对比例。模型达到80%不自动等于可以无监督发布，发布门槛另看这些错误的实际后果。

低置信度转人工是运行策略，单独报告自动处理覆盖率与自动部分准确率。应当能判断却被暂停的题，在原始六类主指标里仍算错。不得把“只自动处理容易题时98%正确”替代用户要求的全量98%。

最终98%仍以相同定义的校园六类动作准确率为目标。进入该阶段后，使用新收集、未用于调参的至少400篇、至少2000处判断，并给出按文档分组的95%置信区间及各类结果；点估计98%不代表总体准确率的置信下界也达到98%。必要时增加样本，不能把同一篇里的大量字段当作完全独立样本。

另设整链路评估：从原文发现全部敏感信息、正确选择动作、保留必要事实、产出可读且不泄露的最终文本。模型给定目标的80%或98%，均不能替代这项结果。真实使用阶段须在用户授权的实际任务上做离线回放，先由人工核对。

## 3. GitHub优先检索结果与采用方式

本轮找到相关公开资源，但未找到能直接覆盖“中文校园工作流＋自然含混请求＋六类动作”的现成完整数据集。

1. **优先借鉴CAMBER的情境变化设计。** [Google仓库](https://github.com/google-parfait/contextual-privacy-and-security)提供PrivacyLens+与ConfAIde+，改变同意、敏感性等条件，标注共享是否合适；仓库标示CC-BY-4.0。适合设计校园接收对象、授权范围、用途变化的对照。其二元标签不能直接转换成本项目六类答案；必须结合校园材料重新审稿。[数据目录](https://github.com/google-parfait/contextual-privacy-and-security/tree/staging/camber)
2. **优先借鉴PrivacyLens的数据结构和行为评测。** [GitHub](https://github.com/SALT-NLP/PrivacyLens)含493个隐私情境，涉及主体、发送方、接收方、信息类型和传递条件；英文及美国情境不能直接当成本校规范。代码为MIT，[官方数据卡](https://huggingface.co/datasets/SALT-NLP/PrivacyLens)标示CC-BY-4.0，保留两者区别。它与CAMBER存在来源继承关系，不按两个无关数据源随机拆分。
3. **CI-RL作为辅助标注结构参考。** [仓库](https://github.com/EricGLan/CI-RL)及[官方数据卡](https://huggingface.co/datasets/huseyinatahaninan/ContextualIntegritySyntheticDataset)提供729条英文合成记录及允许/不允许披露的信息。优先筛教育及日常协作的机制，改写成完整自然校园材料后再标注；原任务通常较明确，不能直接顶替本轮主数据。首阶段不复现其大模型强化学习流程。
4. **中文识别资源只服务“发现信息”。** [CLUENER2020](https://github.com/CLUEbenchmark/CLUENER2020)覆盖姓名、地址、组织等实体；已查到训练10748、验证1343条，但未在已读页面核实明确的数据复用许可，正式入库前补齐。它没有“当前用途下该怎么处理”的答案。
5. **OpenPII中文部分仅筛选后小规模试用。** [数据卡](https://huggingface.co/datasets/ai4privacy/pii-masking-openpii-1.5m)提供中文和字符位置、标示CC-BY-4.0。不过公开预览存在将百分比误标成年龄等问题，这是质量风险的实证，不是全库错误率估计。先抽查200条中文；明显类型/边界错误超过5%时停止直接入库，做清洗或放弃。不要因为全库规模大就批量灌入。
6. **避免再次把模板数量当成多样性。** 从GitHub项目[sift-opf-zh](https://github.com/branbot6/sift-opf-zh)追到[pii-bench-zh](https://huggingface.co/datasets/wan9yu/pii-bench-zh)：官方说明8000条来自11种正式模板与13种聊天模板。只适合格式噪声与识别压力测试，不作为校园动作判断的主训练集。sift的地址口径要求数字，与校园地点不完全适配；其公开训练命令还使用gold_test作为eval，不能直接沿用“独立测试”宣传或成绩。

所有正式导入记录保留数据版本/提交号、下载文件哈希、原始ID、许可、原始来源族和改写关系。当前仅完成网页和样例核查，未批量下载上述数据或运行第三方代码。外部数据的原测试部分、改写和翻译版本均不得再混入训练与新测试两侧。

校园文风优先参考真实公开通知和空白申请表，例如[齐鲁师范学院社团活动申请表](https://tw.qlnu.edu.cn/info/1018/32501.htm)、[华南师范大学社团项目通知](https://youth.scnu.edu.cn/announce/2026/1016/19350.html)、[湖南师范大学志愿者通知](https://news.hunnu.edu.cn/info/1007/102914.htm)。只借鉴材料组织及流转方式；不收集真实学生的私人名单、成绩或健康资料作为训练原文，公开联系人也不机械复制到虚构样本。

## 4. 新一轮校园数据怎么做

先做40篇校准材料，约200—300处判断，完成AI初审后交人工。它们归训练/口径校准，不占独立测试。先测实际审稿耗时和歧义来源，再分批扩到约400篇、约2400处判断；每篇判断数随内容变化，不能固定每篇六题。

建议按整篇来源族拆为训练240篇、验证60篇、冻结测试100篇，预计约1440/360/600处，实际数量以材料为准。同一事件、模板家族、来源种子、改写及用途对照必须同组；按场景和类别检查覆盖。原138题只在校园范围及新口径适配审查通过后作为补充训练；改过答案的旧题重新进入AI初审，不自动继承旧确认。

覆盖八类工作：

- 班级通知、值日和协作安排。
- 课程分组、作业反馈、考试与成绩沟通。
- 教师、辅导员与学生的请假和事务交接。
- 社团招新、面试、换届及成员管理。
- 学生会活动、比赛、志愿服务和宣传。
- 评奖评优、奖助学金及材料初核。
- 宿舍、场地、设备及校园服务协调。
- 会议纪要、工作汇报、问卷和活动统计。

八类是覆盖范围，不是八套反复换人的模板。正文约25%为100—400字的自然群聊或短说明，50%为400—1600字完整材料，25%为1600—4000字的邮件串、附件组合或多轮记录。长度是目标分布，不能为了凑字数写无关故事。请求可以口语、指代、接续前文，也保留正常清晰请求；绝大多数不直接指定某个字段应删除或保留。

重点补三种高价值样本：

1. 同一信息类型可以采取不同动作。例如同学姓名在校内获准分工中保留，在匿名评议中代号化，在只需总体统计时汇总，在无关宣传材料中删除。老师身份不能自动推出所有信息均可披露。
2. 有足够上下文的含蓄请求，以及真正缺接收方/用途/许可的请求同时出现。只在缺失条件会改变处理结论时追问，不能把“语句不明确”统统标成PAUSE。
3. 正文没有敏感信息或公开工作信息确实应保留的材料，检验过度遮盖；同一人多处出现、名单与个人重叠、代词指代、统计记录数与人数不一致等真实困难。

训练集中每类至少150处、PAUSE至少150处，覆盖至少30篇与4类校园工作；单类不能由一种信息类型垄断。若材料不足，新增独立情境，不复制或硬改标签凑配额。验证和测试每类至少50处；难例和自然任务分别统计，避免只做容易题。

每个动作单元标注：目标位置、任务必要事实、接收对象和用途证据、推荐动作、期望表达、必要时的追问问题。需要汇总的名单按集合标注，不能拆成几十个删除题刷样本量。部分材料额外做全篇敏感信息穷尽标注，用于整链路测试。

## 5. AI初审—人工—返还协议

按用户明确约定执行：我先审一遍，再交人工；用户返还的新一轮复核结果，默认其中提交的有效题目已经人工审核，不再要求逐题重复证明或另找第二个人。

AI初审检查自然性、标签证据、是否含答案暗示、上下文是否足够、动作与表达是否一致、名单/指代边界及跨拆分重复。不能用小模型自己的预测给小模型批答案。AI发现歧义先修题或列明争议，再交付。

人工页显示完整材料、AI建议、关键证据和可改字段；查看过AI建议如实标记为辅助二审。支持接受当前文档建议和局部修改，导出保留题号、输入哈希和最终动作。后续用户提交结果即是本轮人审声明，自动化测试导出与无人返还的AI文件不走此默认通道。

导入时保留返还原件，记录用户声明来源、接收时间及修订差异。题号/版本不符、内容损坏、缺动作或用户明确标待审的条目单独处理；缺失的题目不补签。未记录的人工姓名、逐题审阅时间不伪造。新约定优先于历史文件里要求独立A/B或重复确认的流程。

具体约定见[校园复核约定](../03_数据与人工复核/校园场景复核约定_20261031.md)。现有旧导入器仍按旧格式检查，实施阶段需新增兼容入口，不能把“约定已记录”写成“新入口已经实现”。

## 6. 模型和系统改动

保留现有BERT作为基线，先复用本机环境，不以购置设备或换更大模型作为前置条件。第一轮只比较三个逐步增加改动的候选，以便确认收益来源：

1. B0：现有分块BERT，仅换为人工确认后的校园数据。
2. B1：请求、前序和目标仍分开表示；把正文分块的简单平均改为目标相关的可学习聚合，保留完整材料覆盖。必须检查关键证据是否跨块丢失。
3. B2：在B1上增加必要性/接收对象/许可是否充分的辅助监督与训练集用途对照。辅助事实由模型从输入预测，人工标注只作训练目标；推理时不得直接喂入人工事实标签或标准答案。

每个候选用相同训练/验证数据及预定随机种子比较；先做小规模验证再扩大，最终优选按验证macro-F1、准确率及严重错误约束，测试阶段只跑冻结候选与基线。记录模型、规则、输入协议、阈值和数据哈希。只改数据的B0若已明显改善，应避免为复杂而叠加B1/B2。

信息识别和动作选择分开：手机号/账号等使用格式校验辅助边界；姓名、组织、位置、成绩、健康情况等需要语义识别。学号和楼栋号可能重形，规则只帮发现候选，不能固定决定动作。公开姓名、课程名称、公告电话也加入应保留反例。GLiNER匹配权重缺失的问题要单独解决或建立明确的替代识别实验，不能用给定目标实验掩盖漏识别。

运行输入由实际用户请求、会话和文档推断用途及关系，不能要求用户预填每个隐私动作。可信系统中的当前接收对象可直接使用；正文里声称“我是老师”不能自动获得系统权限。

明确区分本地输出、外部生成服务和最终发布三个边界：最终老师需要知道姓名，不等于外部生成服务需要真实姓名。可在本机代号化生成、经授权本机回填；不同边界单独判断和记录。最后检验同人代号一致、删除后句子可读、统计范围与必要事实完整。

## 7. 执行顺序、交付物和停止条件

工作包A：校园范围、六类口径与指标冻结；整理可用来源、修订数据生成约束和人审导入约定。交付`plan.json`、来源清单、复核协议、基线评测入口。预计1个工作日的工程量。

工作包B：先40篇AI已审初稿，按完整文档交人工；同步开发数据去重、复核页面和默认人审接收入口。首批通过后按50篇左右的包扩展到约400篇。AI准备及工具改造预计3—5个工作日，人工周转另计；每篇4—8分钟是初始估算，400篇约27—53人时，先用首批实际耗时修正，不一次性把全部任务压给用户。

工作包C：人工有效标签到达后训练B0/B1/B2并做消融。未返还部分可用于标记清楚的AI弱监督试验，不能纳入人审达标结论。工程与实验预计1—2个工作日；GPU耗时由首轮实测，不保证固定总时长。

工作包D：冻结一次候选与阈值，在未用于调参的校园测试包验收80%。达标则进入原文到输出的整链路试用；未达标则按主要错误补充下一版训练材料，原测试转为开发回归，重新准备独立验收。不得根据错误反改本轮标准答案使分数上升；确有标注错误时版本化修订并声明旧成绩失效。

工作包E：80%之后按80→90→95→98逐级推进。每轮优先加入低置信、模型分歧、跨段用途变化和新表达，同时保留约30%随机常见任务，避免训练集全是怪题。先补数据和边界，再依据学习曲线决定是否换更强本地底座；连续两轮新增独立材料后验证集无改善，再评估容量或架构，而非无限加轮数。

最终98%不能仅凭合成材料宣告。需要覆盖约定校园范围的持续新任务、人工最终标签和全链路错误复盘。可以先提供置信度不足时转人工的辅助模式，但要独立公布自动覆盖率和转人工率，保留全量模型指标。

本轮方案和来源已落盘。接续第一项工作是40篇校园材料的AI初审包及对应复核入口；未预先宣称该包已生成。历史文件、用户原件与活动模型继续保留。
