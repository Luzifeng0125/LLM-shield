# 先完成第一批试标

完整安排见同目录的《隐盾数据复核与模型训练执行方案》。本包为现有“隐盾数据集_v1”的独立执行包，不修改原数据。

1. 指定 A、B 两名复核员与 C 一名裁决员。C 先看方案第 3、4、6 节并确认口径。
2. 只把 `批次/01_训练试标/复核员A` 交给 A，把对应 B 文件夹交给 B。先不要把“裁决员专用”发给 A/B，也不要分发封存测试答案。
3. 双击各自的“打开复核.html”。下拉选择试标编号 N00187、N03301、N03696、Z0016、A8052、A9041、C12140、C12213，共 8 个单位，其中两段三轮对话。
4. 独立选中实体文字添加类别；动作或对话还要填处理结果和理由。无实体的样本保留空列表。只确认自己已检查的完整单位。
5. 点击“下载全部复核结果”，把文件保存在本机。页面不联网、不自动保存；每 15 至 20 分钟下载一次，关页前必须下载。可导入自己先前下载的同批次结果继续。
6. C 组织试标讲解，统一口径；这 8 个讲解过的单位不计入盲审一致率。之后 A/B 各自完成训练批剩下的 120 个单位。
7. 全批完成后提交两份结果，由 C 或我进行比较与裁决，再导出训练 gold。

## 批量通过（2026-10-15 更新）

1. 如果旧页面还开着，先下载当前进度，再刷新页面、导入刚下载的同批次结果。已有结果文件不用修改。
2. 展开导航栏下方的“批量通过”，可按类型、完成状态筛选，或搜索编号和原文。切换筛选会清空勾选。
3. 勾选已经逐条检查的记录，或点击“全选当前筛选中可通过的记录”。缺少动作、理由、外发内容或实体位置错误的记录会显示原因，不能通过。
4. 如果所选记录含空实体列表，先确认相关材料或对话轮次确实没有应标实体，再勾选相应确认框。尚未标注不能当作无实体。
5. 点击“批量通过所选”。实体、动作、理由和备注保持原样，只更新完成状态，并记录复核员 A/B、操作时间和批次编号。点击“下载全部复核结果”保存。
6. 误点时可“撤销本次批量通过”；只撤销最近一批仍保持该次完成状态的记录，后续修改过的记录保持现状。刷新或导入后不能撤销上一页面的批次，可逐条取消完成。

批量通过表示本人已完成独立复核，正式 gold 仍需 A/B 两人复核和 C 裁决。页面不会自动填充机器答案，也不自动保存。操作时间来自本机时钟；旧进度没有操作记录仍可导入，新增操作才会记入。

## 给 C 的运行说明

工具只用 Python 标准库，项目已有便携 Python，可直接执行。下面的 PowerShell 命令假定当前位置为本执行包目录；输入文件名可按实际下载名称修改。

如果把本包单独解压到另一台电脑，A/B 页面仍可直接打开。C 的脚本需 Python 3.10 或更新版本；该电脑没有项目便携 Python 时，将下方 `$reviewPython` 改为本机 Python 路径即可。

```powershell
$reviewPython = '..\..\runtime\python\python.exe'
& $reviewPython scripts/review_workflow.py validate '工作结果/A.jsonl' --batch '01_训练试标' --reviewer A
& $reviewPython scripts/review_workflow.py validate '工作结果/B.jsonl' --batch '01_训练试标' --reviewer B
& $reviewPython scripts/review_workflow.py compare --a '工作结果/A.jsonl' --b '工作结果/B.jsonl' --batch '01_训练试标' --out '工作结果/第一轮比较'
```

validate 可以检查未完成的进度文件；compare 要求双方全批完成。命令不会覆盖已有结果目录，重新比较应使用新的目录名。

比较后得到“裁决表.jsonl”和“比较统计.json”。C 查看全部分歧、8 个培训单位和 must_inspect 为 true 的一致抽检项。裁决表中 annotation_A、annotation_B 保留原样；填 final_annotation、adjudicator、adjudicated_date、adjudication_reason，并在批准后设置 approved 为 true。机器建议只能辅助查错，不能直接批量复制成最终答案。C 不熟悉 JSON 时可将逐项裁决意见交给我录入，再核对签署。

所有单位批准后运行：

```powershell
& $reviewPython scripts/review_workflow.py export --a '工作结果/A.jsonl' --b '工作结果/B.jsonl' --batch '01_训练试标' --decisions '工作结果/第一轮比较/裁决表.jsonl' --out 'gold/train_gold.jsonl'
```

验证、测试批分别更换 batch 与输出文件名，禁止导出到 train_gold。导出记录自带 split，供后续转换训练格式时再次核对。未批准时导出会拒绝；不会把机器建议自动变成人工 gold。

## 文件范围

- `批次`：三批各有 A/B 离线页面与空白 JSONL。
- `裁决员专用`：机器候选答案与源记录指纹，不提前发给 A/B。
- `培训试标编号.json`：8 个培训单位，已经包括在第一批 128 个中。
- `执行统计.json`：128、92、92 的实际数量与来源数据包指纹。
- `scripts/review_workflow.py`：验证、比较与 gold 导出；不会训练或替换模型。
- `scripts/build_batches.py`：重现抽样的构建代码；已有批次时拒绝覆盖，日常不用运行。
- `qa`：工具自测及文档版面检查资料；测试结果不属于人工标注。

不需要 API、不需要先租 GPU。第一步是人先完成试标，验证口径和实际耗时。
