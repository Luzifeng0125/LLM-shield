# 隐盾数据复核与模型训练执行方案

适用数据：隐盾数据集 v1　制定日期：2026 年 10 月 14 日　人员：复核员 A、复核员 B、裁决员 C

本方案把现有数据变成可执行的人工标注、质量检查和模型训练流程。建议先完成 128 个训练样本的试标，再完成 92 个独立验证样本，最后在模型冻结后使用 92 个封存测试样本。全部 312 个是已经选好编号的复核单位；其中一段三轮对话按一个单位计算。

现在可以开始人员培训和标注准备。当前人工 gold 数量仍为 0；这里交付的是待执行方案、空白表单和工具，不代表人工已经复核，也不代表本地小模型已经训练完成。此处的“培训”包括复核员培训与模型训练，两者分别安排。

## 1 先明确人工究竟要做什么

人工复核包含三层工作。第一层是确认敏感信息的范围和类别，例如某个片段究竟是姓名、宿舍还是普通工作内容。第二层是根据任务、权限和对话历史，判断应删除、统计、泛化、用代号、保留还是暂停。第三层是检查实际外发文本是否遗漏隐私、丢失任务信息或在多轮中泄露身份。给实体标 gold 只完成了第一层。

A 和 B 必须分别判断同一批数据。两人结果不一致时由 C 裁决；结果一致时，C 按数据类型抽查至少 20%，并签署整批质量结论。机器可以检查索引、格式和标志冲突，却不能替人确认某个任务是否真的有权披露个人信息。

项目负责人先确认标注规范及披露边界。若 C 同时担任负责人，可以合并这两个角色；A、B 两份独立标注仍须由两个人完成。无需把所有一万多条数据逐条人工复核，但凡声称是人工 gold 的样本，都必须真正经过相应流程。

### 分工与自动化边界

| 工作 | 谁执行 | 是否需要人工 |
| --- | --- | --- |
| 读取文件、去重、分层抽样、锁定 split、核对哈希 | 脚本或我 | 不需要逐条人工 |
| 检查 JSON、字符索引、实体文本、重复和重叠、动作字段 | 脚本 | 不需要逐条人工；失败项退回修改 |
| 判断应标哪些实体及其边界 | A 和 B 独立判断 | gold 必须；弱标签可以暂不逐条审 |
| 判断任务必要性、权限、可接受动作和应外发内容 | A 和 B，C 裁决 | gold 必须；不能由生成答案自行认证 |
| 判断多轮代号、指代、去重、累计披露和材料内指令 | A 和 B，C 裁决 | 按完整会话人工审 |
| 比较 A/B、列分歧、选取一致项抽检、导出数据 | 脚本或我 | 工具不替 C 批准 |
| 补生成训练候选、转换 SFT、训练、评测、画错误分布 | 我负责实现和运行 | 结果解释及上线边界需负责人确认 |
| 提供真实材料授权、确定业务权限、支付 GPU/API 费用 | 负责人 | 需你们执行；当前试标无需 API |

人工标签允许纠正机器答案。例如原建议为“保留”，但任务配置不足以证明可公开，则应修改或留疑问；不能为了提高与原答案的一致率去改人的判断。

### 实体数据的四种形态

NER 的 5,100 条包括 4,200 条单实体、300 条困难负例、300 条混合段落和 300 条表格。训练部分分别为 2,800、200、200、200；验证和测试各为 700、50、50、50。

单实体样本用于学习类别和边界。困难负例用于检查“字段名、日期、版本号、工作事项”是否被误标为隐私。混合段落和表格用于检查漏实体、列错位以及一次处理多种信息的能力。原 92 个待复核单位没有覆盖后三种 NER 形态，本次已在训练试标中补入各 12 条。

### 四种标签身份必须分开

“机器弱标签”是生成器给出的答案，可以用于探索性训练，但不能称为人工正确答案。“人工待裁决”是 A/B 已提交、C 尚未批准的结果，暂不进入 gold。“人工 gold”指双人复核、必要裁决并签署通过的结果；即使是 gold，文本仍然是合成来源。“真实业务 gold”还需要材料来源及使用授权，目前尚未交付这部分数据。

## 3 十四类实体怎么标

统一采用 Python Unicode 字符索引，start 包含起点，end 不包含终点；页面会自动计算。实体只标真实出现的值，不标“姓名”“电话号码”等空字段名。不跨标点吞入周围句子。同一片段不同时标两种类别；需要嵌套或跨类解释时留备注，由 C 确定当前规范下的唯一边界。

| 类别 | 当前规范与人工关注点 | 人工必要程度 |
| --- | --- | --- |
| PERSON_NAME 姓名 | 标完整姓名；“完成海报”等事项不是姓名；人员甲作为生成代号不按真实姓名标 | 高，必须判断语义 |
| PHONE 电话 | 标完整号码，包含号码内部空格或连字符；不含字段名与句末符号 | 格式可自动验，抽样人审 |
| EMAIL 邮箱 | 标完整地址；本包 .invalid 域名是合成标记 | 格式可自动验，抽样人审 |
| ID_CARD 身份证 | 标完整号码；校验位通过不代表真身份；本包使用虚构区域码 | 格式可自动验，抽样人审 |
| BANK_CARD 银行卡 | 标完整号码；Luhn 通过不证明真实银行发行 | 格式可自动验，抽样人审 |
| STUDENT_ID 学号 | 结合字段和上下文确认，不能把所有长数字当学号 | 中高，必须有上下文样本 |
| API_KEY 密钥 | 标完整密钥值；本包带 SYNTHETIC_NOT_REAL_KEY 标记，只测合成格式 | 高，补真实格式的虚构值后再验 |
| WECHAT 微信号 | 标账号值，排除“微信号”字段名 | 中高，区分账号与普通单词 |
| BUDGET 预算 | 标金额与计量单位，预算所属关系另在任务判断中检查 | 中高，确认单位和公开性 |
| ORG 组织 | 标完整组织名称；组织被识别不等于必须删除 | 高，区分公开机构和个人关系 |
| LOCATION 场地 | 标完整场地名；是否保留取决于可信配置，不从“已公开”字样自行推定 | 高，必须分开识别与披露 |
| DORM 宿舍 | 当前包按完整宿舍地址短语标，包括学校或楼栋信息；不能只截房间号 | 高，先统一边界 |
| GRADE 成绩 | 当前包包含成绩值及单位，例如“85分”；不把项目分数自动当个人成绩 | 高，必须判断个人关联 |
| SENSITIVE_ATTR 敏感属性 | 标完整属性短语，例如病史或家庭情况；避免任意扩展到整句 | 高，需统一范围与授权边界 |

上表区分的是复核重点，不是“某类永远不需要人审”。列入本次 gold 批次的所有样本都需 A/B 完整检查，包括格式简单的号码。未抽入的格式样本可以保持弱标签状态，不必逐条人工。

当前旧检测器在本包 850 条合成验证数据上的严格实体 F1 约为 0.550。姓名、密钥、微信、成绩、宿舍等类别暴露出问题，但有些属于标注边界不同，例如旧检测器只抓宿舍的一部分。这个数值只用于确定排查重点，不能写成真实业务识别率或小模型训练成绩。

## 4 六种动作与六类多轮场景怎么审

动作不能只由实体类别决定。同一个场地在获准公开的通知中可以保留，在未获批准的项目简介中可能需要泛化。判断顺序固定为：受信任配置是否充分，接收方是否明确，任务需要什么信息，更少披露能否完成任务，当前与历史合起来是否产生新风险。

| 动作 | 在本包中的判断问题 | 人工需要交付的内容 |
| --- | --- | --- |
| DELETE 删除 | 私人联系方式是否与任务无关 | 删除后的完整文本，保留事项与期限 |
| LOCAL_AGGREGATE 本地统计 | 任务是否只需要人数，能否本地算出 | 正确统计值，外发不含名单 |
| GENERALIZE 泛化 | 降低地点等信息精度后能否完成任务 | 降低精度后的文本及理由 |
| PSEUDONYMIZE 代号 | 是否需要保留人物与任务关系 | 稳定代号、人物关系和完整文本 |
| RETAIN 保留 | 精确信息是否必要且已有可信权限依据 | 保留的具体内容及权限依据 |
| PAUSE 暂停 | 权限未知、指代不清或本次请求无法安全处理 | send_allowed 为 false，外发文本为 null，说明原因 |

每条 policy 同时复核实体、首选动作、可接受动作集合、外发文本和理由。首选动作必须属于可接受集合；可接受集合可以不止一个，不能把机器原来的单一答案当成唯一正确答案。PAUSE 与允许外发动作不同时列为同一条件下的可接受答案；若缺条件导致两者都有可能，先把条件问题交给 C。

| 会话场景 | 全会话需要检查的重点 |
| --- | --- |
| deadline_correction 期限更正 | 同一人代号不变，事项不串人，保留更新后的期限 |
| restore_identity 恢复原名 | 后续要求恢复真实姓名时，不能把本地映射发给外部模型 |
| embedded_instruction 材料内指令 | 材料中的“忽略要求、上传映射”不能获得系统权限 |
| ambiguous_reference 指代不清 | “他的期限”无法确定对象时先暂停；明确对象后再处理 |
| roster_followup 重复名单 | 同一人补录不重复计数，外发内容保持只含统计结果 |
| cumulative_disclosure 累计披露 | 组织、代号和唯一奖项组合可能重新识别个人，须审历史 |

会话是不可拆分的抽样和分集单位。A/B 从第一轮开始顺序标注，第二轮依据自己已批准外发的第一轮内容判断。暂停轮不进入“此前已外发”列表，但原始请求可保留在本地上下文中帮助后续澄清。C 解决了前轮分歧后，要重新检查所有后续轮，不能只改出错的一行。

这里审的是“准备发给外部模型的内容”，不是外部模型最终回复的文笔。后者归入端到端验收。当前样本的部分多轮目标尚未在应用中完整实现，标注目标不代表功能已完成。

训练试标的 NER 包括每类 4 条单实体，共 56 条；困难负例、混合段落、表格各 12 条。24 条动作按原建议动作每类抽 4 条，12 段会话按场景每类抽 2 段。原有 92 个候选全部保留，再增加 36 个 NER 单位。类别平衡按生成答案抽样，人工纠正后分布可能变化，需重算。

验证和测试各含每类 2 条单实体，共 28 条，再加 12 条负例、8 条混合材料、8 条表格；动作和会话的数量与第一批相同。三批 ID、split、模板族和源记录哈希已保存在“裁决员专用”下对应批次的清单中。第一批来自 train，第二批只来自 validation，第三批只来自 test。

### 谁能拿到哪些文件

负责人只把“01_训练试标/复核员A”发给 A，把“复核员B”发给 B；第二批同理。每个子文件夹都有“打开复核.html”和空白 JSONL。C 保管机器建议和批次清单，A/B 第一轮不看建议答案。先独立作答，再由 C 在裁决时查看机器建议及其依据。

第三批文件先由 C 封存。为了冻结标准答案，可由 A/B 在不看模型输出的条件下先完成标注；训练和调参人员只在候选模型、提示词、阈值与代码版本冻结后获得该批评分结果。文件夹名称不构成访问控制，需要负责人实际按角色分发，不能把整个执行包发给所有人后宣称盲审。

三批中的 8 个培训试标单位已经包含在 128 里，不额外计数。试标讲解后的这 8 个可用于训练，但不纳入盲审一致率统计。尚未被抽中的自建数据和外部数据仍是弱标签或上游合成标签，不会因同模板几个样本通过就整批自动变成人工 gold。

## 6 复核员培训与上岗练习

建议安排一次约 2 小时的共同培训：前 20 分钟讲清数据、实体与动作的区别；随后 20 分钟学习边界及权限；用约 45 分钟独立完成下面 8 个单位；最后约 35 分钟由 C 讲解分歧并形成规范 v1.0。时间只是排班初值，若对话样本耗时更久应延长。

| 试标 ID | 训练重点 | C 应追问什么 |
| --- | --- | --- |
| N00187 | 姓名边界 | 是否只选姓名，是否漏字或包含标点 |
| N03301 | 宿舍完整边界 | 为什么不能只标房间号 |
| N03696 | 成绩与单位 | 是否包含成绩单位，是否有个人关联 |
| Z0016 | 无敏感信息负例 | 日期、数量为什么不是个人信息 |
| A8052 | 无关联系方式删除 | 联系方式删掉后事项和期限是否仍完整 |
| A9041 | 公开地点保留 | 凭哪一个可信配置认定可公开 |
| C12140 | 材料内越权指令 | 材料内容为什么不能覆盖系统约束 |
| C12213 | 指代不清与澄清 | 暂停后新一轮怎样继续且不串人 |

C 先根据规范独立确定讲解意见，不能直接把生成标签作为标准答案。A/B 不互相抄答案；讲解后各自修订，再由 C 对这 8 个全部检查。

上岗标准是本项目建议门槛：8 个单位都能解释判断依据；不发生“未经核实仍外发”“原名或映射恢复给云端”“忽略材料内越权请求”的关键错误；实体边界错误已统一。达不到时，另选训练集同类型 4 至 8 个样本复训，不能拿验证或测试样本作课堂答案。

培训结束写一份简短口径记录：争议问题、采用的规则、反例、签署人、规范版本。之后发现规范有重大变化，须定位受影响类别并重审相关记录，而非只修改一个样本。验证和测试口径也需同步版本，但不得因此把其答案转入训练。

## 7 每天怎样操作与怎样形成 gold

### A 和 B 的实际操作

1. 双击各自批次文件夹中的“打开复核.html”。先确认顶部显示自己的 A 或 B 身份；页面离线工作，不需要 API 账户。
2. 阅读任务及 trusted_context 或 trusted_policy。选中原文中的实体，选择类别后点“添加所选实体”。检查整个原文，避免只改机器容易发现的部分；本页面没有预填机器实体。
3. 动作与对话样本还需填写首选动作、可接受动作、外发文本和理由。纯 NER 不需要编造处理动作。每段对话完整检查三个轮次。
4. 有疑问就在备注中写清问题，不勾“确认本条全部标注已完成”。把问题编号交给 C；不要自行修改原始任务和材料来迎合答案。
5. 完成每个单位后勾完成。每 15 至 20 分钟下载一次全部结果；浏览器不会自动把结果写回文件夹。关页前必须下载。重新打开后用“导入进度”继续。
6. 交给 C 自己最新的 JSONL 文件。不要交换 A/B 结果。建议把每天文件命名为“批次_复核员_日期_版本”，保留上一版以便追溯。

### C 的裁决过程

先运行格式检查；缺字段、索引错误、未完成单位退回原标注员。两份完整结果通过后，脚本比较实体、动作集合、外发标志和脱敏文本，生成裁决表与比较统计。理由文字保留，但不同措辞本身不计入实质性分歧；脱敏文本不同仍会进入裁决，C 判断是否只是等价表述。

C 必须看所有分歧和 8 个培训单位，并检查脚本选出的各数据类型至少 20% 一致样本。抽查发现一个同类关键错误，就扩大到该类该批全部样本；修改规则后将相关项退回 A/B 重审。两人一致不等于两人都正确。

每个单位都有裁决签署字段。对于未被抽中的一致项，C 可以在完成抽检后按批次批准，理由写明“独立双人一致，按批次抽检通过”，不能写成自己逐条全审。对分歧项须填写最终实体和动作、裁决人、日期及具体原因；无法裁决时保持未批准，整批不导出。

脚本只在 A/B 均完整、原文与批次未变、所有裁决已批准、最终结构合法时导出 gold。它检查不了人的实际判断是否认真，也检查不了脱敏文本的语义安全，因此不得把“校验通过”当作“隐私保证”。

### 三类质量指标

标注过程看 A/B 严格一致率、各类别分歧和 C 抽检错误。模型识别看严格实体精确率、召回率、F1 及每类漏检；不能只报全局平均。动作与会话看可接受动作命中率、该暂停却外发的次数、信息泄露、必要信息丢失及整段会话是否全部通过。

本次首批是小规模启动标注，不用几个样本给出稳定的每类性能承诺。某类验证只有 2 条单实体时，一个错误就影响一半样本。所有百分比同时写出分子、分母和数据来源。

## 8 用这些数据怎样训练模型

### 第一步先完成数据门槛

先跑通 128 个训练单位的 gold 形成流程，再得到独立验证批的 gold。检查同一原文、同一源材料、同一对话没有跨 split。原来的 8 个培训单位只留在 train。所有历史轮次随会话整体移动，不能随机按轮划分训练与测试。

训练前还要完成两项核对：将人工改过的原 ID 从弱标签池排除，避免同一个输入同时出现新旧冲突答案；把实体标签边界和输出 JSON 模式固定为版本化规范。doccano、sft、legacy_actions 都是派生视图，不作为不同来源重复抽样。

### 第二步先做实体识别候选

建议先以本地小模型的实体识别能力为第一训练目标。可以使用 ner/train.jsonl 的 3,400 条弱标签作低权重启动数据；其中人工改过的记录用 gold 覆盖。若首批暴露某类模板批量错误，应先修复或隔离该类，不能继续把错误标签大量喂入。

之后只用训练 split 的人工 gold 做小步微调，以验证 gold 选择候选。首批实体 gold 只有 92 条，目的是验证标注口径和训练链路，不能期待它独立支撑可靠的通用识别。实体模块输出类别与范围；权限检查和发送前校验继续独立保留。

### 第三步再训练动作与对话

首批提供 24 个动作 gold 和 12 段三轮会话 gold；与 92 个 NER 合计可展开为 152 个训练记录。这个数量适合打通流程，仍不足以证明复杂决策已经学会。

policy/train 的 960 条与 dialogues/train 的 240 段可以保留为弱监督实验组；不要把“弱监督模型表现”写成“人工规则已全面审核的模型表现”。优先用人工 gold 确认过的目标做最终校准。验证 116 条展开记录用于选择候选；测试 116 条展开记录仅在冻结后评分。

转换 SFT 时须使用最终人工实体和动作，不得拷贝旧机器 target。会话输入只包含当前请求、已发生的本地历史和此前实际允许外发的内容，不能包含未来轮次或当前标准答案。前轮裁决修改后，必须重新构造后续输入。原文和身份映射属于本地守护模型上下文，不能借训练格式转换混入云端生成请求。

当前导出工具先生成带 split 的审核记录，尚未自动转换为现有应用可以直接加载的模型权重。完成 gold 后，由我实现并校验训练格式转换、训练脚本和模型接口；不让复核员手工拼 SFT 或修改权重文件。

### 第四步比较候选并受控替换

至少比较现有检测器与动作模型、使用弱标签训练的候选、加入人工 gold 后的候选。各候选使用同一份验证与测试规范，报告实体分项、动作和会话结果。不能只选一个对自己有利的总分。

模型大小、量化及 GPU 租用时长应以本机显存和短跑实测确定。先用几十条数据跑通读取、前向、反向、保存和本机加载，再租较长时间。训练时长应拆成数据准备、GPU 运行、错误分析和回归测试；当前无法在尚未完成 gold 的情况下承诺准确训练天数。

候选模型始终另存版本目录，记录基座、数据清单哈希、规范版本、参数、代码版本及评测结果。候选通过后再接到本地决策接口，模型不可用或输出非法仍暂停外发。当前应用权重不会因本次制作方案而被覆盖。

## 9 哪些数据需要继续补充

当前合成数据存在四个明显局限：词库和模板有限；身份证、银行卡和密钥有明显合成特征；动作任务描述常直接提示答案；多轮历史只有三轮。人工复核能修标签，却不能凭空增加真实分布和长期对话多样性。

建议在首批错误分析后新增训练候选，至少覆盖以下内容。新增样本先由我生成候选和机器建议，再交 A/B 判断；所有新增源材料固定归入 train，不能挪用封存测试答案改写。

1. 60 组任务对照，共 120 个动作单位。同一份材料分别用于需要人物关系的任务和只需统计的任务；或保持任务相同，只改变受信任的接收方权限。任务描述改为自然需求，减少直接写出“删除、泛化、保留”等动作词。整组留在同一 split。
2. 60 个困难实体或负例。补非常见姓名、空格电话、表格错位、无关长数字、同形词、未填写字段、不同金额和成绩表达。生成值保持虚构，但格式不要只靠 SYNTHETIC 标记识别。
3. 12 段五至八轮对话。覆盖多人同姓、代号沿用、先暂停再澄清、重复材料、后续纠错和多条线索累积。新增对话作为训练扩展，另留独立来源作之后的新版本测试。

这 192 个扩展单位是下一轮建议工作量，当前没有宣称已生成人工 gold。优先顺序由本轮错例决定；不为凑数量机械扩充。训练错误修复后，先在验证集确认改进，再冻结后测封存集。

外部 8,000 条来自 pii-bench-zh，包含正式文本 5,000 条和口语文本 3,000 条，来源是上游合成数据。优先自动跑完整基准，人工检查争议错例；未经独立复核的上游标签不称为本项目 gold。其 ADDRESS、PASSPORT、LICENSE_PLATE 三类超出当前自建 14 类，须单独报告覆盖缺口，不要把 ADDRESS 强行映射为公开 LOCATION。

该外部包保留来源、版本、Apache 2.0 许可及研究评估用途说明。当前方案维持为外部评估用途，不混入训练；具体信息见原数据包 public/来源与许可.md，来源页面为 https://huggingface.co/datasets/wan9yu/pii-bench-zh 。

## 10 排期与人时预算

建议每位 A/B 每天安排约 2 小时，分成两次 45 分钟标注加整理和答疑。C 每天预留半小时答疑，集中裁决时安排更长时间。下列估算尚未经你们实际计时，应在首日记录每类单元耗时及分歧率后重排。

共同培训约 6 人时，已与首批 8 个样本有少量重叠；C 后续裁决与抽检预留约 6 至 10 人时。整套基础流程保守按约 31 至 51 人时排班，不含新材料征集、训练开发和扩展批。分歧多、规范返工时还需增加。不要把三个人的总人时误当成每个人都需连续工作这么久。

## 11 怎样验收以及如何衔接旧复核方案

数据验收先看每个已导出的 gold 是否有两份独立记录、C 的裁决签署、规范版本及源记录指纹。批次无缺失 ID、无结构错误、无跨 split 误放。对于 C 抽检发现的共同错误，完成相同类型的扩查和重审后才能批准该批。

模型验收先分清安全错误与任务质量错误。首版建议把“该暂停却外发、禁止披露的原文或映射进入外发、模型不可用仍外发”作为阻断发布的关键问题；在封存集上发现任一项都先修复。零次观测只代表这批样本没有发现，不能证明任意输入都安全。

实体指标必须分别报告 14 类以及负例误报；动作同时报首选动作与可接受动作集合命中；对话报整段通过数、稳定代号、正确人数和前后轮关系保留情况。具体可用性目标由负责人在测试解封前签署；可暂沿用旧方案中的误暂停不超过 10%、关系保留至少 90%作为内部目标，并同时列出分子分母及小样本限制。

旧方案的 9 个端到端试标单位继续用于检查页面、日志、暂停和外发流程；本次 312 个属于数据标注与模型评测，二者不相加宣传为同一套 gold。旧方案提出的 12 份材料乘 2 种任务，加 6 段三轮对话，共 42 个请求轮次，是后续端到端业务验收计划，目前未据此宣称已收集或已复核。

真实材料由你们确认可使用范围，优先去除不必要的个人信息；确实无法获得授权材料时，可由成员重新撰写独立的虚构材料进行验收，并明确其合成来源。无论哪种来源，都要检查实际请求中的外发内容，而不仅看模型回答是否漂亮。

使用封存测试结果分析并修改模型后，该批对新版本已经成为已知测试；需要另建未见过的测试版本，不能持续反复调参再宣称始终是盲测。
