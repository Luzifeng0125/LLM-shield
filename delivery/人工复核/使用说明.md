# 两人独立试标

1. 从根目录“打开人工复核.cmd”进入。A、B 各自填写相同的 9 个合成单元。
2. 每条先标必须保留的事实与禁止信息，再展开系统结果；写依据后保存各自的 JSON。
3. 本批模式是 mock，回答完成度选择“不适用”。所有人工选项保持空白，等待实际填写。
4. 将两份 JSON 一起拖到“比较两份复核.cmd”，生成本目录“裁决待填写.json”；也可交给开发人员操作。
5. C 核对证据指纹，逐条填写 conflicts 中 final 和 reason，并填写 arbitrator。两人都选“不确定”仍须裁决。
6. 工具仅报告一致率与待裁决数。它不生成实体金标，也不自动批准试用。正式标注按报告中的完整方案进行。

关闭页面前保存 JSON。恢复记录只导入自己上次的文件；不要互看后修改为一致。
evidence.json 留存原文、实际交给适配器的完整 messages、模型动作、回复和暂停理由。全部材料为虚构试标，不代表已经取得真实材料授权。
网络调用、密钥和上传文件不会由本页面读取。正式复核记录留本机，不应随公开交付包分发。

重跑试标：在 app 目录执行 `..\runtime\python\python.exe -X utf8 scripts/run_review_trial.py`，每次生成独立证据目录。
如指定 `--real`，会尝试发送固定合成样例，最多 9 次请求并可能消费额度；先由负责人确认。
