# field_v1 —— 独立手写识别评测集

## 这是什么

87 条**手写**的中文校园场景文本，覆盖班群通知、社团通知、会议纪要、邮件往来、
报销单、项目申报、档案登记、口语聊天等 68 个场景，共 **149 个敏感实体**、
**17 条纯负例**（不含任何敏感实体），覆盖全部 14 个敏感类别。

它的用途只有一个：**当一把和训练数据不同源的尺子**，测量识别层在真实文本上到底
有多准。它不是训练数据，**任何时候都不要把它并入训练集**。

## 为什么需要它

`data/gold_v3`（312 条人工双人标注 + 裁决）是这个项目原本唯一的评测依据。但它有一个
致命问题：**它和训练语料出自同一个生成器，实体取值几乎不重复、格式高度模板化**。
模型只要背下模板就能拿满分，测不出"读不读得懂上下文"。

`scripts/field_v1_check.py` 的实测证据：

| 表面特征 | gold_v3（旧人工集） | field_v1（本集） |
|---|---|---|
| 身份证前 6 位地区码 | **只有 `999999`** | 110108 / 310115 / 440305 / 420106 / 120103 / 610113（真实地区码，且全部通过 GB 11643 校验位） |
| 银行卡前 6 位 BIN | **只有 `000000`** | 621700 / 621226 / 622202 / 622848 / 622609（真实 BIN，全部通过 Luhn） |
| 手机号前 3 位号段 | 130 / **140** / 150 / **160** / 170 / 180 / **190**（140·160·190 非真实号段） | 138 / 139 / 135 / 136 / 137 / 158 / 177 / 189 + 座机 021 / 0571 / 0574 |
| 邮箱域名 | **只有 `example.invalid`** | 163.com / qq.com / ncu.edu.cn / stu.edu.cn / hzsyxx.edu.cn / yuntu-dc.com |
| 密钥前缀 | **只有 `SYNTHETIC_NOT_REAL_KEY_`** | `sk-`+32位十六进制 / `ghp_` / `AKIA` / `api_key=` / `password=` |
| 微信号前缀 | **只有 `wx_synth_`** | xuwenbo_0326 / xiaoyu_2026 / zhangwei_88 / QQ 数字号 |
| PERSON_NAME | 112 次命中 **112 个不同取值**（生成器固定词表） | 含复姓（诸葛超、上官云）、少数民族名（阿依古丽·买买提）、以及刻意重复出现的张伟/李思远（用于一致性测试） |
| LOCATION | 32 次命中**只有 20 个取值**，全是「虚构校区共享教室23号场地」式模板 | 新体育馆 / 图书馆三楼 / 教三201 / 第三教学楼207教室 / 材料楼B404 / 行政楼第一会议室 / 文科楼305 |
| DORM | 「示例公寓N栋N室」 | 梅园7栋312室 / 桃李苑2栋408室 / 紫荆公寓A座812室 / 紫荆公寓B座1010室 |
| GRADE | 24 个取值 / 36 次，全是 65~96「分」 | 92分 / 88分 / 79分 / 95.5分 / 绩点 3.76 |
| 数值诱饵 | 几乎没有 | 日期、教室号、人数、票数、名次、组数、报销阈值、5 位公开热线 |
| 姓名假阳性诱饵 | 无 | 张罗（动词）、王者荣耀（含姓氏字「王」） |

**独立性（字符 n-gram 重合率，低=不同源）：**

| 对照语料 | 6-gram | 8-gram | 10-gram | 12-gram |
|---|---|---|---|---|
| 人工 gold 训练集（196 条） | 6.0% | **2.4%** | 0.0% | 0.0% |
| 旧模板训练集（196 条） | 6.0% | **2.4%** | 0.0% | 0.0% |
| 自举增强集（220 条） | 22.6% | 10.7% | 2.4% | 1.2% |
| **对照：旧人工 test 集（80 条）vs 训练语料** | — | **78.8%** | — | — |

也就是说：旧 test 集有 **78.8%** 的记录能在训练语料里找到 8 字以上的连续重合片段
——它根本不是留出集；而 field_v1 只有 **2.4%**，且残留重合全部是「如对本次……请咨询」
这类通用公文表述与我自己此前生成数据引入的号码前缀。

## 标注口径

为了能和旧 gold 公平对比，标注口径尽量沿用旧 gold 的习惯；有歧义处一律按下列规则处理，
并在文末列出全部争议项。

1. **PHONE / BUDGET / GRADE / DORM / LOCATION 含单位与后缀**：
   `13812345678`、`1280元`、`92分`、`梅园7栋312室`、`第三教学楼207教室`。
2. **PERSON_NAME 只标姓名本体**，不含「老师 / 教授 / 同学 / 班主任」等称谓。
   理由：代号替换时应当保留称谓（「王秀兰老师」→「人员甲老师」），
   把称谓并进实体会丢掉这一层信息。
3. **ORG 只标注具名单位**（学院 / 社团 / 公司 / 中心 / 学生会部门全名），
   **不标注**泛指职能（教务处、学校）与班级编号（计算机2301班）。
4. **LOCATION 只标注具名场所**（楼宇 / 教室 / 会议室 / 场地 / 地标），
   **不标注**泛指功能场所（辅导员办公室、校园卡服务中心、自助机）与模糊指代（老地方、线上）。
5. **数值诱饵一律不标**：日期、人数、票数、名次、分组数、报销阈值、5 位公开热线。
6. **身份证 / 银行卡使用真实地区码与真实 BIN，并通过校验位**——本集刻意使用**真实可用**的
   格式特征，因为「格式真实」正是旧集最大的捷径来源。

## 已知边界争议项

以下是本集中**两种标注都说得通**的地方，已在评测里单独识别，读数字时请注意：

| 记录 | 争议点 | 本集取法 |
|---|---|---|
| F035 | `500元` 是制度阈值，不是某材料里的金额 | 不标（但正则/模型都会报出） |
| G053 | `校园服务热线12345` 是公开号码 | 不标（模型报为 PHONE） |
| G056 | `计算机2301班` 算不算机构 | 不标（模型报为 ORG） |
| F021 / F025 | `教务处` 算不算机构 | 不标（模型报为 ORG 或 LOCATION） |
| G058 | `卡号2023110245` 该算 STUDENT_ID 还是 BANK_CARD | 标 STUDENT_ID（该号在别处确为学生学号），模型报 BANK_CARD |
| F050 | `信仰基督教` 的粒度（整句 vs 拆成「宗教/信仰/基督教」） | 整段一个实体 |
| F004/F008/F018/F038 | `王秀兰老师` 该不该含称谓 | 只标姓名 |

## 文件清单

| 文件 | 说明 |
|---|---|
| `field_v1.jsonl` | 数据集本体。每行 `{id, text, scenario, annotation.entities, source_kind, notes}` |
| `README.md` | 本文件：数据集卡片、表面特征对照、标注口径、争议项 |
| `integrity_report.md` | 完整性校验 + 独立性证明（由 `scripts/field_v1_check.py` 生成） |
| `eval_report.md` | 识别层评测报告，含逐类别 / 分级 / 误报结构诊断（由 `scripts/eval_field_v1.py` 生成） |
| `eval_report.json` | 同上，机器可读 |

配套的脚本与回归测试：

| 文件 | 说明 |
|---|---|
| `scripts/field_v1_build.py` | 从结构化片段构建 `field_v1.jsonl`（偏移由程序计算，不手写） |
| `scripts/field_v1_check.py` | 完整性校验 + 与三类训练语料的 n-gram 独立性证明 |
| `scripts/eval_field_v1.py` | 3 配置 × 2 数据集评测，复用 `scripts/eval_gold.py` 的匹配口径 |
| `tests/test_field_v1.py` | 回归门禁：把评测数字写成断言，防止「只报旧留出集分数」 |

## 复现

```bash
# 1. 重新生成数据集（改 scripts/field_v1_build.py 里的 RECORDS 后运行）
python scripts/field_v1_build.py

# 2. 校验完整性 + 打印独立性证明
python scripts/field_v1_check.py

# 3. 评测（3 种配置 × 2 个数据集；需要 GLiNER 权重）
python scripts/eval_field_v1.py

# 4. 回归门禁（默认秒级，不加载模型）
python tests/test_field_v1.py
#    追加 GLiNER 项（约 1 分钟）
#    PowerShell: $env:SHIELD_TEST_GLINER=1; python tests/test_field_v1.py
```

评测脚本刻意**复用** `scripts/eval_gold.py` 的匹配函数，保证与项目既有口径一致
（`cover` 粒度无关 / `overlap` 区间相交 / `strict` 边界严格）。

## 声明

`source_kind` 为 `hand_authored_independent`：文本由本项目作者**手写**，
不来自任何生成器模板，也**不包含任何真实个人数据**——所有姓名、号码、证件号、
银行卡号、密钥均为虚构；身份证与银行卡号虽然通过校验位，但地区码/生日/BIN 之后的
序列是任意编排的。
