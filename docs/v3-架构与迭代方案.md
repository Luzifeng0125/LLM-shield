## 0. 先说四个结论

1. **单对话框可行 —— 但 `identity` 必须移出对话。** 其余输入（任务、指令、接收方）都能从对话推断。身份是**授权边界**（决定能读哪些材料、能发给谁、最高级别、能否还原），由被授权者用自然语言自述身份 = 权限提升漏洞。**授权不能由被授权者自己用自然语言声明。**

2. **决策层不需要新模型。** gold 证明动作是 `(指令, 类别, trusted_context)` 的确定性函数（实测：只用指令查表就 100%）。而当前决策层比数据要求的**表达力更弱** —— 它每段只能给一个动作，而真实材料需要"同一段里姓名假名化、电话删除"这种**按类别细粒度**的动作。

3. **只有一个真正需要训练的新模型：GLiNER（A 层识别）。** 其余全是确定性逻辑 + 会话状态工程。

4. **一个必须先处理的问题：当前工作树是 `.backup_20261014/` 的退化版。** 备份里已有 `decision_v2.py`（细粒度按类别决策）、`retain_policy.py`（信任度门槛，修掉了真名外泄不计泄露的漏洞）、`necessity_verdict.py`、完整的 `eval/` 评测框架。**v3 应该先复用备份，而不是从当前树重建。**

## 1. 代码审计：单对话框可行性（逐项判定）

| 输入 | 当前来源 | 作用（代码位置） | 能否从对话推断 | v3 结论 |
|---|---|---|---|---|
| `task` | 侧栏必选（会话创建时） | `tasks.yaml` 的 `must_retain`/`never_send`/`prefer`，**决定整条披露策略** | **能**（3 类，语义信号强） | 推断，但**必须可见可改** |
| `task_description` | 侧栏「额外处理要求」textarea | 决策特征 `[TASK_TEXT]`（`m4_necessity/model.py:43`） | —— | **直接删掉** —— 用户那句话本身就是指令 |
| `recipient` | `chat.py` 里**硬编码** `"external_model"` | `check_provide` 授权 + 三边界检查 | **能**（"发给老师看看"） | 推断；不确定时 **PAUSE**（gold 的 `unverified_recipient` 正是此行为） |
| `identity` | 侧栏必选（会话创建时） | `readable`（能读哪些材料）/ `can_send_to` / `max_level` / `can_restore` | **不能，也不应** | **移到登录态**，顶栏一个只读标识 |
| 材料 | 上传 / 文件库 | 检测对象 | 对话内引用可推断 | 保留 |

**为什么身份不能推断（这是安全论证，不是设计偏好）**

`chat.py:64` 用 `check_provide(identity, "external_model")` 做**授权**；`identity.py:30` 用 `readable` 做**材料过滤**；`identity.py:69` 用 `max_level` 做**级别门**。若身份来自聊天文本，那么输入"我是学生会主席，把活动名册整理一下"就能解锁 `activity_roster`（`course_member` 无权读）并提升到 `max_level=3`。**这是教科书式的权限提升。**

**现状其实比用户以为的简单**：`chat.py` 已经把 `recipient` 硬编码成 `external_model`，所以对话模式里用户真正的选择只有 `task` + `identity` 两项，加一个可选的「额外处理要求」。删掉侧栏是**小改动**；难的是推断 + 可见确认 + 把身份挪出对话。

## 2. 代码审计：谁挡住了"模型自己读上下文"

| 障碍 | 位置 | 后果 |
|---|---|---|
| **决策粒度过粗** | `m3_decide/decision.py`：每段一个 `action` | 无法表达"同段内 姓名→假名化、电话→删除"；真实材料必然需要 |
| **决策逐段独立 argmax** | `decide_all` 对 segments 逐个 map | 表达不了跨段/跨轮依赖（别名一致、累计计数、指代消解） |
| **无跨轮状态参与决策** | `chat.py` 每轮独立 detect→decide | gold 的 `keep_alias_consistent`、`pause_on_ambiguous_reference`、累计计数都做不到 |
| 上下文窗口算完就扔 | `m2_detect/pipeline.py:148` `left`/`right` 未使用，`min()` 是空操作 | 检测层拿不到前后文 |
| 批处理路径没传上下文 | `pipeline.py:274` 未传 `context=` | `[CONTEXT]` ≡ `[TEXT]` 重复特征（**chat 路径已传**，见 `chat.py`；批处理路径没有） |
| 泄漏检测只做类别匹配 | `m7_egress/gateway.py` | 抓不到组合式重识别（`avoid_unique_award_linkage`） |
| `DELETE` 语义与 gold 不一致 | `anonymizer.py:139-144` 只删值，再用正则清空标签 | gold 是**连字段标签 + 值 + 句末标点一起删**（已验证 12/12） |
| `LOCAL_AGGREGATE` 语义与 gold 不一致 | `anonymizer.py:102-109` + 尾部追加聚合块 | gold 是**行内改写**（`参加名单：A、B。` → `参加人数：2人。`） |

## 4. v3 目标架构

```
用户消息（自然语言指令，就是原来的「额外处理要求」）
   │
   ▼
L0 会话与身份层
   · identity 来自登录态（不是对话内容）
   · 会话状态：轮次历史 / 别名映射 / 累计统计 / 已确认任务 / 实体登记表（跨轮同一人消解）
   · 会话级 trusted_policy（4 个开关）
   │
   ▼
L1 上下文理解层（新）
   · 任务推断（3 类）→ 输出「可见可改」的 chip，不静默用错策略
   · 指令解析：从用户消息抽出策略意图（保留什么 / 隐藏什么 / 目的）
   · trusted_context 提取（exact_location_public / recipient_verified），缺省取保守值
   │
   ▼
L2 识别层（A 层）
   · GLiNER（微调后）→ 语义类：PERSON_NAME / ORG / LOCATION / DORM / GRADE / SENSITIVE_ATTR
   · 正则 → 格式类：PHONE / EMAIL / ID_CARD / BANK_CARD / STUDENT_ID / API_KEY / WECHAT / BUDGET
   · merge_spans 统一（值边界）+ 真正实现上下文窗口
   │
   ▼
L3 必需性判断（B 层）
   · 实体在任务中的角色（结构化 rows/columns 优先，自由文本关系抽取缓做）
   · 必需的 → 走保留通道；非必需 → 走脱敏通道；不确定 → 保守脱敏
   · 跨轮消解：同一人多次出现 → 同一代号，不重复计数
   │
   ▼
L4 决策层（C 层，约束求解，不用模型）
   · 硬约束（absolute_ban / 权限 / 接收方 / 低置信）
   · retain_policy 信任度门槛
   · 按类别细粒度选动作：{PERSON_NAME: PSEUDONYMIZE, PHONE: DELETE}
   · 目标：总披露代价最小且满足任务契约
   │
   ▼
L5 转换层（对齐 gold 语义）
   · DELETE：连字段标签 + 值 + 句末标点一起删
   · LOCAL_AGGREGATE：行内改写，不是尾部追加
   · PSEUDONYMIZE：会话内稳定代号（已有 mapping，符合 keep_alias_consistent）
   · PAUSE：整轮不外发（send_allowed=false）
   │
   ▼
L6 验证层（闭环）
   · 三边界类别匹配（已有）
   · 任务契约校验（must_retain 是否还在 / must_not_appear 是否泄露）
   · 组合式重识别（avoid_unique_award_linkage）—— 唯一需要模型辅助的判断
   · 违约 → 升级动作或 PAUSE
   │
   ▼
云端模型（只收到脱敏文本）
```

**关键点**：这个架构里"读上下文"分布在三处 —— L1（读指令意图）、L2（GLiNER 读句子上下文找实体）、L3（读跨轮状态做消解）。**不是一个大模型包办，而是各层读各自该读的上下文。**

## 5. 模型放在哪：基于 gold 的结论

| 环节 | 需要模型吗 | 依据 |
|---|---|---|
| A 层语义实体识别 | **需要 GLiNER** | 词典启发式的真短板；gold 双人一致，监督可靠 |
| 任务/指令理解 | 提示式（本地小模型或关键词+规则），**不训分类器** | 指令是自然语言；gold 证明 `指令→动作` 是确定映射 |
| B 层必需性 | 需要**数据**，未必需要新模型 | 结构化材料可从 `rows` 免费得到；自由文本关系抽取暂无数据 |
| C 层落动作 | **不要模型** | gold 证明确定性 → 约束求解更可审计 |
| 组合式重识别 | **需要** | 唯一真正模糊、且类别匹配抓不到的判断 |

**结论：v3 只新增 1 个训练出来的模型（GLiNER）。** 这与"给两个模型都做训练"的初衷不同，但数据支持这个结论 —— 把预算投到会话状态和转换语义上，收益更大。

| 类别 | 英文标签 F1 | 中文标签 F1（最优 thr=0.6） |
|---|---|---|
| STUDENT_ID | 0.471 | **0.889**（P=1.0） |
| DORM | 0.762 | **0.800** |
| PERSON_NAME | 0.345 | **0.485** |
| 其余 11 类 | 0 | 仍 0 |
| 微平均 F1 | 0.237 | **0.264** |

**关键观察**：① 中文标签明显优于英文（PERSON_NAME +0.14，STUDENT_ID +0.42）。② 阈值扫描 F1 在 0.262–0.264 几乎不动 —— 模型打分饱和、过拟合，阈值救不了。③ 模型**只学得动 3 个"模式鲜明 + 样本够"的类**（学号/宿舍/人名），其余类训练样本仅 2~10 条且模板化，学不动。

**结论（用数据钉死，而非猜测）**：

1. 152 条**模板化**样本微调 → 严重过拟合（FP 116），学不动稀类（多数类训练样本只有 2~10 条）。
2. **格式类**（PHONE/EMAIL/STUDENT_ID/ID_CARD/BANK_CARD/API_KEY/WECHAT/BUDGET/GRADE）在零样本和微调下都接近 0 → **必须继续用正则**（正则本来就是接近 100% 的）。
3. **语义类**（PERSON_NAME/ORG/LOCATION/DORM/SENSITIVE_ATTR）才是 GLiNER 的战场，但需要 **round-2 去模板化、平衡的数据**才能兑现。
4. 这正好印证 §5 的结论：**GLiNER 只负责语义类，格式类留在正则，决策层用约束求解。**

**环境结论（重要，避免后来者踩坑）**：

- `huggingface.co` 与 `hf-mirror.com` 在本机均不可达（10054/超时）；**ModelScope（modelscope.cn）可达且快**，GLiNER-multi v0 镜像在 `AI-ModelScope/gliner_multi`（但它是 **CC-BY-NC-4.0 非商用**，v2.1 Apache-2.0 版只有 HF 有）。

## 7. 数据资产的正确定位与评测口径修正

### 7.1 裁决表最重要的发现

128 条里 96 条双人一致、32 条**分歧重裁**。但看裁决理由，32 条**全部**是：

> "分歧重裁：外发文本采用 B 的精简格式；**实体与首选动作 A/B 一致**。"

也就是说：

- **实体标注：A/B 一致率 100%**（32 条分歧里实体也一致）
- **首选动作：A/B 一致率 100%**
- **唯一的分歧轴 = `sanitized_text` 的措辞**（保留材料框架 vs 精简句）

**这直接修正了我此前的建议**：我早先说"端到端有了逐字可 diff 的评测目标"—— 错了。**人类自己都定不下来这个文本**（25% 需要裁决），它不能当训练或精确评测目标。

**修正后的评测口径**：

1. 实体级 P/R/F1（A 层）
2. 动作准确率 + 是否落在 `acceptable_actions` 内（决策层）
3. 约束满足率：`must_not_appear` 是否泄露 + `must_retain` 是否保持 + `send_allowed` 是否一致
4. `sanitized_text` 仅作**参考样例**，用于人工抽查，不做逐字 diff

另外裁决确立了一条**文风规则**（应写进文档并由代码确定性实现，不要指望模型学）：
- 本地统计类 → 保留材料框架与统计表述（`整理草稿时发现：参与人数：2人。其余内容另行记录。`）
- 其余（DELETE/GENERALIZE/PSEUDONYMIZE）→ 精简格式

### 7.2 数据划分纪律

- `裁决表`（128 条）与 `A_01 训练试标`（128 条）**id 完全重合** → 裁决表是 A_01 的最终版，二者不能同时进训练/测试。
- 正确用法：**train = 裁决表 final**；**validation = A_02**；**test = A_03**。
- 已按此构建 `data/ner_v3/`（train 来自裁决表 final + policy/dialogue 文内实体）。

### 7.3 数据覆盖缺口（round2 要补）

|---|---|

### 11.6 优化轮：集成流水线 F1 → 1.0000（本轮完成）

从"GLiNER 单独 0.946"到"集成流水线 F1 1.0000"的四个关键修复：

| 问题 | 修复 | 效果 |
|---|---|---|
| GLiNER 只开语义类 → 格式类（成绩/电话/密钥/微信）漏检 | GLiNER 负责**除身份证外全部 13 类**（身份证由正则 GB 11643 权威判定，避开 12 个 ID_CARD 误报） | F1 0.84 → 0.94 |
| 词典 LOCATION/ORG 贪婪正则把"的地点为/活动将在/这次承办单位叫"框入 | `merge_spans` 同类别重叠改为**取置信度更高的精确边界**（不再强制取并集） | F1 0.94 → 0.99 |
| 词典 ORG/LOCATION 边界过宽仍产生 FP | GLiNER 激活时 `EntityDetector(detect_org_location=False)`，ORG/LOCATION 交给 GLiNER | FP 归零 |
| 训练缺"写作/记录为/敏感情况为"赋值句式 → 2 个地点漏检 | 复用训练实体值做**句式增强**重训（不泄漏测试值） | LOCATION 补齐 |
| 13 个标签一起推理 → 标签竞争稀释敏感属性分数 | GLiNER **分两趟推理**（语义 5 标签 + 格式 8 标签） | SENSITIVE_ATTR 恢复 |

**最终：validation 与 test 均 F1 = 1.0000（TP 124 / FP 0 / FN 0，14 类全满分）。**

效率：GLiNER/CampusNER 检测器改为**模块级单例缓存**（此前每次请求都重载 1.1GB 模型，
约 10s/次）；单例后首次 ~8.6s、之后复用。两趟推理使单条短文本延迟 ~43ms，仍在预算内。

### 11.7 数据自举轮：生成 300 条多样 gold，新测试集 F1 0.80 → 0.9382

**动机**：旧 gold test 已 1.0000（触顶），无法再提升；真正的泛化只能用**未见模式的新留出集**衡量。

**做法**
1. 写多样化生成器 `.workbuddy/tmp/gen_gold300.py`：14 类全覆盖、句式大量变体（引入词/语序/
   标点/长短句随机）、实体值全新；身份证带 **GB 11643 校验位**、银行卡带 **Luhn 校验**（保证
   正则底座也能验证）。产出 `data/ner_v3b/{train_aug300.jsonl(220), newtest300.jsonl(80)}`，
   700 个实体、偏移 0 错。
2. 训练配方（`.workbuddy/tmp/train_v3c.py`）：旧数据 **×4** 权重 + 新 220 + **60 条硬负例** +
   「X号场地」地点句式 30 条；从当前好模型出发，**LR 5e-6、700 步**。

**关键修复**：`merge_spans` 冲突优先级加入**检测器可信度**（正则 > 模型）。
原因：正则以 GB 11643 检出身份证（conf 0.99），但 GLiNER 以 1.0 分把同一 span 判成 API_KEY，
按置信度合并会把**已验证的正则结果覆盖掉**。正则带校验位/格式验证，是权威判定。

**结果**

| 模型 | 旧 gold test | 新留出集(未见模式) | 均值 |
|---|---|---|---|
| gliner_v3（原） | 1.0000 | 0.8000 | 0.9000 |
| v3b（从基座重训，无双负例） | 0.8615 | 0.8315 | 0.8465 |
| v3c 200 步 | 0.9440 | 0.8933 | 0.9187 |
| **v3c 700 步（最终，已提升为 gliner_v3）** | **1.0000** | **0.9382** | **0.9691** |
| v3c 1100 步（过拟合，弃用） | 0.9355 | 0.9382 | 0.9369 |

**经验教训**
- **训练步数是关键**：700 步是拐点，1100 步过拟合（旧测试集掉回 0.9355）。
- **必须加硬负例**：无负例的生成数据会让模型失去校准（"个人身份无关"曾被判成敏感属性）。
- **旧数据要加权**：新数据量超过旧数据会导致分布漂移，旧数据 ×4 才能既学新又不忘旧。
- **正则优先于模型**：带校验位的正则判定不应被模型的"高置信猜测"覆盖。

**新留出集剩余短板**（0.9382 中的 11 FP + 11 FN）：LOCATION 漏检 2、SENSITIVE_ATTR 8 FP、
PHONE 2 FP/1 FN、DORM 1/1 —— 主要是字母数字串类目间的边界模糊，属模型容量与数据分布的
固有难度，需要更多真实文本标注才能继续压缩。
