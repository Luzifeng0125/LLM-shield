# 隐盾项目计划书更改建议

对照文件：桌面《隐盾项目计划书_申报完善版_修订版_20261017.docx》
对照作品：2026-10-17 统一入口 `启动隐盾.cmd`
当前运行事实来自 `delivery/先读我.md`、`app/models/ACTIVE_MODELS.json`、`app/models/action_training_report.json`、`app/data/field_v1/eval_report.md` 和 `docs/archive/technical/执行状态.json`。

计划书可以继续把 GLiNER、全表精确计数、真实外部生成和独立人工验收写成研究目标。需要改的是把这些目标写成“当前原型已经完成”。

## 1. 当前入口与计划书主线要分开写

计划书摘要、3.1.2、3.2.3、3.4.1、3.5.2、4.4 多处写：当前原型已经完成本地 GLiNER 运行，并以 GLiNER 与轻量动作模型作为在线处理核心。

作品事实：

- 统一入口加载 `models/reviewed_ner` 的人工 gold BERT `ner_bert_v1`，解码为 `bio_viterbi`。
- 动作模型是 `segment_coverage_v2`（`models/necessity_action.joblib`），特征为 TF-IDF，分类器为逻辑回归。
- GLiNER 代码仍在，`use_gliner()` 默认关闭。启动脚本会关闭未参与本次验证的可选识别模型。
- 微调后的 GLiNER 权重不在当前运行目录，也不能从 GitHub 仓库补齐。

建议：凡写“当前 / 已完成 / 在线主链”的句子，改成 BERT 加格式规则。GLiNER 语义五类与 13 类保留在 3.3.2 的对照实验和 3.5.3 的阶段记录里，并删掉“当前默认”这四个字。`field_v1/eval_report.md` 第 3 节标题里的“当前默认”也已过时，计划书不要沿用。

## 2. 外部生成目前是模拟，不是已连通的 DeepSeek

3.4.4、3.5.2 写：已接入真实 DeepSeek，并在一条公开合成短文本上完成约 1.83 秒往返。

作品事实：

- `ACTIVE_MODELS.json` 中 `llm_mode` 为 `mock`。
- `启动隐盾.cmd` 强制本地模拟。此入口下填写 API 密钥也不会自动启用真实生成。
- 代码保留 OpenAI 兼容客户端，另有 `检查API连接.cmd` 供以后联调。
- 2026-10-17 通知验收记录 `external_model_called` 为 false。
- 当前仓库里找不到 1.83 秒这条记录。没有日志之前，不要写进计划书。

建议：3.4.4 改为“接口按 OpenAI 兼容格式预留，当前交付入口强制模拟回复”。若以后补做连通实验，单独写日期、模型名、是否使用合成文本，以及耗时是否包含网络。不要把历史连通和当前启动状态写成同一句话。

## 3. 工程测试数字要改成 10 月 17 日这次复跑

3.5.2 写：38 项冒烟、402 项 pytest，2026-10-17 复跑通过。

作品事实：同日清理后的复跑是冒烟 38 项通过，pytest 290 项通过、90 个子检查通过，1 条 Starlette/httpx 弃用警告，0 失败。仓库里对不上 402 这个数。

建议：改成上述口径，并写明这组测试确认的是接口、文件、会话和边界，不代替识别或动作的正式验收。

## 4. 动作分数要换成当前权重，并保持“弱标签”身份

3.5.4 写：训练 157 组、验证 53 组，准确率 0.9929，Macro-F1 0.9846。

当前 `segment_coverage_v2` 的分组留出记录是：

- 训练 23,304 条 / 217 组，验证 7,650 条 / 73 组，组重叠为 0。
- 准确率 0.9860，Macro-F1 0.9794。
- 标签来源是规则弱监督，不是人工动作 gold。
- 12 个开发例通过 11 个。剩下的一例是“活动地点：行政楼。”被识别成宿舍后，安全检查暂停。这 12 例已经参与开发，不能再称作盲测。

建议：替换组别和分数，保留“弱标签、非人工验收”这句。补上 11/12 和宿舍误识，避免读者把 0.9794 理解成任务动作已经达标。计划书表 3 里 Macro-F1 不低于 0.90 的句子继续作为拟验收目标，不要写成已经达到。

## 5. field_v1 的表可以留，但要补误报和身份

表 6 的三行数字与 2026-10-16 报告一致，可以保留：

| 配置 | 精确率 | 召回率 | 粒度无关 F1 | 严格边界 F1 |
| --- | --- | --- | --- | --- |
| 格式规则与词典 | 0.8814 | 0.6980 | 0.7790 | 0.6716 |
| GLiNER 13 类 | 0.7622 | 0.9463 | 0.8443 | 0.7940 |
| 语义五类加规则 | 0.8439 | 0.9799 | 0.9068 | 0.8607 |

建议补上纯负例误报：规则 3/17，13 类 13/17，语义五类 10/17。0.9068 低于表 3 拟定的 0.92，而且这批材料后来又用于模型选择，不能再称为新的独立盲测。3.5.3 末句“后续将以冻结的独立测试集重新验收”应保留，并明确这张表不是表 3 的验收结果。

## 6. 全表精确计数还是研究目标

3.2.5、4.2 写：对专业、学院、校区等单字段精确计数，扫描完整表格并与人工逐例对照。

作品事实：`aggregate()` 汇总的是已经识别出的人员、组织和金额区间，金额再做成区间。名单页只在本机返回各类片段计数。没有一条按“专业”列逐行精确匹配的全表计数路径。

建议：把“专业 / 学院 / 校区全表精确计数”移到拟研究内容和表 5 的对照设计。已实现部分改写为“本地聚合已识别实体，明细不外发；名单核对与通知草稿分为两次请求”。通知路径可以保留：名单只在本机识别，草稿只接收单独填写的公开活动名称和预设事项。

## 7. 验收目标、人员分工和预期成果不要提前写成完成

表 3 的 0.92、0.90、计数全对、暖启动 P95 不高于 1 秒、人工评分 4 分，都还没有对应的冻结测试。3.6 表 7 和第七章的交付物可以维持“拟完成”。

另外三件已知未完成，建议在 3.5 末或第五章第一阶段写明，避免和“已完成基础”混在一起：

- 地点、机构、宿舍的对照数据还没补，公共地点误识为宿舍的问题还在。
- 真实外部文案质量没有验收。
- 运行环境依赖本机 Python 3.12，还没有在第二台干净电脑上复现。

GitHub 上另一份 feature v3 动作权重与当前特征空间不同，没有替换 `segment_coverage_v2`。计划书不必写入这次取舍，也不要把它写成已经融合的新模型。
