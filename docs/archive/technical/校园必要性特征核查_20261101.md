# 校园必要性模型输入核查

日期：2026-11-01。查的是活动模型 `necessity_action.joblib`，SHA-256 `cbfed4ca422a1a6d416ce1b5f488649816c261b6acc86ffc173887c8dfed1b9f`。没有改权重，没有改规则。

## 结论

当前错误不全是输入缺失。任务键和接收方已经进入模型，活动通知和班级协作仍然选错，主要是任务键的编码和训练分布把它们带偏。用户的自然语言要求也写进了特征，但活动模型对三种不同说法给出的六个概率完全相同，差是 0。处理边界编号、接收方禁止项、级别上限和能否恢复没有进入必要性模型；这些只在模型选完动作之后，由硬约束决定放行还是暂停。

## 实际进入模型的内容

推理入口是 `NecessityModel.score`。它调用 `build_feature_text`，把一串文本分成两段，中间用 `[|SPLIT|]` 隔开。活动模型两段都用字符 2 到 4 元组。结构化一段权重 1.0，内容一段权重 0.35。

结构化一段有：

| 字段 | 例子 | 作用 |
| --- | --- | --- |
| `[CAT]` | `BUDGET` | 信息类别 |
| `[TASK]` | `meeting_minutes` | 任务键 |
| `[RECIPIENT]` | `viewer_teacher` | 接收方编号 |
| `[ROLE]` | `VIEWER` | 接收方类型 |
| `[TRUST]` | `high` | 接收方信任度 |
| `[IDENTITY]` | `student_leader` | 身份编号 |
| `[COL]` `[N]` `[CONF]` | 列名、片段数、置信度 | 片段形态 |

内容一段有：

| 字段 | 来源 |
| --- | --- |
| `[TASK_TEMPLATE]` | `tasks.yaml` 里该任务键的说明。`class_coordination` 不在这四个模板里，这段是空的 |
| `[TASK_TEXT]` | 用户这次输入的原话。没有原话时，退回模板说明 |
| `[CONTEXT]` | 片段上下文 |
| `[TEXT]` | 当前片段原文 |

同一条预算，只改用户原话，活动模型的概率向量如下。三句分别是「印刷费写出大概范围就行。」「请按收据上的原数字写入。」「语气正式一点。」

| 动作 | 三句的概率 |
| --- | ---: |
| `DELETE` | 0.402619 |
| `RETAIN` | 0.298961 |
| `PSEUDONYMIZE` | 0.284959 |
| `PAUSE` | 0.012493 |
| `GENERALIZE` | 0.000708 |
| `LOCAL_AGGREGATE` | 0.000259 |

三句之间每个动作的差都是 0。原话被放进了 `[TASK_TEXT]`，但没有改变判断。字符词表在训练时已经固定，这三句里新出现的字组没有影响到线性模型的输出。

接收方会改变结构化一段。`viewer_teacher` 和 `viewer_peer` 的接收方编号、信任度不同，特征前半段不同。

## 没有进入必要性模型的内容

`build_feature_text` 的参数里没有处理边界。`boundary_id` 只在 R0 和硬约束相关的规则里使用。

接收方配置里的 `forbidden`、`max_level`、`can_restore` 没有拼进特征。身份配置里的 `max_level`、`can_send_to`、`can_restore` 也没有。身份只以编号字符串出现。

因此模型在选动作时看不到「外部模型禁止接收预算」「同学的级别不够看金额」「老师可以恢复代号」。这些检查发生在 `decide_segment` 选定最高概率之后。检查失败只把动作改成暂停，不改选另一个动作。

班级协作的工作流说明也没有进入 `[TASK_TEMPLATE]`，因为 `tasks()` 只认识四个旧模板。用户原话仍在 `[TASK_TEXT]`，但是上面的探测说明，这段文字目前推不动活动模型。

## 和已经看到的错误怎么对应

活动通知的外部人名被判成本地汇总，概率约 0.91。任务键 `activity_notice` 已经在特征里，不是没把任务交给模型。它和 `activity_stats` 共用「activity_」的字符片段，而社团统计的人名偏好是本地汇总。这是任务键编码和训练分布的问题。

班级协作的外部人名被判成泛化，概率约 0.52。任务键 `class_coordination` 也已经写进特征，但训练任务里没有这个整词，模板说明又是空的。模型是在一个没学过的任务键上选了泛化。

会议纪要的外部预算被判成删除，泛化概率接近 0。用户有没有写「大概范围」，活动模型给的分布一样。金额错误不能归因于「原话没送进模型」，要归因于这段原话没有形成有效特征。

邮箱、宿舍、分数先被模型选成保留，再由硬约束改成暂停。禁止项没有参与必要性判断，所以模型自己不选删除。暂停挡住了原文，任务却停住了。

授权老师能不能看原名、公开渠道的级别够不够，模型都看不到。它只能看到接收方编号和信任度。旧批次里老师本机查看和公开发布的争议，不能靠现有特征自行分开。

## 对下一轮的含义

下一轮如果仍用这份活动模型的特征，单靠多标数据，学不会「粗略金额」和「原样金额」的差别，也学不会接收方禁止项。那两项要么让相应字段以模型能用的方式进入特征，要么继续放在硬约束里，并接受硬约束只会暂停。

共享特征函数仍然没有加上金额精度或接收方禁令。2026-11-01 晚另训了一份候选，只用任务、类别、接收方这三格去贴校准标签，内容权重为 0。活动权重没有换。说明见 `docs/archive/technical/校园必要性对齐候选_20261101.md`。

2026-11-02 没有改版本 3 的特征函数，活动模型的输入保持原样。新候选使用版本 4：原话的每个字和类别绑在一起，单独成段，权重为 3；原文段权重仍是 0。边界、能否发送、能否恢复和类别是否被禁，写进结构化段。说明见 `docs/archive/technical/校园必要性任务需求候选_20261102.md`。
