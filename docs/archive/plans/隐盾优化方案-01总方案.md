## 1. 项目目标与此次范围

目标是：**构建并验证一个在既定权限约束下，根据任务、上下文和接收方选择最小必要披露形式的本地轻量决策模型。**

模型要区分三件事：

1. 信息对任务有没有用。
2. 完成任务是否必须把它交给这个接收方。
3. 这个接收方是否确实有权获得这种形式的信息。

例如，负责人姓名有助于你在本机核对分工，但外部生成服务通常只需稳定代号与“事项—期限”关系。信息有用，不意味着姓名原值必须外发。

继续按既有讨论安排：约 70%—80% 的研究与数据工作投入必要性判断及其验证；其余投入输出、用途、生命周期、界面和交付验证。比例是投入方向，不允许为了守比例搁置已发现的安全缺口。

**本阶段默认目标：单机、单用户、单进程研究与演示版本。** 多人联网部署作为独立扩展阶段，必须增加真实身份、资料归属和隔离验证，不能只把监听地址改为局域网地址。

三张图片可转化为以下设计要求：

- 数据最小化：先在本机选择任务所需字段、必要关系或统计结果，再做出站检查。
- 目的限定：资料的获准用途跟随原始资料及派生会话，不能靠文档中的一句指令扩权。
- 生命周期：区分临时保存、长期本机资料库、会话清除、资料删除及派生状态失效。
- 输出保护：分别检查模型请求、查看者结果、工具提交，不能把某一个边界通过当作全部通过。
- 隐私与效用平衡：同时测未授权披露、过度删除和实际任务完成，不用“全部删除”制造优异安全结果。

不在本阶段增加差分隐私训练、联邦学习、同态加密、成员推断防御或大型生成模型训练。这些不能直接修复当前标签、用途和输出问题。若将来提供对外统计查询服务，再独立研究小群体、差分查询和正式隐私预算。

稳定代号属于去标识化思路，保有映射时不能宣传为不可恢复匿名化。图片中的法律时间线不是当前法规核对表；产品文案只能陈述已实现控制，不能直接写“已全面合规”。最小范围、保存期限及去标识化/匿名化概念可对照[《个人信息保护法》正式文本](https://www.miit.gov.cn/jgsj/zfs/fl/art/2022/art_515a4b20c12f430eab54bb4f56d89f56.html)；具体真实业务适用判断由资料负责人和必要时的专业人员完成。

## 3. 人员、模型与软硬件安排

### 3.1 人员分工

- **你：项目与资料负责人。** 决定业务目标、权限、保存期限、统计口径、资源预算和最终可用性；可兼任标注 A。
- **真人 B：独立标注者。** 在不看 A 答案和机器建议的情况下判断题目。不能由同一人换编号，也不能由第二个 AI 充当。
- **裁决人：** 优先由第三位了解业务的人担任。没有第三人时，可在独立提交后由 A/B 共同讨论并记录；必须如实标为讨论裁决。
- **盲测保管人：** 你或独立评估者；在候选和阈值冻结前，不把盲测原文、标签和逐题反馈交给训练 AI。
- **AI：工程和研究执行者。** 编写工具、校验数据、整理分歧、训练候选、运行实验、修复代码、整理证据。AI 不替真人签署授权、补造标注或认定现实身份。

### 3.2 模型方案

**必须保留的基线：**

1. 格式敏感信息：现有正则、词典及格式校验。
2. 语义实体识别：恢复当前项目 gliner_v3；其配置使用 microsoft/mdeberta-v3-base。GLiNER 的职责是发现实体，不是决定披露权限。[官方项目说明](https://github.com/urchade/GLiNER)
3. 披露动作：先继续字符 TF-IDF + 逻辑回归，保留结构信息、任务描述、上下文和接收方输入。
4. 生成：软件检查用 mock；整链路真实验收可使用当前已配置的生成服务，仅发送获准的虚构或公开输入。

**有条件加入的候选：**

- 第一档：BAAI/bge-small-zh-v1.5 作为本地冻结文本编码器，输出向量后训练分类头，同时保留结构特征。它不是开箱即用的隐私决策模型，必须学习本项目标签；不把相似度直接当披露置信度。[官方模型卡](https://huggingface.co/BAAI/bge-small-zh-v1.5)
- 第二档：只有第一档仍在关系语义上稳定失败、数据覆盖足够，才评估 hfl/chinese-roberta-wwm-ext 加六类分类头。它是中文预训练编码器候选，不是恢复退役的 NER BERT 默认路径。[官方模型卡](https://huggingface.co/hfl/chinese-roberta-wwm-ext)
- 不因“更大”就升级。先按错误归因区分：漏检、上下文缺失、标签矛盾、权限不明、动作分类错误或转换实现错误。

六类动作固定为 DELETE、LOCAL_AGGREGATE、GENERALIZE、PSEUDONYMIZE、RETAIN、PAUSE。权限和硬约束只能批准候选或暂停；第一名被拒绝后，不自动改选第二名。

当前决策单位是一个 Segment 片段，而非每个实体独立选择动作。新增多实体数据时，标注片段的首选动作，同时记录各实体期望的残留表达与必要关系。例如同一片段选择 PSEUDONYMIZE，可能将姓名改为代号、同时删除电话。若现有六动作无法满足所需组合，记录为分段/转换能力缺口；不能强造“正确动作”，也不能未经独立设计改成逐实体决策。

### 3.3 系统与设备

以下是规划建议，**不是本机硬件实测或保证运行的最低配置**。本次系统硬件读取未成功；历史文档还有 RTX 5060 与 RTX 4060 Laptop 两种描述，采购前必须核实当前设备。

- 人工标注：普通 Windows 电脑、Edge/Chrome、可保存 JSON 的本机目录；无需 GPU、API 账户和网络。
- 轻量模型与软件检查：沿用现有 Python 3.12 环境，普通多核 CPU；16GB 内存作为工作配置建议，32GB 更便于同时运行模型与浏览器。优先使用现有机器。
- 存储：预留约 20—40GB 工作空间作为起始安排，实际以权重、环境、数据与独立实验输出大小盘点为准；不要为此删除原始证据。
- GLiNER：先用 CPU 完成正确性验证，再测现有 GPU；速度是否可接受由实际材料规模决定。
- 编码器训练：冻结编码器分类头可以先用 CPU；需要微调时再试现有约 8—12GB 显存设备，以实际峰值、序列长度、batch 和优化器为准。GLiNER 重训另行估算，不能套用这一显存建议。
- 异机验收：另一台电脑或新建、可重建的虚拟机。虚拟机可证明安装流程，不自动证明不同物理设备的性能。
- 不强制购买云 GPU、服务器、向量数据库、Docker、Kubernetes 或本地大生成模型。

依赖基线以本项目已验证环境为起点：Python 3.12；scikit-learn/joblib；FastAPI/uvicorn；文档解析组件；GLiNER 额外依赖目前写有 gliner==0.2.29、transformers==4.57.6、torch>=2.6,<3。未来 AI 应冻结实际验收的完整版本和 CPU/CUDA 组合，不进行无差别升级。

## 4. 分阶段实施步骤

下面每一步都包含负责人、目的、执行逻辑、交付物和完成条件。步骤之间允许并行，但依赖不能跳过。

### S00｜建立可追溯基线

**执行：AI。你只需确认维护目录和保留材料。**

目的：防止后续报告引用错版本，也防止旧工作覆盖本轮成果。

1. 记录分支、基准提交、未提交差异、活动模型哈希、非敏感环境信息。
2. 盘点已有报告，按“当前实现”“旧证据”“待验证”归类。
3. 新建独立方案实施产物目录，记录输入、输出和版本；保留现有实验与用户报告。
4. 核对真实模型缺失和规则模式边界，不根据历史状态补写就绪。

交付：基线清单、阶段验收清单、恢复路径说明。

完成条件：每项指标可追溯到代码/数据/模型/模式；没有覆盖旧产物。版本漂移时先更新差异说明，再继续。

### S01｜冻结业务与数据使用口径

**执行：你主责；AI 提供表单、示例和矛盾检查。必须人工完成。**

目的：给模型一个稳定目标，也给工程控制一个明确边界。

1. 对会议纪要、活动统计、项目介绍、名单核对与通知，逐项写清输入、产出、必须保留的事实。
2. 为每个实际接收方填写：可见哪些类别、什么精度、用途、授权依据和有效期。
3. 决定统计按记录、人次还是去重人数；若去重，确定合法且可靠的键。
4. 确认临时保存 30 分钟是否适合；资料库保留条件；旧材料如何确认或迁移。
5. 确认本期只做本机研究演示还是需要多人联网。
6. 在看盲测结果前确定质量目标和不能接受的失败类型。

交付：人工填写的业务决策记录，详见人工手册 H01。

完成条件：业务问题没有被 AI 自行填成“已授权”。未确定的现实权限必须保持未知，未知不能靠模型预测补齐。

### S02｜完善人工复核协议与页面

**执行：AI；你确认表单含义。依赖 S01，先于大批量标注。**

目的：避免两人动作一样、事实理解不同，却被自动认定完全一致。

1. 增加结构化必要事实、关系、缺失证据和协议版本。
2. 校验首选动作与最小表达一致；多个等价动作需分别说明满足任务且披露最少的理由。
3. A/B 的关键事实、关系、动作或表达冲突进入待裁决；自由文本措辞不同不直接判错。
4. 旧导出缺新字段时标为“需补充”，不能由 AI 补成真人答案。
5. 冻结输入哈希、标签哈希、A/B/裁决文件哈希及工具版本；旧文件只读保存。
6. 增加未保存提醒、导出提醒、续标版本检查；使用明确标为自动测试的虚构导出验收。

交付：新版离线页面、合并器、协议说明、兼容策略和测试证据。

完成条件：缺一方、同一人编号、事实冲突、版本不符、硬约束冲突都不能进入“已双人复核”状态。

### S03｜完成首批试标与口径裁决

**执行：你/A + 真人 B；AI 只汇总。依赖 S02。**

目的：在投入全量人力前发现定义歧义。

1. 两人独立完成现有首批 28 题，不看机器建议。
2. AI 汇总分歧和误解类别；两人或裁决人逐条说明理由。
3. 对含混定义修订规范；受影响的已标题目重新核对并产生新版本。
4. 补一小批其他来源/表达的校准题，覆盖首批没有体现的多实体、泛化和暂停情况。

交付：两份真实导出、裁决记录、稳定规范版本。

完成条件：首选动作/最小表达/关键事实的实质分歧均已处理；不能以追求某个一致率为目的强行改答案。28 题完成仍不能宣称模型已通过人工验收。

### S04｜全量复核与有目的地补数据

**执行：AI 准备和校验；你/A、B 负责标签。依赖 S03。**

目的：把当前机器草稿变为可追溯的人类监督，并补当前分布空白。

1. 分批完成 336 条复核，首批可在规范未变化且哈希相符时续用。
2. AI 输出按动作、任务、实体、身份、接收方和模板族的覆盖情况。
3. 优先补 GENERALIZE、PAUSE、多实体、职责变化、同名不同人、不同授权状态；同时保留真实使用频率，避免只构造极端难题。
4. 同源改写、任务变体、上下文变体归入同一分组；检查近重复，不能靠改几个名字跨拆分。
5. 起步可追加约 120—240 条有明确缺口的判断；这是分批预算建议，不是固定统计充分性标准。是否继续由错误和覆盖决定。

交付：冻结人工复核版本、覆盖报告、分组清单、未完成项。

完成条件：进入实验的样本来源和标签状态真实；未裁决或单人标注不能混成双人金标。若采用部分完成子集，必须重新说明它的覆盖与合法分组，不能静默丢弃难题。

### S05｜验证并收紧资料生命周期

**执行：AI；你决定政策。可与 S03—S04 并行。**

目的：让删除、到期和用途控制在长处理、首次使用及多个入口中保持一致。

完成条件：拒绝路径没有实际外发；删除后的派生状态不可继续用。物理文件清理由触发时机决定，不宣称到秒安全擦除。

### S07｜恢复真实 GLiNER 识别环境

**执行：你提供可信文件/位置/来源；AI 校验、隔离加载和测试。可与标注并行。**

### S09｜训练轻量候选，再决定是否上编码器

## 5. 指标如何定义，如何防止“看起来很好”

### 5.1 动作层

- 可接受动作率：预测动作属于人工允许集合的条数 / 全部判断数。
- 宏平均 F1：使用唯一首选标签，逐类计算再平均；同时报告允许集合指标，说明二者差异。
- 非暂停覆盖率：非 PAUSE 条数 / 全部判断数。当前代码字段 completion_coverage 应改名或解释，不能译为“任务完成率”。
- 非暂停动作错误率：非暂停且不在允许集合的条数 / 非暂停条数；分母为零时写不适用，不能记成零错误。
- 应暂停召回、错误保留原值、过度删除：逐项定义分母，按类别和接收方分层。

### 5.2 任务与边界层

- 会议纪要：负责人/稳定代号—事项—期限关系是否正确；没给期限不要求编造。
- 活动统计：与独立计算结果一致，口径明确；记录数、人次、去重人数分别统计。
- 项目介绍：授权公开事实是否保留，内部信息是否混入，有无编造。
- 名单通知：名单本机核对与公开通知输入分离；通知只依赖独立公开事实。
- 隐私：分别报告 B1 请求、B2 显示、B3 工具、接口 JSON、错误、日志和后续历史中的未获准披露。零观察泄漏仅说明本次样本未观察到，不是数学保证。

### 5.3 验收目标如何冻结

安全阻断条件固定：确认的未授权外发、映射泄漏、无依据扩权、盲测用于调参、伪造人工数据，任一出现即不得晋级。

其他质量指标由你在盲测前确认。可采用如下**讨论起点，不是现有成绩或行业标准**：人工允许动作率至少 90%、宏 F1 至少 0.85、业务事实/关系正确率至少 90%；非暂停覆盖不低于已确认可用基线且不靠放宽安全换覆盖。达不到时调整数据或模型，不在看到终测后降低门槛。

每项均报告数量、比例、来源组和区间。仅 56 条、且来自两个模板族的验证集，不足以把“5% 动作错误上限”当隐私保证；应优先增加独立来源。概率阈值选择和概率校准不是同一件事，未经校准的 predict_proba 不自动等于现实正确概率。[scikit-learn 概率校准说明](https://scikit-learn.org/stable/modules/calibration.html)

## 6. 依赖、时间与停止条件

关键路径：

    S00 基线 → S01 业务口径 → S02 复核工具 → S03 试标 → S04 人工数据
      → S08 实验协议 → S09 候选 → S10 整链路 → S11 性能/设备验收
      → 冻结最终版本 → S10 独立盲测 → S12 交付

可并行：

- 人工标注期间，AI 完成 S05 生命周期、S06 界面/统计/完整性。
- 你寻找权重，AI 准备 S07 加载校验；不阻塞提供实体的动作研究。
- 独立评估者在训练期间保管新盲测；不把内容反馈给训练方。
- S13 多人部署不挤占当前核心研究，除非你修改目标。

按实际投入估计，不作为保证：

- 业务口径：你约 1—2 小时，复杂权限另计。
- 28 题试标：每人约 45—90 分钟，之后约 1—2 小时讨论；复杂题更久。
- 336 题：按每题 1.5—3 分钟，每人约 8.4—16.8 小时；两人共约 17—34 人时，另加裁决。不能按“AI 训练几分钟”来估整项研究工时。
- AI 工程与实验：建议分 5—10 个工作日穿插推进，取决于复现问题和人工资料到位；扩展编码器、补盲测或重训 GLiNER 单独估算。
- 60 个新源案例与标签：安排数个独立工作时段，先试做 5 个估实际耗时，再确定总量；不要压缩人工判断来赶时间。

你本次提到的“五小时额度”用于方案质量要求，不是将来全部实施工作的工期，也不能由 AI 保证读取或耗尽。此次方案以覆盖完整、依据可核查和任务可交接作为完成标准。

遇到阻塞的处理：

- 没有第二位真人：继续单人试标和工程工作，不能称双人金标或晋级候选。
- 没有 GLiNER 权重：继续软件与动作层研究，真实识别/端到端栏保持未完成。
- 没有真实 API 账户：完成 mock 与真实本地模型验证，真实生成另列待做。
- 轻量模型达标：停止新增模型，进入交付；不为了“用了深度学习”增加成本。
- 阈值无可行解：不放宽硬约束；分析标签、覆盖和错误，继续补数据或维持旧模型。
- 盲测失败：记录失败、退回开发、使用新盲测再次终验；不反复刷同一测试集。
