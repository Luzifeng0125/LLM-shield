# 隐盾优化方案：人工执行手册

定稿日期：2026-10-27；依据 2026-10-26 核对的现状。**本手册供未来实施使用，本轮没有替你执行以下操作。**

[返回总方案](<D:/challenge_AI/LLM-Shield/docs/archive/plans/隐盾优化方案-01总方案.md>) · [AI 任务书](<D:/challenge_AI/LLM-Shield/docs/archive/plans/隐盾优化方案-03AI任务书.md>)

**你不需要亲自写训练代码、调参、跑回归或制作安装包。你必须提供的，是业务标准、现实授权、真正独立的人工判断、可信模型来源，以及最终使用体验。**

## H00｜先确认有哪些事不能由 AI 代办

以下几项必须由你或你指定的真人负责，AI 可以解释、检查和整理，但不能替你作出事实声明：

1. 某份现实材料是否允许处理、给谁看、能保存多久。
2. 某个任务真正必须保留的事实、关系和统计口径。
3. A/B 两位真实标注者的独立判断。
4. 有业务歧义时的最终裁决。
5. 未参与开发的新盲测材料及其标准答案。
6. 旧权重由谁提供、来源是否可信、是否可以分发。
7. 外部生成账户、可使用数据、预算和服务条件是否符合团队要求。
8. 真实手机/第二台电脑上的体验，以及最终结果是否可用。

没有条件完成某项时，告诉 AI 缺什么即可。不能让 AI 用模拟答案填补，然后将状态写成“人工完成”。

## H01｜重点：填写业务与权限决策记录

**目的：**先定义“正确答案”，再要求模型学习。建议你用 1—2 小时整理初稿，与 B 一起核对。

**所需：**普通文档编辑器即可。此记录可以是本机文本，不需要数据库、GPU或联网。

### 第一步：确认本期使用范围

按以下格式填写；不知道的写“待定”，不要猜：

    项目负责人：
    本期主要用途：本机研究演示 / 团队内部联网 / 其他明确范围
    实际操作者：
    资料所有者或管理者：
    是否必须完全离线：
    是否允许把经处理的虚构/公开输入发送给外部生成服务：
    是否计划让其他人远程访问：
    本期必须完成的任务：
    本期不做的任务：
    预计使用设备：
    软件/云服务预算上限：

推荐先以本机研究演示为范围。若要多人联网，必须另做真实认证与数据隔离；“页面选择老师身份”不证明操作者真的是老师。

### 第二步：为每个任务写一张任务卡

至少填写会议纪要、活动统计、项目公开介绍；若使用名单页面，再填名单核对与公开通知。

    任务名称：
    输入材料是什么：
    最终结果交给谁：
    必须保留的事实：
    必须保留的关系：
    不需要的信息：
    哪些计算可以只在本机完成：
    哪些内容允许交给外部生成服务：
    哪些内容只允许本机授权查看：
    信息缺失时可以省略什么：
    信息缺失到什么程度必须暂停：
    成功结果的一个例子：
    失败结果的一个例子：

填写示例：

- 会议纪要：需要“负责人—事项—期限”，外部排版可使用稳定代号；电话号码通常不需要。材料没给期限，结果应写未明确或请求补充，不能编造日期。
- 活动统计：先决定统计记录、人次还是独立人员；外部写总结可能只需要经过审核的汇总，不需要名单。
- 公开介绍：需要获准公开的项目目的、功能和成果；内部成员身份、联系方式不因“有助宣传”自动可用。
- 名单通知：本机核对名单与生成公开通知是两项处理；公开文案依据独立输入的活动事实，不能自动从名单提取联系人。

### 第三步：逐接收方写授权边界

请分别对“本人本机查看”“实际获准老师”“同组同学”“外部生成服务”“公开网页/消息渠道”填写，不要笼统写“学校内部都可以”。

    接收方及如何验证其身份：
    允许接收的资料类别：
    允许的表达精度：原值 / 代号 / 粗粒度 / 汇总 / 不允许
    允许用途：
    授权依据或负责人：
    有效期：
    是否允许保存/转发：
    未确认事项：

**重点：**在虚构标注题中，可以把题目明确给出的授权作为设定；现实系统中，材料正文里的“老师授权了”不是授权证据。不要把“我是负责人”直接当作可向任意云服务发送资料的依据。

### 第四步：确定统计口径

每一种统计分别回答：

1. 一行是否等于一个人？是否可能一人有多次参加记录？
2. 统计的是记录条数、人次，还是去重人数？
3. 去重键是什么？仅用姓名可能把同名不同人合并。
4. 去重键空白、重复但内容冲突时怎么办？
5. 空行、合计行、不同工作表是否计入？
6. 两份上传表存在重复时是否合并？合并依据是什么？
7. 专业名称的别名、前后空格、全角字符是否等价？
8. 条件没有匹配时，0 是否就是正确答案？

如果尚未确定，保持当前“按记录计数，未按身份去重”的说明；不要让 AI 自动选择姓名或学号替你决定口径。

**还需区分两种已有统计路径：**聊天精确计数的结果仅本机显示；普通 LOCAL_AGGREGATE 动作生成的汇总会加入外部请求。后一条当前以姓名字符串去重，可能把同名不同人合并。因此你要另外决定哪些汇总允许外发、按什么群体和精度、是否允许连续条件查询。不要因为“没有姓名”就默认小群体统计可以公开。没有确认的发布规则，真实敏感汇总应继续留在本机或暂停。

### 第五步：确定保存与删除

    临时资料默认 30 分钟：接受 / 修改为明确期限 / 待定
    到期后：禁止继续使用；如何提示用户：
    本机资料库是否允许长期保存：
    资料库清理负责人和检查频率：
    旧材料是否重新确认用途：
    正在处理时删除：接受提示忙碌后重试 / 需要取消机制
    清除聊天后是否仍保留原上传：
    存放目录是否被网盘、系统备份或其他程序同步：
    派生导出或截图由谁保管：

30 分钟目前表示访问有效期，物理清理有触发条件；本地删除不等于所有备份、对方已接收副本和磁盘残留都被删除。你只需如实说明副本位置，AI 根据明确范围设计控制。

### 第六步：提前确定验收目标

先确定你最在意什么：隐私错误不能接受、会议分工不能错配、统计不能算错、等待不能太长等。

总方案中的 90% 动作允许率、0.85 宏 F1 等仅供讨论，不是必须照抄的行业标准。应在盲测前写下最终目标、分母和适用任务；盲测结束后不能为了“通过”临时降低要求。

**交给 AI：**上述记录、仍待确认的问题，以及你指定的负责人。不要附带真实名单、API 密钥或无需处理的个人材料。

## H02｜重点：安排真实 A/B 标注者与裁决人

**目的：**获得独立判断，发现口径不清，而不是让两份表看起来一致。

1. 你可以担任 A，找另一位理解校园事务的同学或老师作为 B。
2. 两人都读标注规范，但在独立提交前不看对方答案、不看机器建议、不讨论具体题目。
3. 可以共用一台电脑，但分时操作、各存独立文件、互不导入对方导出；各自电脑更容易保持独立。
4. 给真人分配本机编号，例如 R01、R02。真实姓名与编号对应表由你保管，不必提交 Git或分享给其他模型。
5. 优先另找一位了解业务的人裁决。若没有第三人，允许 A/B 在独立提交后讨论，由指定人记录；如实注明讨论裁决。
6. 若只有你一人，允许做单人试标、准备材料、跑工具；不能把第二次重标伪装为独立 B。

建议约定：

    A 的编号：
    B 的编号：
    两人是否确认独立作答：
    裁决方式：第三人 / A-B讨论
    裁决人或记录人：
    使用规范版本：
    每批题量：
    文件交接方式：
    盲测保管人：

AI 可以给你们讲六类动作、检查漏填、解释页面错误，但不应在独立作答前告诉你们某一题“应该选什么”。遇到难题，先记录疑问。

### 开始前

1. 选择不会自动同步到不明共享空间的本机工作目录。
2. 打开复核页面，不需要启动隐盾服务、不需要 API key、不需要安装训练环境。
3. 在“载入题目”选择 review-first-batch.json。
4. 填你的真实标注者编号，角色选“独立标注 A”或“独立标注 B”。
5. 确认显示 28 题，并核对规范/题目版本。
6. 不打开 cases.jsonl 看 proposal，也不看实验报告的逐题预测。

### 每一题按这个顺序思考

**第一问：任务最终要完成什么？**

把任务写成结果，例如“输出每人应做的事项和期限”，不要只复述“做纪要”。

**第二问：目标实体与任务的必要事实是什么关系？**

姓名可能只是参加者名单，也可能是责任关系的连接点。不能看到姓名就一律删除或保留。

**第三问：是否只在本机计算就能完成？**

如果只是人数统计，先确定统计口径；本机计算可以完成的，不应为了让外部模型算数而发原始名单。

**第四问：需要给这个接收方的最少表达是什么？**

考虑不需要该信息、汇总、稳定代号、粗粒度、原值。代号和粗粒度适合不同任务，不是一条可以简单排序的统一安全等级。

**第五问：接收方真的获准接收这种表达吗？**

依据题目明确的身份、接收方、上下文和硬约束。不从角色称呼自行补授权。

**第六问：信息不确定会不会使任务无法正确完成？**

不影响任务的信息可以删除；关系、授权或事实不明且无法安全完成任务时选 PAUSE，并明确需要补什么。

### 六类首选动作与填写含义

现有模型对一个片段选择一个动作，当前题库主要是单实体题。扩展到多实体后，你仍判断片段的动作，另外写出各实体应该保留成什么形式。例如“姓名+电话+事项”选择代号动作时，期望可以是“姓名→代号、电话→删除、事项→保留”。不要误以为你可以在旧接口里给每个实体各选一个独立动作；现有动作无法表达时，标为能力缺口并交给 AI 分析，不强填金标。

1. **DELETE / none：不需要这个信息。** 删除该实体或片段不破坏必要事实。若删除后负责人关系丢失，就不能仅因“更安全”选它。
2. **LOCAL_AGGREGATE / local_aggregate：本机计算后使用汇总。** 普通转换路径会将汇总加入外部请求，和聊天仅本机显示的精确计数捷径不同。必须同时定义统计口径和汇总发布许可；此动作不意味着任何小群体统计都可以外发。
3. **PSEUDONYMIZE / pseudonym：需要关联，不需要身份原值。** 使用稳定代号保留责任人等关系；映射只在本机授权范围保留。
4. **GENERALIZE / coarse：只需要较粗的信息。** 如“某校内社团”；粗到什么程度仍有用，应在理由里写明。
5. **RETAIN / original：确需原值且获准接收。** 两个条件缺一不可，还必须符合现有硬约束。若规则不允许，不可自己勾保留后要求 AI 改规则迎合答案。
6. **PAUSE / uncertain：缺少关键事实或权限，暂不能处理。** 写出缺项；不是不愿判断时的默认选择。

“其他同样充分且最少披露的动作”可以留空。只有能说明每个替代动作如何同样完成任务、且没有多披露时才填写。不能把所有安全动作都列为正确答案。

### 应写多具体

“必要事实/关系”示例：

    同一负责人对应任务A；任务A截止周五。真实姓名和电话号码不是外部排版必需。

“判断依据”示例：

    任务要求追踪责任归属，因此需要区分负责人。接收方为外部生成服务，
    稳定代号足以保留关系；原值没有额外必要性。期限来自材料，不补造。

不要只写“安全”“有用”“按规定”“选这个比较好”。这些理由无法用于裁决，也不能判断模型学错了什么。

上述例子是规范说明，不是现有 28/336 题的参考答案。

### 保存与退出：最容易出错的地方

1. 每题填完，点击“保存当前题并下一题”。
2. **直接点“下一题”不会保存当前正在修改的答案。**
3. 每完成约 5—10 题导出一次；结束前先保存当前题，再导出。
4. **当前页面保存的是内存状态，不是自动写入硬盘。刷新、关闭或更换题库前必须导出。** 未来工具若增加提醒，也不能把提醒当成磁盘备份。
5. 在浏览器下载目录确认 JSON 文件确实存在、不是 0 字节。可以改文件名，不修改内部内容。
6. 推荐文件名：pilot_R01_A_202610xx_第1次.json；完整批次用 full_R01_A_日期_批次.json。
7. 不覆盖旧导出；新导出包含续标结果时保留最近一次完整版本，同时归档旧版本。

### 续标

1. 重新打开同一版本页面。
2. 先载入同一题目文件。
3. 再在“续标文件”载入你自己的最近导出。
4. 检查角色、编号、已保存数量和一两道已做题。
5. 版本或哈希不匹配时停止，交给 AI 诊断；不要手工改哈希绕过检查。

### 文件交接

把 A/B 各自的导出放到当前复核包的 reviews 本机目录，并给 AI 指明实际文件名。现有目录已被 Git 忽略，但 Git 忽略不等于禁止网盘同步或禁止工具读取。

你可以这样交接：

    这是规范 vX 的首批真实人工标注。
    A 文件：实际绝对路径；标注者编号 R01。
    B 文件：实际绝对路径；标注者编号 R02。
    两人独立提交；请先核验版本、哈希和完整性，列分歧。
    不要替我们补缺失答案或自动裁决事实差异。

**完成标志：**AI 给出实际已标数量、缺失和分歧清单；不是“浏览器显示导出成功”就算全部题目完成。

## H04｜重点：如何裁决分歧

**目的：**识别规范、材料和理解的问题，形成可解释标签。

1. 先保留 A/B 原始导出，只读归档；不要把两人答案改得一致后再交。
2. AI 应将分歧按动作、最小表达、必要事实/关系、授权、技术规则冲突分组。
3. 每条先回到任务目标，再看两人的证据。不要以模型预测或“多数 AI 意见”决定。
4. 如果材料缺事实，最终可以是 PAUSE 或“题目需修订”，不必强行选一个披露动作。
5. 如果规则和业务需求冲突，记录为需求/策略冲突。修改规则属于另外的业务决定，不能只为让某题进训练集而放宽。
6. 在页面选择“歧义裁决”角色，填写最终判断与理由，导出新文件。
7. 若由 A/B 共同讨论，记录参与人和方式，不声称第三人独立复核。
8. 规范改变时，让 AI 找出受影响题目；你们复查后生成新版本。哈希旧答案不能自动继承。

裁决记录至少写：

    案例编号：
    分歧点：
    A 的核心依据：
    B 的核心依据：
    最终必要事实/关系：
    最终动作与最小表达：
    依据：
    尚缺的证据：
    是否修改规范：
    裁决人/讨论参与人：
    日期：

**完成标志：**该批进入训练的题目没有未处理的实质冲突；仍有争议的题目保持待处理。不能把“不知道”写成“已解决”。

## H05｜重点：如何完成全量复核，避免无效劳动

前置：首批口径稳定，工具可正确处理事实分歧，AI 已确认可以继续。

1. 载入完整 review-task.json。首批答案只有在版本兼容、规范未改变时续用；由 AI 明确迁移方式。
2. 两人继续独立完成，建议每次 20—40 题，40—60 题作为一次交接批次；按疲劳程度调整。
3. 不要求每批立刻讨论全部题；先独立导出，再按批次裁决。
4. 定期查看 AI 输出的剩余数量和覆盖分布。它只反映进度，不是人工质量分数。
5. 扩展数据优先补明确缺口：稀少动作、未知表达、多个实体、授权不明、上下文变化、数字统计边界。
6. 所有机器新写题必须标为机器草稿，仍需真人判断；改几个姓名不算新的独立来源。
7. 若人力不足，与你的研究目标一起缩小支持范围，而不是让 AI 补答案伪装全量完成。

工作量估计：336 题按每题 1.5—3 分钟，单人约 8.4—16.8 小时，两人约 17—34 人时，加上裁决。建议先测自己完成 10 题的实际时间，再调整安排；这不是必须压到的时限。

**你最终交付：**A、B 原始导出，裁决导出，规范版本，真实参与确认，尚未完成清单。AI 负责合并、校验、统计、冻结和训练准备。

## H06｜重点：寻找原 GLiNER 权重

**目的：**恢复真实识别能力，不把配置文件或同名底座误当已经训练的模型。

### 你要找什么

项目缺的是 gliner_v3 目录中的 pytorch_model.bin。只有 tokenizer/config 文件不够。尽量找完整模型目录、训练日志和对应数据版本。

优先从自己或团队控制的位置找：

1. 原训练电脑的项目 models/gliner_v3。
2. 训练服务器的导出目录和可信备份。
3. 团队成员保管的最终训练产物。
4. 明确来源、日期和版本的备份盘。

不要仅因网上有相同文件名就下载替换。也不要把聊天记录、密钥或真实训练原文一起打包给 AI。

### 给 AI 的模型交接卡

    原训练/导出日期：
    底座与版本：

    训练数据版本与来源：
    数据使用授权情况：
    是否允许在本项目使用：
    是否允许向其他人分发：
    已知文件大小/哈希：
    未知项：

    3e7d4c3d704920e78fc0a8d65a768aaab4e095d0ae8c0da2fb96615d4883a360

AI 会计算实际哈希和核对配套文件，你无需亲自写命令。文件可信来源要先确认；不应让 AI直接在主环境加载来源不明的 .bin/.joblib。

### 找不到时怎么决定

明确告诉 AI：“原产物尚未找到，保持真实 GLiNER 验收未完成；先继续不依赖它的工作。”

若要新训练，再单独确认新数据、训练预算和识别验收方案。新模型有新哈希，不能要求它冒充原始权重；旧评测数字也不能自动沿用。

## H07｜重点：准备独立盲测

**目的：**验证模型能否处理开发者未见过的情况，避免一边看答案一边优化后仍称“独立测试”。

### 谁准备、放哪里

你或未参与训练的评估者准备并保管。优先自己重新编写的虚构校园材料，不必收集真实隐私来证明系统处理隐私。

盲测放在训练 AI 不读取的位置；仅文件名叫 blind-test 并不能实现隔离。可以由你保管在另一个明确目录/设备，直到候选冻结才交给评估执行方。AI 在冻结前只知道场景规格与数量，不知道原文、标签或逐题结果。

### 起步规模与覆盖

可以先安排约 60 个独立源案例：会议纪要、活动统计、项目介绍各约 20 个；名单通知另做工作流验收。

这是第一轮可行性规模，不保证足以证明极低错误率。建议先做 5 个估算制作与双人核对时间，再安排后续。

至少包含：

- 负责人是参会者之一，但姓名出现位置不同。
- 同名不同人；同一人跨轮承担不同任务。
- 同一文本换任务、换上下文、换接收方，最小表达发生变化。
- 多实体与多类别在同一段；不能只测单个姓名。
- 机构公开性不同、地点粒度不同、宿舍或敏感属性组合。
- 0 人、重复行、空值、合计行和多表统计。
- 资料里包含“忽略之前限制”等指令，但资料不是授权来源。
- 权限或事实明确缺失，应暂停。
- 生成模型诱导恢复原名或把本地统计带入下一轮。

同一个源案例的三个变体只能算一个独立来源组。不要把 20 份材料各改 5 个名字写成“100 份独立材料”。

### 每个案例记录什么

    案例编号、来源组、来源类型：
    材料全文（本机保管）：
    具体任务、身份、接收方、权限事实：
    预期必须保留的事实/关系：
    禁止披露内容：
    片段边界/编号、片段可接受动作与首选动作：
    各实体的期望残留表达（删除/代号/粗粒度/原值等）：
    当前动作无法表达的组合需求：
    实体边界与类别（用于提供实体的动作评估）：
    预期业务结果或计算答案：
    A/B及裁决状态：
    规范版本：

“提供实体”的评价用于隔离动作模型；另一份真实识别评价不能把这些人工实体直接喂给识别器当作检测结果。

### 什么时候交给 AI

AI 先提供冻结候选哈希、代码版本、特征版本、阈值、测试命令和验收标准。你记录冻结时间后，再允许评估执行。

如果本地材料含真实个人信息，不要把原文粘贴到聊天或让编码 AI把它打印到工具输出。工具读取的文本也可能成为外部 AI 的上下文；“文件在本机”不等于所有 AI 处理都在本机。应使用获准的本机脚本评估，只输出汇总和安全案例编号，或者先完成明确的数据准入流程。

现有 research 只接受 synthetic，真实材料不能改标 synthetic 绕过。需要真实数据时让 AI先设计隔离评测路径，你确认授权和保管范围后再实施。

### 看到失败之后

失败是研究结果，不是需要隐藏的瑕疵。记录原因并回到开发。若根据这些失败修改模型，这套盲测已不再独立；下一轮用新材料或事先封存的未使用批次终验。

先做公开/虚构输入验收。真实个人资料准入不是“API 能调用成功”后的自动下一步。

### 机器准备

不需要先买新显卡。先给 AI 当前设备的操作系统、CPU、内存、显卡型号/显存和可用磁盘信息；Windows 可在设置“系统—关于”和任务管理器“性能”查看。只提供必要信息，不附序列号或完整账户截图。

## H09｜重点：亲自验收结果与界面

### 业务结果

准备每个任务 5—10 个清楚的成功/失败示例，按冻结标准检查：

1. 必需事实有没有保留。
2. 负责人和事项有没有错配。
3. 统计是否遵守口径，0 和重复记录是否正确。
4. 是否添加了原材料没有的日期、地点、联系人或链接。
5. 对应接收方是否看到了不应看到的原值或线索。
6. 暂停是否说明缺什么，用户能否采取下一步。

可用“通过/失败/无法判断”，并写证据。无法判断不是通过。LLM评分可辅助整理，不能替代你的业务评价。

### 手机体验

单机服务绑定 127.0.0.1 时，手机不能通过自己的 127.0.0.1 访问电脑。**不要自行把服务改成 0.0.0.0 开到局域网来完成测试。**

可先由 AI完成手机尺寸模拟和截图。若需要真手机，AI应提出临时受控测试方式：仅合成资料、限定可访问设备/网络、必要访问限制、测试后关闭；由你确认该方式。也可在具备隔离条件的测试环境完成。这个临时测试不代表支持多人部署。

实际操作：

1. 打开侧栏和任务选择。
2. 上传合成文件，分别选临时保存和资料库。
3. 输入长问题，弹出输入法后检查发送按钮。
4. 查看长回答、错误提示和长文件名。
5. 清除对话，再检查历史。
6. 进入通知页面并返回。
7. 横竖屏切换、浏览器放大，检查按钮和说明可见。

### 异机安装

提供另一台电脑或可重建虚拟机。AI负责可执行安装说明，你按说明从交付包开始，不从原电脑复制整套虚拟环境和缓存。

重点确认：缺权重有明确提示；恢复权重后可加载；启动地址正确；公开样例可跑；没有你的私人资料或密钥跟着交付。虚拟机完成不应被写成已验证所有GPU机器。

## H10｜最终发布前你要确认的事项

AI 应先提供具体候选、证据和交付包清单，你再确认：

1. 你认可的任务质量和隐私边界是否通过。
2. 数据与权重是否允许给目标接收者。
3. 已知限制是否写清，例如只支持本机单人、尚未覆盖的场景。
4. 是否同意使用该版本替换当前活动模型；替换方案能否回滚。
5. 是交付源码包、完整运行包，还是仅提交研究报告。
6. 对外服务、发布或发送的具体目标是什么。

你的确认记录针对具体版本和对象，不是一张无限期、无限范围的授权。失败时恢复旧版本，并保留失败证据。
