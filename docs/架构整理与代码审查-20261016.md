# 架构整理与代码审查（2026-10-16）

## 本次核查范围

检查了 `llm_shield/` 的在线调用链、`server.py` 的 API、`web/` 的入口文件、配置、启动脚本、打包脚本以及 `tests/` 的回归覆盖。`m9_data/` 和 `scripts/` 属于离线工具，未并入在线链路。本工作目录没有 `.git`，本次修改以文件和测试结果为交付记录。

## 当前在线架构

```text
web/ → server.py → chat.py 或 pipeline.py
                     ↓
                 m1_access 权限和材料读取
                     ↓
             material_processing 材料展开及逐份识别
                     ↓
                 m2_detect 识别与分段
                     ↓
          m4_necessity 模型评分 → m3_decide 硬约束
                     ↓
              m6_transform 脱敏与代号映射
                     ↓
        m7_egress 外发复检 → 模型/展示/工具
                     ↓
                 m8_audit 记录边界结果
```

`schema.py` 是跨模块数据契约；`config.py` 读取 `config/*.yaml`、模型目录和环境变量。`m5_utility` 只提供结果提示。`m9_data` 只在离线训练中使用。

## 已处理的问题

1. **材料处理重复且行为不一致。** 对话入口逐份识别材料，单次运行和预览把多份材料合在一起识别，却只传第一份的列与行元数据。现由 `material_processing.prepare_materials()` 统一展开、逐份识别并转换到拼接文本的全局坐标；三条入口共用它。新增第二份表格材料的坐标与列上下文回归测试。
2. **预热提示与实际策略相反。** 配置启用 GLiNER 而模型不可用时，识别器会拒绝请求；启动日志原称“退回规则底座”。提示已改为“请求将暂停处理”，与失败关闭策略一致。
3. **上传边界处理。** 未预期的解析异常原样传给 HTTP 客户端，可能包含本地路径或原文片段；上传代码还会一次读入整份文件后才做 5 MB 检查。现返回固定错误说明，只读取上限加 1 字节，并加入异常回归测试。
4. **首页文档与当前目录不符。** 原 README 引用不存在的上级交付目录和已过时的运行说明；已重写为当前工作目录的结构、启动步骤与测试命令。

## 仍需安排的架构工作

| 优先级 | 问题 | 建议 |
| --- | --- | --- |
| 高 | 会话存储为进程内单例；多进程部署时不同进程无法共享会话，重启后历史消失 | 明确只运行单进程；若需多进程，再抽象 `ChatStore` 并引入受控存储 |
| 高 | `.env.example` 启用 GLiNER，但权重和可选依赖不在仓库内；新环境可能全部暂停 | 为交付环境提供模型安装与健康检查步骤，并做一次干净电脑验收 |
| 中 | `pipeline.py` 的完整运行和 `preview_only()` 仍各自维护权限/决策步骤 | 后续可把共同的“权限→识别→决策”结果封装成服务；需用端到端安全测试锁定暂停行为后再迁移 |
| 中 | 配置里的默认模型位置是 Windows 固定路径 `D:\project\models` | 为其他机器显式设置 `SHIELD_MODEL_DIR`；部署包提供路径检查 |
| 中 | `tests/test_smoke.py` 在导入时执行并退出，不能随 pytest 一起收集 | 将其改成 pytest 测试或保留为独立脚本并在 CI 中单独调用 |
| 低 | 历史报告描述的模型开关、资产规模与当前文件存在差异 | 以本 README、实际配置与代码为运行依据；历史报告保留为阶段记录 |

## 验证边界

在可用的 Python 3.13 环境中设置 `SHIELD_USE_GLINER=false` 后，`pytest`（排除独立冒烟脚本）和 38 项冒烟均通过。这验证了规则识别路径、接口与外发防护的回归；本次环境缺少 GLiNER 依赖，因此没有验证启用 GLiNER 时的推理，也没有调用真实外部 API。测试结果不能替代人工标注材料的隐私评测。
