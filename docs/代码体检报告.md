## 一、系统架构（一眼看懂）

### 1.1 只有一个入口，一条主干

整个系统**只有一条主干**，从浏览器到云端：

```
浏览器 (web/index.html + chat.js)
   │  POST /api/chat/{id}/messages
   ▼
llm_shield/server.py ── FastAPI，只做「收参数 → 转交 → 返结果」
   ▼
llm_shield/chat.py ──── 会话状态（多轮历史、代号映射、20 轮上限、30 分钟过期）
   ▼
llm_shield/pipeline.py ─ 端到端编排（真正的主干，291 行）
   │
   ├─ m1_access   权限：这个身份能不能读这份材料 / 能不能发给这个接收方
   ├─ m2_detect   识别：找出敏感片段          ← 唯一的「模型密集区」
   ├─ m3_decide   决策：选六种动作之一
   ├─ m4_necessity 动作模型：给六个动作打分    ← 第二个模型（TF-IDF+逻辑回归）
   ├─ m5_utility  效用：这样处理后任务还做得成吗
   ├─ m6_transform 转换：删除/聚合/泛化/代号替换
   ├─ m7_egress   外发：三边界检查 + 调云端 API
   ├─ m8_audit    审计：记录每次外发
   └─ m9_data     数据：合成训练语料（**离线工具，不在运行链路里**）
```

**关键理解**：`pipeline.py` 是唯一把九个模块串起来的地方。看代码只要先看它，
就知道每个 mX 模块在什么时候被调用、输入输出是什么。

## 五、决策层「电话触发暂停」根因与重训（2026-10-16 深夜）

### 5.1 现象

`联系电话13812345678。` 这类**只含电话**的片段，会让**整个请求暂停**——操作员看到的是
"系统拒绝处理"，而实际原因藏在决策层。

### 5.2 根因（与原判断不同，实测推翻了"特征泄漏"假说）

排查发现三层问题，一层比一层深：

| 层 | 问题 | 证据 |
|---|---|---|
| **① 训练语料没有单类别片段** | 合成案例总把多个类别塞进同一句，标签生成器又把多类别**塌缩成一个代表类别**（有人名就取人名）→ `{PERSON_NAME, PHONE}` 整体被标成 `PSEUDONYMIZE`。于是**「纯 PHONE 片段」在语料里为 0 条** | `load_synthetic()` 里纯 PHONE 片段计数 = 0；真实管线却会切出 `联系电话13812345678。`（类别只有 PHONE） |
| **② 模型于是外推成人名的动作** | 没见过纯电话片段，只能从最接近的 `[CAT]PERSON_NAME\|PHONE→PSEUDONYMIZE` 外推 → 选 `PSEUDONYMIZE` | 旧模型对 14 个类别里的 **12 个**一律输出 `PSEUDONYMIZE`，连文本压成 `"x"` 也一样 |
| **③ 而电话根本不能代号化** | `PSEUDONYMIZABLE = {PERSON_NAME, ORG}`，`action_applicable` 判否 → 安全层只能暂停 | 决策层设计契约：模型选错就暂停，**绝不回退到安全备选** |

另外查清一件重要事实：**部署的模型并不是用仓库里那份 `necessity_train.jsonl` 训的**
（那份是 `FEATURE_VERSION=1` 的旧格式，3,469 条，当前 `train()` 会直接拒绝）。
artifact 自述训练样本 10,554 条、来源 `synthetic_rule_baseline` —— 是训练时现场生成的。

### 5.3 修法（三步，每步都有量化验收）

**第一步：补齐训练覆盖。** `expand_segments()` 为每个片段生成**全部类别子集投影**
（1~2 元组），原文/上下文沿用不动、只有 `[CAT]` 与 `[N]` 随组合变化——等于强制模型
用类别信号而非"这段文字像什么"来区分动作。样本 11,064 → **64,026 条**。

**第二步：把特征拆成「结构化 / 内容」两路并降权后者**（`FEATURE_VERSION` 2 → 3）。
根因是长原文的 char n-gram 数量压倒 `[CAT]` 这类短策略信号；实测把任务描述也留在
结构化块里会继续稀释，故 `[TASK_TEMPLATE]`/`[TASK_TEXT]` 一并归入内容块。
用 `FeatureUnion` + `transformer_weights={结构化: 1.0, 内容: 0.35}` 实现。

**第三步：真实管线逐片段验收**（96 个"片段 × 接收方"组合，教师标签与模型动作逐一对比）：

| | 修前 | 修后 |
|---|---|---|
| 与规则教师一致 | — | **91/96 (94.8%)** |
| **模型选择不可行动作（→触发暂停）** | **大面积** | **0** |
| 不安全方向偏差（少删/多留） | 7 处 | **0** |

剩余 5 处偏差全部是 `PAUSE→DELETE`、`GENERALIZE→DELETE`，即**更保守**的方向。

分组留出验证：Accuracy **0.9929** / Macro-F1 **0.9846**（49,110 训练 / 14,916 验证，组重叠 0）。

### 5.4 重训后又暴露两个边界复扫缺陷（各自都会拦掉全部外发）

模型修好后端到端**仍然全暂停**，继续排查发现外发复扫把**系统自己产生的内容**当成泄露：

| 缺陷 | 表现 | 修法 |
|---|---|---|
| **代号被当成真名** | 脱敏后 `负责人人员壬负责…`，GLiNER 把代号尾字 **`壬`** 抠出来判成 `PERSON_NAME`（conf 1.0）→ 低信任接收方禁令命中 → 拦截 | 实测 `人员-甲` / `〔人员甲〕` / `P1` 等 8 种别名格式**全部照样被误标**，故改格式无用；改为在判定侧豁免——`MappingTable.is_placeholder()` 判定"检测结果是否落在本进程已发出的代号之内" |
| **自己的提示词被判敏感** | 系统提示词里的 **`（已脱敏）`** 被判成 `SENSITIVE_ATTR`——属**绝对禁止**类别，于是**每一次**外发都被拦 | 改措辞（并移入 `config.SYSTEM_PROMPTS`）。**不能靠豁免模板绕过**：模板若真含敏感值必须照拦（`test_unsafe_system_message_is_blocked_before_model_call` 守着这条）。新增回归测试 `test_shipped_system_prompts_are_detector_clean`，它当场又抓出默认模板 `校园文本处理助手` 里的 `校园文本` 被判 `ORG` |

> 这两个缺陷都是**启用 GLiNER 之后才出现**的——正则+词典底座不会在 `壬` 或 `已脱敏`
> 上误报。它们是"开启模型"的真实代价，必须随开关一起处理，否则应用会 100% 自我拦截。
