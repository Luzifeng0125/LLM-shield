## 合并做法

以 `v3` 的整理后结构为基准，把 `origin/main` 与本地工作目录并入：

1. **把 `origin/main` 合入 `v3`**（保留双方全部历史），冲突逐个手工解决。
   Git 的重命名检测已自动把 main 的新文件放到整理后的位置：
   `隐盾整合交付_20261012/数据集/` → `delivery/数据集/`，
   `隐盾整合交付_20261012/app/llm_shield/m2_detect/reviewed_ner.py` → `delivery/app/...`。
2. **两处代码冲突按「两边都留」解决**（二者是互相独立、可同时开启的识别链路）：

   | 文件 | main 带来的 | v3 已有的 | 解决 |
   |---|---|---|---|
   | `llm_shield/config.py` | `reviewed_ner_settings()` | `use_gliner()` / `gliner_model_dir()` | 两个都保留 |
   | `llm_shield/m2_detect/pipeline.py` | `_reviewed_detector` 缓存 + 注入逻辑 | GLiNER 单例缓存 + `use_gliner` 形参 | 两个都保留 |
   | `.env.example` | `SHIELD_REVIEWED_NER_*` | — | 补上 `SHIELD_USE_GLINER` / `SHIELD_GLINER_MODEL_DIR`，四项目前齐全 |

3. **`README.md` 冲突**：保留 v3 的目录结构说明，并把 main 的关键入口链接改写到新路径
   （原链接指向已消失的日期目录）。
4. **删除日期命名目录**。`隐盾提交材料_20261014/` 与 `delivery/提交材料/` 内容一致，
   合并时被识别为重命名，已自动收敛。
5. **并入本机工作目录**：field_v1 全套（数据集 + 评测脚本 + 回归测试 + 报告）、
   五个更新版代码/配置文件、三个新测试、11 个数据文件、三个报告/PPT 交付物、
   两个打包脚本与一个停止入口。
