# 当前架构与模型取舍

更新：2026-10-17，本机与 GitHub 代码已实际融合。

## 在线路径

单一启动入口 → FastAPI（127.0.0.1:8787）→ 权限检查 → 按文件独立展开 → GLiNER 批量语义识别与格式校验 → 分段动作模型 feature v3 → 约束检查 → 转换 → 外发网关 → DeepSeek → 回答复检与会话历史。

chat.py、pipeline.py 的对话、预览和运行入口共用 processing.analyze。material_processing 处理逐文件表头、全局坐标、不同类别分段和 GLiNER 批量窗口，避免多套编排互相漂移。昂贵识别器为带锁单例；并行分析受限，耗时统计最多保留 500 条且不保存内容。会话关闭、过期和清除均释放私有原值与映射。

名单 review 接口只在本机识别；draft 接口只有公开活动字段，不接受名单、文档 ID 或历史。通用入口拒绝 activity_notice 任务，通知行为保留独立约束。

## 模型选择

| 组件 | 状态 | 原因 |
| --- | --- | --- |
| GLiNER gliner_v3 | 默认开启，CUDA/CPU 自动选择 | 本机完整权重已找到，已在本机离线加载与推理；五类语义标签与原本地版保持一致 |
| 格式规则与词典 | 启用 | 格式校验、表头语义和补充检测仍有独立职责 |
| 动作 feature v3 | 启用 | 使用原本地配套权重与结构/内容分路特征；与 v2 权重不可直接混用 |
| Campus NER | 已移除 | 本机无该权重，在线叠加会增加维护与推理开销；本次没有证据表明它有额外收益 |
| 人工复核 BERT | 仅离线评测代码 | 本机未找到训练产物；不再作为启动依赖，不能宣称其历史成绩属于当前系统 |
| GLiNER 训练底座及动作 v2 备份 | 离开活动目录，备份保留 | 当前推理已验证只需 gliner_v3 完整目录与动作 v3；训练底座不必随在线程序加载 |

活动版本和哈希见 delivery/app/models/ACTIVE_MODELS.json。现有权重的训练来源没有在本次重新独立审核，不能仅凭目录名宣称人工金标。

## 验证及限制

38 项 smoke、307 项 pytest、95 项子检查通过。GLiNER 在 CUDA 上完成启动预检；合成名单核对、完整选中表计数、网页路由以及通过处理链的真实 DeepSeek 公开短句均通过，示例稳定态整轮约 1.8 秒。首次加载模型仍有一次冷启动开销。

已有 GLiNER 开发集和 BERT 历史分数均不代表本次独立盲测。地点、宿舍、间接身份信息和复杂跨表统计仍需单独评估。当前精确统计只支持一个选中表中的窄口径专业、学院或校区人数，不把检索片段当作全表。
