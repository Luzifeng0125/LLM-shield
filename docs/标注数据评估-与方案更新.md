## 1. 这批数据是什么

| kind | 条数 | train/val/test | 内容 |
|---|---|---|---|
| `ner` | 204 | 92 / 56 / 56 | 纯识别：`annotation.entities[] = {start,end,text,category}` |
| `policy` | 72 | 24 / 24 / 24 | **决策**：实体 + `target{preferred_action, acceptable_actions, send_allowed, sanitized_text, reason}` |
| `dialogue` | 36 | 12 / 12 / 12 | **多轮**：3 轮 × 12 = 108 轮，每轮含实体 + target |

**质量很高**，具体地：

- **无泄漏**：train∩val、train∩test、val∩test 的 id 与 text 交集全为 0。
- **动作平衡**：`policy` 批 6 个动作各 12 条。
- **偏移全部自洽**：204 条 ner 中 `text[start:end] == entity.text` 全部成立（0 处不一致）。
- **span 边界是"只标值"**：`赵雨瑞`、`150 6376 3788`、`示例公寓2栋402室` —— **0 条**含"姓名：""手机号："这类字段标签前缀。这与我上一版方案建议"统一为只标值"完全一致。
- **36 条困难负例**（0 实体），文本里都带数字干扰（"第20日""7项待办"）。
- **每条决策都带人写的理由**（`reason`），这是策略语料，比标签本身更值钱。
- **32 条 notes，其中 14 条是明确的"请裁决/请确认"** —— 标注者主动把边界争议交出来了（见 §6）。

## 2. 决定性发现：`policy` 批不看材料也能拿 100%

我把 train 批的 `task_description → preferred_action` 抽成 6 条查表规则，**完全不看材料文本**，在全集上打分：

```
policy 全集    72/72 = 1.0000
validation     24/24 = 1.0000
test           24/24 = 1.0000
```

原因在数据设计里 —— 每条指令都**直接写明了策略**，且与动作一一对应：

| task_description | 动作 | 实体类别 |
|---|---|---|
| 删除与任务无关的私人联系方式，只保留事项和期限。 | DELETE | PHONE |
| 只需参加人数，必须在本地统计；不要发送姓名名单。 | LOCAL_AGGREGATE | PERSON_NAME |
| 活动地点尚未批准公开精确位置，只保留"校内某场所"。 | GENERALIZE | LOCATION |
| 请整理负责人—事项—期限清单，姓名使用稳定代号。 | PSEUDONYMIZE | PERSON_NAME |
| 地点已获准公开，通知必须包含这个精确活动场地。 | RETAIN | LOCATION |
| 请将资料原文转交接收方；系统尚未核实该接收方的权限。 | PAUSE | PERSON_NAME + PHONE |

进一步的交叉表证明：**`(指令, 类别)` 唯一决定动作**（无任何反例），`trusted_context` 也只有 3 种组合、各自绑定特定动作。

**所以要如实说清楚：这一批是极好的「策略规格书 + 测试集」，但它不是「读上下文分辨是否脱敏」的训练集** —— 因为答案写在指令里。拿它训模型，模型会学到"指令关键词 → 动作"这条捷径并拿到满分，同时**完全没学会读材料**。

这不是标注者的问题，是**探针轴的选择**问题：round1 变化的是*指令*，而"是否脱敏"在材料侧的判断（同一个敏感片段，在不同任务里该不该脱敏）根本没有被测。**round2 需要把指令固定住、变化材料**（§7）。

> 附带发现：round1 里**指令文本与 `trusted_context` 是冗余的**（"地点已获准公开" vs `exact_location_public=true` 说同一件事），所以这一批也分不出模型到底用了结构化标志还是读了指令文本。round2 应把两者解耦。

## 3. 这批数据真正给了什么（很值钱）

### ① 变换语义被钉死了 —— 而且我用确定性实现复现成功

| 动作 | 反推出的语义 | 复现率 |
|---|---|---|
| `DELETE` | 删「**字段标签 + 值 + 后随标点**」，不是只删值 | **12/12** |
| `PSEUDONYMIZE` | 值 → `人员甲`（会话内稳定） | **12/12** |
| `GENERALIZE` | 值 → `校内某场所` | **12/12** |

DELETE 这条尤其重要。例：

```
原: 材料登记：电话15063486623。请在18日前完成场地确认。请核对这条记录。
后: 材料登记：请在18日前完成场地确认。请核对这条记录。
```

只删数字会留下别扭的"材料登记：电话。"；标注者的口径是**连字段标签和句末标点一起删**。这直接定义了 `m6_transform` 该怎么写 —— 而项目现在没有这个语义。

`LOCAL_AGGREGATE` 还带**标签改写**：`参加名单：冯明乐、施乐星。` → `参加人数：2人。`（不只是聚合，还要改写字段名）。

### ② 端到端有了"逐字可比对"的评测目标

每条决策都给了人写的 `sanitized_text`。这意味着评测可以从"动作分类准确率"升级成**输出文本逐字对 diff** —— 这是最强的端到端指标，项目之前完全没有。

### ③ 显式上下文通道

`trusted_context` = `{exact_location_public, recipient_verified}`；`trusted_policy` = `{allow_identity_restoration_to_cloud, keep_alias_consistent, pause_on_ambiguous_reference, avoid_unique_award_linkage}`。

**它们是确定性的门**（`recipient_verified=false` → PAUSE；`exact_location_public=true` + 任务需要 → RETAIN），所以正确的位置是**约束层**，不是模型。这正好落在我上一版方案建议的 C 层。

### ④ 标注者的理由语料

72 条 `policy` + 108 轮 `dialogue` 的 `reason` 是人写的策略解释，例如：

> "任务只需参加人数，姓名名单属个人信息；在本地统计得到2人，外发内容只含统计值，不含名单。"

这是写策略文档、做 few-shot 提示、以及**审计解释**的现成材料。

## 4. 数据暴露的新能力缺口（项目现在完全没有）

| 缺口 | 现状 | 影响 |
|---|---|---|
| `trusted_context` 输入通道 | 项目无此概念 | 需要新增请求字段 |
| `trusted_policy` 会话级策略 | 项目无此概念 | 需要新增会话配置 |
| `unverified_recipient` | `recipients.yaml` 没有这个 key | 需要新增接收方 |
| `send_allowed` / `acceptable_actions` | 项目只有单一 `action` | 需要扩展决策输出 |
| `DELETE` 的标签级删除 | 项目只替换 span | 需要改 `m6_transform` |
| **跨轮状态** | `pipeline.py` 每次请求是**单次**的，无对话历史 | `pause_on_ambiguous_reference` 需要会话历史 |
| **组合式重识别** | `m7/m8` 只做**类别匹配**式泄露检测 | `avoid_unique_award_linkage` 是**推理式**泄露：即使假名化后，"本组织唯一的年度个人奖"+组织+代号仍可重识别到个人。**任何类别匹配都抓不到** |
| `keep_alias_consistent` | 项目 `m6_transform/mapping.py` 有会话内映射 | 需核对是否满足 |

**最后一条是真正的硬骨头**：它要求系统评估"唯一性组合"带来的重识别风险，这是当前架构里完全没有的能力，也是这批数据里唯一我觉得**确实需要模型辅助**的判断（`dialogue` 里 6 例 `avoid_unique_award_linkage=true` 全部 PAUSE）。

## 5. 方案怎么改

好在这批数据与上一版方案的 A/B/C 分层**对得很齐**：

| 层 | 上一版方案的建议 | 这批数据 |
|---|---|---|
| **A 识别** | GLiNER 读上下文找敏感片段 | `ner` 204 条 → 直接可做训练/验证集；值边界约定已对齐 |
| **B 必需性** | 角色/关系判断 | `trusted_context` 给了显式门；但"角色"轴**未被测试** |
| **C 落动作** | 契约/约束求解，不用模型 | `policy` 批**证明**了它是确定性的 → 就该写成策略表 + 约束 |

### 更新后的做法

1. **把标注 schema 接成项目的评测契约**，写逐字 diff 评测器（动作 + `sanitized_text` + `send_allowed`），让现有 v2 流水线跑全部 288 个决策单元（72 + 108 轮）+ 204 条 ner → **拿到真实基线**。这比上一版方案里用 `expect` 契约做基线强得多，因为现在是**人工 ground truth**。
2. **实现确定性的部分**（预计 `policy` 批直接到 ~100%，而这是**正确**的，因为它本来就是策略表）：
   - `trusted_context` / `trusted_policy` 作为约束门；
   - 三个已验证的变换语义；
   - `send_allowed=false` → PAUSE。
3. **A 层上 GLiNER**（这是模型真正该去的地方），用 204 条 ner 做训练/验证，并核对边界口径。
4. **补两个真正的新能力**，都要先拿到你的裁决：
   - 跨轮会话状态（`pause_on_ambiguous_reference`）——**这是全数据集里最纯粹的"读上下文"任务**，因为"他"指谁只能靠读前面几轮；
   - 组合式重识别（`avoid_unique_award_linkage`）——唯一我认为需要模型辅助的决策判断。
5. **round2 按 §7 重新设计探针轴**，否则训出来的模型只会读指令。

模型该放在哪，这批数据给了很清楚的答案：**A 层需要，组合式重识别需要，其余不需要。**

## 7. round2 该怎么设计（这一节最关键）

round1 的问题不是质量，是**探针轴**。要真正测"读上下文 → 脱敏"，round2 需要三组新探针：

### ① 固定指令，变化材料（补上"材料侧"的判断）
同一条指令"只保留事项和期限"，配不同材料：

| 材料 | 期望动作 | 考点 |
|---|---|---|
| 无关的私人手机号 | DELETE | 现状 |
| 完成任务的必需联系方式（如场地预约电话） | PSEUDONYMIZE 或 RETAIN | **同一类别，角色不同 → 动作不同** |
| 完全没有敏感内容 | RETAIN + `send_allowed=true` | 不该无谓删除 |
| 指令前提不成立（说"只保留事项和期限"，但材料里没有事项/期限） | PAUSE | **能否发现指令前提失败** |

### ② 指令不点明动作，只给目的（这才是"分辨是否脱敏"）
round1 每条指令都直接写了动作（"姓名使用稳定代号"→ PSEUDONYMIZE）。round2 应给**只描述用途**的指令：

> "我要在班会上念这份名单，但不想让人知道谁是谁。"

系统必须自己推出 PSEUDONYMIZE（而不是 LOCAL_AGGREGATE 或 DELETE）。**这一组才真正测"读上下文分辨是否要脱敏、怎么脱敏"。**

### ③ 解耦指令与 `trusted_context`
同一条指令配不同的 `exact_location_public` / `recipient_verified`，看系统用的是结构化标志还是指令措辞。

### ④ 覆盖度补口
- **identity 只有 `student_leader`**（108/108）——项目有 3 个身份且权限不同，应覆盖 `course_member` / `external_partner`；
- **task 偏斜**：`policy` 批 meeting_minutes 48 / activity_stats 12 / project_intro 12；
- **receiver 只有** `external_model` + `unverified_recipient`——项目的 `viewer_teacher` / `viewer_peer` / `egress_tool_public` / `egress_tool_internal` 一个没测；
- **`acceptable_actions` 全程单元素**（72 + 108 轮都是），集合语义没用起来。建议 round2 真的用上（很多隐私策略有多个可接受答案，例如 DELETE 与 GENERALIZE 都行），这样评测才不会把合法答案判错；
- **ner 批偏模板化**：`复核意见写道`44 / `交接问答`44 / `材料登记`24 等几个模板占绝大多数；`ORG` / `LOCATION` / `SENSITIVE_ATTR` 各只有 8 条，偏薄。

## 8. 结论

- 这批标注**质量高、纪律好**（无泄漏、平衡、偏移自洽、边界争议主动上交），是一份**可用的策略规格书 + 测试集**。
- 它**解决了上一版方案里"判定标准不存在"这个卡点的一半**：6 个动作的语义、`trusted_context` 的门、变换后的文本形态，现在都有了人工确认的样本。
- 但它**还不能用来训"读上下文"的决策模型** —— 因为 `policy` 批的动作完全由指令决定（已实测 100%）。
- 所以 v3 的路线更清楚了：**A 层（识别）用 GLiNER；C 层（落动作）写成确定性策略 + 约束，不训模型；B 层（材料侧必需性）和组合式重识别，等 round2 的数据再上模型。**
