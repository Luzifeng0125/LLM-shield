# 隐盾 v3 修订方案：读上下文 → 脱敏

> 目标（用户原话）：**读取上下文然后进行脱敏**。
> 本文件是对 `docs/v3-方案.md` 的修订；原方案保留以便对照。

---

## 0. 先把"读上下文"拆对，否则会训错模型

"读上下文然后脱敏"实际是三个子问题，**每个子问题里"上下文"的作用完全不同**：

| | 子问题 | 上下文要回答什么 | 正确答案的形状 | 该用什么 |
|---|---|---|---|---|
| **A** | 识别 | 这段字是不是敏感？是哪一类？（"明天"≠"张明"；"学生活动中心"是地点不是机构） | span + category | **GLiNER**（真读上下文） |
| **B** | 必需性 | 这个实体在任务里扮演什么角色？任务需不需要它？（名单里的姓名 vs 任务负责人） | 角色 / 关系结构 | **关系抽取**（UIE 或同栈备选） |
| **C** | 落动作 | 在权限与任务契约下，哪种动作组合"披露最少且不违规"？ | **全文档**的动作集合 | **约束求解 + 闭环验证**，不是逐段分类 |

原方案的预算几乎全花在 A，然后让 UIE 去做 C —— 但 C 用模型做是最差的选择（不可审计、不可解释、监督信号只有规则）。而 B 几乎没被触碰，可 B 才是"读上下文"真正的战场。

---

## 1. 最重要的一件事：判定标准不存在，不是模型不存在

我核对了三个任务的客观契约（`synthesize.py`）：

| 任务 | `must_not_appear` | 附加契约 |
|---|---|---|
| activity_stats | PHONE, EMAIL, STUDENT_ID | `person_count` |
| meeting_minutes | PHONE, BUDGET, API_KEY | `must_keep_relation` |
| project_intro | PHONE, EMAIL, WECHAT, BUDGET | — |

**`PERSON_NAME` 一次都没出现。**

这意味着：格式类（手机/身份证/银行卡）的"要不要脱敏"是**明确的**，正则直接解决，根本不需要模型。而姓名/机构/地点/敏感属性这些**真正需要读上下文才能判断**的类别，项目里：

- 没有规则（只有姓氏表+称谓的启发式识别，识别 ≠ 判断）；
- 没有标签（`synthetic_rule` 是规则生成的，见下）；
- **连客观契约都保持沉默**。

所以 v3 的第一件事不是选模型，是**把策略写下来**：

> 什么上下文条件下，一个姓名（机构/地点）**必须**脱敏、**可以**保留、**应该**假名化？

可用的判据维度（从数据里能看出来的）：
- 这个实体是否承载任务必需的角色？（"负责人"承载，名单里的行不承载）
- 该实体是否已在材料中被授权公开？（`project_intro` 的"项目负责人"对外介绍场景）
- 类别本身的级别与 `hard_ban`（`rules.yaml` 已有）；
- 接收方的信任级别与身份权限（`identities.yaml` 已有）。

**这份策略文档 + 按它标出的 200~500 条样本，是这个方案里唯一无法绕过的人工投入。** 没有它，训任何模型都只是在模仿姓氏表和停用词表。

## 2. 三个前置修复（不训模型，1 天）

### ① 让上下文真的能进到模型里
- `pipeline.py:274` 调 `decide_all(...)` 时**没传 `context=`**；
- `attach_spans`（`m2_detect/pipeline.py:148`）算完 `left`/`right` 就扔，`seg.context = seg.text`，那个 `min()` 两边表达式相同、是空操作；
- 结果 `[CONTEXT]` ≡ `[TEXT]`，"读上下文"在代码层面不成立。

修：真的拼接前后 N 字（跨段），真的传进 `context=`，顺手删掉空操作。

### ② 统一 span 边界约定
gold 含字段标签（`"姓名：郑志远"`、`"手机号：17422568210"`），正则只标值（`group: 1`）。
**建议统一为"只标值"**：与正则一致、与通用 NER 惯例一致、不让模型去学"手机号："这种模板串、脱敏后文本更自然（"姓名：人员甲"）。
动作：写归一化脚本改 `gold_spans` + 回归对比。

### ③ 建客观评测基线
用 §1 的契约当度量：`must_not_appear` 命中率、`person_count`/`must_keep_relation` 保持率。
**先量出 v2 决策层的真实数字**——现在没有任何证据说明决策层不行。

## 3. A 层：GLiNER（原方案对的部分，保留）

- **角色**：只做识别。格式类继续交给正则（更快、更准、可解释）。
- **监督是真的**：`gold_spans` 由合成器生成（它自己知道实体种在哪），不是规则猜的。
- **接入是真的**：`CampusNERDetector` 已实现 `Detector` 接口，热替换现成；torch 栈已装。
- **做法**：零样本基线 → 按 §1 的标注 + 归一化后的 gold 微调（LoRA，RTX 4060 够用）→ 对比现有 `roberta_campus` 基线。
- **评测**：13 类实体级 F1，重点看姓名/机构/地点/敏感属性。

---

## 4. B 层：必需性 / 角色判断 —— 上下文的真正战场

**数据现实（关键）**：合成器**保有结构化三元组**，就在每个案例的 `rows` 里：

```
meeting_minutes: columns = ["事项", "负责人", "期限", "联系电话"]
                 rows    = {"事项": …, "负责人": …, "期限": …, "联系电话": …}
```

所以：

- **有表格的材料**，角色/关系是**免费的**（`rows` 直接给出），不需要模型。检测层其实已经在用 `rows` 做列名提示了，只是决策层没用。
- **没有表格的自由文本**（真实上传文档的主要形态），才需要关系抽取。

**这决定了 UIE 的入场条件**：
1. 当前评测集**测不出** UIE 的价值 —— 因为每条案例都有 `rows` 兜底；
2. 要用 UIE，必须先造**自由文本 + 关系标注**的案例（合成器能做，它知道三元组），然后在上面证明 UIE（或同栈备选）比"从 `rows` 读"或"roberta_campus + 关系头"更好；
3. 代价是 Paddle 运行时（项目目前唯一的异质深度学习依赖）。

> 诚实说明：GLiNER 是否原生支持关系抽取，我这一轮没能查证（搜索服务不可用）。**如果它支持，B 层可以和 A 层共用一套依赖**，UIE 就没必要了。这个要先查清。

**B 层的输出**不是动作，是"这个 span 在任务中的角色 + 是否必需"，交给 C 层。

---

## 5. C 层：契约驱动的动作求解（替换逐段 argmax）

**为什么必须换**：`decide_all` 对每段**独立**取最高概率动作。但"这个姓名要不要假名化"取决于**别处**是否需要保留"负责人—事项—期限"的对应关系。逐段独立的分类器，读多少上下文都表达不了跨段依赖。

**做法**（复用现成零件）：

1. **算可行集**：对每个 span 用已有 `action_applicable()` + `check_hard()` 过滤掉不可行动作；
2. **按契约求解**：在可行集里找 **总披露代价最小** 且满足任务契约的组合：
   - `must_not_appear` → 这些类别 RETAIN 不可行；
   - `must_keep_relation` → 逼出 PSEUDONYMIZE（DELETE 会让"负责人："空掉，关系失去可读性）；
   - `person_count` → 逼出 LOCAL_AGGREGATE（只需计数就不必发明细）；
   - **B 层给出的角色** → 决定哪些姓名承载任务角色（要假名化）vs 只是名单行（可删）；
3. **闭环验证**：转换后跑**现成的**三边界泄露观测（`m7_egress` + `m8_audit`）当约束校验器；违约就升级动作（或暂停）。
   这一步很关键 —— 项目**已经有**载荷级泄露检测，把它从"事后记录"变成"求解器的校验器"，就能构成 propose → transform → verify → escalate 的闭环。
4. `m5_utility/estimator.py` 已在"效用检查"的位置，但现在是"只提示、不参与判定"；C 层把它升级为**参与**。

**好处**：客观、可审计、可解释、监督信号是真的（契约而非规则），并且天然表达跨段依赖。

**代价**：动作不再由模型"直接给出"，而是"模型/规则给候选、契约给结果"。这一点需要你明确接受（见 §8）。

## 6. 与原方案的区别

| | 原方案 | 修订方案 |
|---|---|---|
| 上下文管道 | 没发现是断的 | §2 先修，且作为前置 |
| span 边界 | 没提 | §2 统一为"只标值" |
| 决策层 | UIE 直接替 TF-IDF | **C 层契约求解**；UIE 只在 B 层做角色抽取 |
| 决策粒度 | 逐段独立 argmax（保留） | **全文档**约束求解 + 闭环验证 |
| 训练监督 | 弱标签 + gold 留出训练集 | **禁**用 `synthetic_rule` 训决策模型；用契约 + 人工标注 |
| 人工投入 | 几乎没算 | **策略定义 + 200~500 条标注**（列为关键路径） |
| 模型数量 | 2 个都进热路径 | A 层先上；B 层按评测决定；两个不同时进热路径 |
| 首个可交付 | 训完两个模型（1.5~2 周） | **3 天内不训模型**就能拿到决策点 |

## 7. 里程碑（重排：先拿答案，再花训练成本）

| 阶段 | 内容 | 训练 | 估时 |
|---|---|---|---|
| **M0** | 修上下文管道 + 统一 span 边界 + 用契约建客观基线 | 否 | 1 天 |
| **M1** | 写策略文档（什么上下文条件下要脱敏）+ 标 200~500 条 | 人工 | 1~2 天 |
| **M2** | C 层契约求解 + 复用泄露观测做闭环验证 | 否 | 1~2 天 |
| **M3** | GLiNER 零样本基线 → LoRA 微调 → 接入 A 层 | 是 | 2~3 天 |
| **M4** | 评测决策点：B 层到底需不需要？需要就造自由文本关系数据 + 训 B | 是 | 2~4 天 |
| **M5** | ONNX/CPU 优化 + 全量回归（81 pytest + 78 前端断言） | — | 1~2 天 |

**M0~M2 完全不训模型**，3~5 天就能回答"上下文感知的脱敏到底缺哪一层"。原方案要 1.5~2 周训完两个模型，才能开始问这个问题。

## 8. 我明确不做的事

1. **不用 `synthetic_rule` 标签训任何决策模型** —— 那只会得到更贵的规则模仿器（含规则的全部错误），0.9922 就是这么来的。
2. **不把 gold 排除在决策层训练之外** —— 决策层唯一能救它的就是人工判断 / 客观契约。
3. **不让两个 transformer 同时进热路径** —— 正面撞 500ms P95 预算（`campus_ner` 当年就是因此默认关闭）。
4. **不为"用上第二个模型"而引入 Paddle** —— UIE 必须靠评测挣到位置。
5. **不在同一套模板数据上刷指标** —— 210 条 / 3 模板 / `must_not_appear` 只覆盖 3~4 个格式类，太窄。

## 9. 需要你拍板

1. **接受"动作由契约定、而非模型直接给"吗？** 这是 C 层的核心前提。不接受的话，就得回到"模型直接预测动作"，而那条路目前的监督信号是坏的。
2. **接受 span 边界统一成"只标值"吗？**（影响微调效果与脱敏后文本形态）
3. **接受"先做 M0~M2 再决定要不要训模型"吗？** 以及 §1 那份策略文档 + 标注，你愿意投入吗 —— 这是唯一绕不过去的人工成本。
4. **UIE 还是同栈替代？** 等我把 GLiNER 的关系抽取能力查清后再定。
