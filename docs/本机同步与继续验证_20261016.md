## 同步后完成的代码修复

GLiNER 原实现把推理异常捕获后返回空列表，导致外发检查可能把识别失败误认为没有敏感实体。现在模型不可用、推理异常或输出的实体位置/置信度无效时抛出固定错误，由识别流水线暂停请求；原异常及材料原文不会进入错误信息。长文本后续窗口失败时也不会返回此前窗口的部分成功结果。

新增 `test_gliner_safety.py`，覆盖推理异常导致外发拦截、后续窗口失败、越界/非整数偏移及 NaN/无穷置信度；成功推理且无实体仍可以返回空列表。更新了原脚本中“缺失模型返回空”的旧预期。

候选模型启动器和重放脚本显式关闭可选 GLiNER，使 BERT 验证口径固定。

## 本机实测结果

原人工 gold 的 56 个 NER 验证单位上，BERT 单模型严格实体 F1 仍为 **99.45%**。使用更新后的规则与合并逻辑，组合链严格 F1 为 **98.91%**（91 TP / 1 FP / 1 FN）。剩余一例是敏感属性的完整语义片段被高置信关键词边界缩短。见 [新版验证重放](../delivery/数据集/复核与训练执行包_20261014/outputs/gold_run_20261016/ner_app_github_1f7fccd/summary.json)。

新增的 `eval_reviewed_field.py` 只读取 `field_v1`，不读取 `test_gold.jsonl`，不训练模型、不修改原评测集。在同一批 87 条手写材料上：

- 纯规则：粒度无关 cover F1 **77.90%**；严格边界 F1 **67.16%**。
- BERT 单模型：cover F1 **74.01%**；严格边界 F1 **54.05%**。
- 规则 + BERT：cover F1 **85.89%**；严格边界 F1 **73.52%**。cover 计数 137 TP / 33 FP / 12 FN；严格计数 118 TP / 54 FP / 31 FN。纯负例误报为 3/17，与规则基线相同。

完整结果见 [reviewed_bert_field_v1.json](../delivery/app/outputs/github_update_20261016/reviewed_bert_field_v1.json)。模板验证集高分没有转化为同等的边界泛化能力；当前收益主要在召回提升，机构、地点、宿舍和敏感属性仍有较多边界错误与误报。不能把 99.45% 当作真实业务的隐私保护准确率。

本轮未重新评分封存 gold 测试；上游仓库已有旧测试集评测记录，所以也不再把整个仓库状态描述为“测试从未被查看”。`field_v1` 保留作评测，未并入训练集。
